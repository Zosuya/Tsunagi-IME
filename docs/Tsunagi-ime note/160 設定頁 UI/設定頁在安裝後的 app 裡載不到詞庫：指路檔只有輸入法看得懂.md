# 設定頁在安裝後的 app 裡載不到詞庫：指路檔只有輸入法看得懂

**症狀**（2026-09-20 Mac 實測回報）：擴充包編輯器的「語言」欄一律顯示
`?`，而且**輸出欄打完詞不會自動反查填按鍵**。

兩個都不像路徑問題，看起來像編輯器的判斷壞了。

## 根因：兩支程式找同一份詞庫，找法卻不一樣

macOS 的開發建置**不把 146MB 的詞庫複製進 bundle**——每次建置都複製太慢，
改詞庫還要重裝。`build-app.sh` 改成在 `Contents/Resources/` 放一張指路檔
`data-dir.txt`，裡面寫著專案的 `data/` 在哪。

| | 怎麼找詞庫 | 認得指路檔嗎 |
|---|---|---|
| 輸入法 | `paths::data_dir()` | ✅ 它就是為此寫的 |
| 設定頁 | `shipped_dir()`：exe 旁邊 → 往上兩層 | ❌ |

而**設定頁的執行檔就住在那個 Resources 裡**，指路檔近在眼前，它卻不認得。
於是安裝之後設定頁一份詞庫都載不到。

（開發環境直接 `cargo run` 不會踩到——那時 exe 在 `target/release/`，
往上兩層剛好是專案根，`data/` 就在那。**只有裝起來才會壞**。）

## 為什麼完全沒有錯誤訊息

詞庫是**背景執行緒**載的（載進來要一兩秒，擋在啟動會讓設定頁按下去要等）。
`project_data_dir()` 回 `None` 時那個 `if let` 直接跳過，沒有任何輸出。

編輯器那邊也不會抱怨：`detect()` 查不到就回 `Unknown`（顯示 `?`），
`guess_keys()` 查不到就回空字串（欄位留白讓使用者自己填）——**兩支都有
合理的退路，於是「詞庫根本沒載」跟「這個詞真的查不到」長得一模一樣**。

## 順帶：`english` 也漏了

設定頁原本只載 `dict::load_bopomofo`。但 `detect()` 判斷語言問的是切法，
而切法要靠英文詞典才分得出英文段——少了它，注音串也會被算成不確定。

## 修法與驗收

`shipped_dir` 加第三條路（exe 旁邊的 `data-dir.txt`；要 `packs` 的話取
詞庫的隔壁，跟 `paths::bundled_packs_dir()` 同一條規則），並把路徑解析
抽成 `resolve_shipped` 純函式讓測試叫得到。

三條測試：指路檔指得到詞庫與包、正式安裝時 exe 旁邊的優先、都找不到回
`None`。把指路檔那條拿掉會紅。

> **路徑不該只能靠「裝起來打開看看」驗證**——這個洞就是這樣躲過驗收的。

## 這個洞的連鎖比看起來大

反查自動填按鍵**在 Mac 上從來沒生效過**，所以使用者只能手動去填「怎麼打」
欄——而那一欄在 macOS 上又有自己的問題
（[[Mac 設定頁的按鍵欄拿到國字：兩平台刻意不一致，撞在一起]]）。
兩個洞疊在一起，看起來像「按鍵欄很難用」，其實**上游那個才是主因**：
修好之後多數情況根本碰不到按鍵欄。

**查一個抱怨時要往上游看一層**：使用者抱怨的是他被迫走的那條路，不一定
是壞掉的那個地方。
