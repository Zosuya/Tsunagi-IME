# 詞庫沒收的英文字：字母三連組判斷「像不像英文」，擱置

> **狀態**：spike 做完、使用者裁決擱置（2026-09-25）。程式在分支
> `spike/english-like`（`31d97b3`），沒有進 master。之後改走「自動產生的
> 技術英文詞庫」＋學習層＋擴充包。

## 問題

注音鍵盤上英文字母、空白、連 `-` 都是注音鍵。引擎判斷一段字母是不是英文，
幾乎只看 `en_50k` 有沒有收。新詞沒收就容易被拆開去湊注音或日文：

| 使用者打的 | 輸出 | 怎麼壞的 |
|---|---|---|
| `codex-with-chatgpt 仍然` | …with-chatgp**吃**仍然 | `t␣`＝ㄔ一聲＝吃 |
| `（人名）Kyro` | Ky＋ろ | 英文＋日文 |
| `自己開的subagent` | suba 判成日文 | |

`tail_eaten_by_tone1`（英文詞尾被一聲吃掉要罰）擋不到，因為它要求補回字母後
是詞庫裡的常用詞，`chatgpt` 不在詞庫裡。

來源：使用者提供的真人社群貼文（本機評估，`data/private/`，不進版控）。

## 做法

用 `en_50k` 訓練字母三連組（含詞首詞尾標記），給一段字母打「像不像英文」的分數，
只在**詞庫查不到、而且 6 個字母以上**時才問。接在三個點：`prune::keep`
（不放行的話新詞在候選階段就被砍掉，排序救不回來）、`fewer_passthrough`
（不再當殘渣扣分）、`tail_eaten_by_tone1` 的「是英文詞」條件。

原本想用「英文模型 vs 注音按鍵模型」取比值，**走不通**：短的日文羅馬字
（`desu`、`tabe`）在英文三連組上跟真的新詞混在一起，比值分不開。改成只看
「像不像 `en_50k`」本身，才有約 1.6 分的乾淨間隔（`en_50k` 最冷僻 1% 是 −3.71，
注音按鍵串最像英文的是 −5.36）。

## 量到的

| 項目 | 結果 |
|---|---|
| 注音按鍵串誤判成英文 | **0／568** |
| 漏斗 | 1382 → 1382（修 `cursor｜稿`、壞 `logout｜早`） |
| 測資外新句子 90 句 | 59 → 60，壞 0 |
| 真人貼文 152 句 | 93 → 93，逐句相同。chatgpt、subagent 那段切對了，但句子別處還錯 |
| bench_session | 沒變慢（p99 5.83 → 5.48ms） |
| bench_typing | 100 鍵以上、完全沒分隔的純日文長句，最慢一鍵 15.0 → **17.5ms**（超過一幀） |

## 為什麼擱置

1. **6 個字母以下救不到**：`codex`、`kyro` 照樣拆錯。放寬長度，`ru`／`su`／`fu`
   這類注音與假名碎片也會被當成英文
2. **分不出「一個詞」跟「兩種語言黏住」**：`seitannlive`（生誕live）、
   `kaigiroom`（会議room）整串都像英文，更激進的版本會讓它們整段贏過正確切法。
   這是三連組本身的限制，不是門檻沒調好。為此加了三道守門，`english.rs` 新增
   336 行、一半是例外判斷
3. **碰到 `logout` 的舊病灶**：`logout` 不在 `en_50k`，原本靠拆成 `log`＋`out`
   湊分；試過「拆得成兩個常用短詞」來擋，但 `web`＋`hoo` 也符合，會誤傷 `webhook`
4. 效能在極端長句上超出預算 1.5ms（真實測資量不到）

每多救一種情況就要多一條例外，淨效果在漏斗與真人貼文上都是 0。

## 之後的方向

- **技術英文詞庫改成自動產生**（從大型、授權清楚的語料統計常用詞，定期重產），
  不手動一個一個補——手動補是治標
- 學習層（選一次就記住）與擴充包（使用者自己加一批詞）已經有
- 若只想處理最具體的案例：**只在字母中間夾連字號時**才啟用，範圍窄、風險小，
  但只救得到 `codex-with-chatgpt` 這一種寫法。沒做
