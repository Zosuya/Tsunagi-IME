# 啟用哪些引擎：關掉的連辨識都跳過

設定頁可以關掉不用的語言（`behavior.engines`）。**關掉的意思是
完全跳過那個引擎**，不只是鎖定輪替時略過那個模式：

| | 關掉日文後 |
|---|---|
| 自動辨識 | `sushi` 穩定判成英文，不會變「すし」 |
| 單按 Ctrl 輪替 | 自→注→英→自（跳過日文） |
| 正在鎖定日文時關掉 | 退回自動模式 |

不打日文的人準確率會提升——這個輸入法的三語言辨識是特色，
但用不到的語言只會製造誤判。

### 英文不能關

它是瀑布的最後一站（passthrough）。關掉的話有些按鍵組合會沒有
任何語言接得住，輸入法就完全不能用了。

兩個都關掉時**會退回英文**（有測試鎖住），設定頁也會提示
「就只剩英文，跟一般鍵盤沒有差別」。

### 實作：在出口過濾，不在入口攔

語言判斷散在切法引擎的十幾個地方
（`candidates.rs`、`incremental.rs`、`prune.rs`、`rank.rs`…）。
要讓它們知道「日文關掉了」有三條路：

| 做法 | 問題 |
|---|---|
| 設定一路傳下去 | 十幾個函式簽名都要改，容易漏 |
| `validity()` 讀全域開關 | `core` 目前無全域狀態，而且**測試會互相干擾**（一個測試關掉日文，別的就掛了） |
| **在切法出口過濾** | 只有一個地方（`Cascade::recompute`） |

選第三個。切法產生後，把含有停用語言的整條切法丟掉；全被丟光
就退回英文 passthrough。

這也是為什麼 `Engines` 放在 `Session` 而不是全域——它跟著那一次
輸入走，測試各建各的 `Session` 就不會互相影響。
