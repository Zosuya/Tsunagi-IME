# 凍結後語言開關失效：前區與後區重開時用了 Self::new()

**症狀**：設定裡關掉日文，打一句長到會觸發凍結的混語言句子，**整句變成
原始按鍵**。漏斗量不到，因為漏斗永遠是全開。

**根因**：語言開關後來被搬進 `Incremental`（`with_engines`），讓關掉的語言
在切點引擎裡就不出現，而不是等到出口才濾掉（見 [[啟用哪些引擎：關掉的連辨識都跳過]]）。
但凍結那條路上有三處另開引擎，全部用 `Self::new()`，也就是「全開」：

- `maybe_freeze` 的前區重算（前區單獨排一次、取第一名定案）
- `maybe_freeze` 的後區重放（`*self = Self::new()` 再把剩下的鍵推回去）
- `freeze_user_prefix` 的解凍重算

於是日文段被凍進前區。前區在每一條切法裡都有，出口的語言過濾
（`input.rs`）就把整批切法丟光，退回「整句當英文」。

**修法**：三處都改成 `Self::with_engines(self.engines)`。全開時行為逐句
0 差異（漏斗 1335/1464 不變）。

**測試**：`cutpoint::incremental::tests::凍結後語言開關仍然有效`——關掉日文打
一句會凍好幾刀的長句，凍結區與所有切法都不可以有日文段。已確認把修正拿掉
會紅（`hoo` 被凍成日文段）。沒有日文詞庫時跳過（CI 上沒有，同旁邊那條的理由）。

**怎麼發現的**：[[漏斗 1335 之後：六群失敗的診斷與 spike]] 的 E 群在查「凍結
定案選錯」時順手看到的，commit `eed852c`、`02d6ee8`。

> 這是 CLAUDE.md「一個設定套用到兩層實作時，兩邊都要各自實作它的語意」
> 的又一例：開關搬進引擎時，**每一個「另開一份引擎」的地方**都要帶著它。
> 新增任何 `Incremental::new()` 的呼叫前，先問它該不該用 `with_engines`。
