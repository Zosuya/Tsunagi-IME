# 輸入法名稱與工作列圖示

> **狀態**：完成。工作列實際顯示出圖示，五張正式圖（通／ㄅ／あ／A＋自動）都已換上。
> 右鍵選單那半拆去 [[Win11 的輸入指示器不給選單]]。

改名為「通譯輸入法（通 · つなぎ · Tsunagi）」時，順帶查清楚了
Windows 輸入指示器上那個小方塊是誰決定的。

### 3.6.1 名稱改在哪裡

TSF 會露出名稱的地方只有三處，全都是**顯示字串**，不是識別碼：

| 位置 | 使用者在哪看到 |
|---|---|
| `guids.rs` 的 `TEXTSERVICE_DESC` | 輸入法清單、Win+Space 切換器 |
| `lang_bar.rs` 的 `GetInfo` → `szDescription` | 工作列圖示的說明 |
| `lang_bar.rs` 的 `GetTooltipString` | 滑鼠停留的 tooltip（會接目前模式） |

`TEXTSERVICE_DESC` 被 `registration.rs` 的 COM 註冊與 `RegisterProfile`
各用一次，改字串就會一路帶進系統註冊表——**改完必須重新註冊才生效**。

**不能動的**：`CLSID_TEXT_SERVICE`、`GUID_PROFILE`（改了等於變成另一個
輸入法，舊的還會留在系統裡）、`%APPDATA%\通用語言輸入法\`（改了會讓
使用者既有設定失聯，見 CLAUDE.md）。

### 3.6.2 工作列上那個「繁體」是怎麼來的

Windows 的輸入指示器是**兩層**，來源不同：

```text
┌────┬─────────────────┐
│繁體│ 繁體中文 (台灣) │ ← 語言層：Windows 依 LANGID 0x0404 自己產生
│    │ 通譯-Tsunagi    │ ← 輸入法層：TEXTSERVICE_DESC
└────┴─────────────────┘
```

左邊那格**優先顯示輸入法提供的圖示**；拿不到圖示時，才退回用語言名稱
的前兩個字充數。微軟注音顯示「ㄅ」、微軟日文顯示時鐘符號，都是因為
它們有交圖；我們顯示「繁體」是因為**沒交出圖**。

而所謂「交圖」，`registration.rs` **早就寫了**——`RegisterProfile` 的
第 5、6 個參數就是「圖示檔路徑 + 索引」，傳的是本 DLL 路徑與索引 `0`。
真正的問題是 **DLL 裡沒有圖示資源**，Windows 去索引 0 撈了個空。

> 教訓同 [[已解決：TSF profile 註冊回傳 E_FAIL 的真正原因（權限）]]：參數傳對了不代表事情會成，指向的東西也得真的存在。

### 3.6.3 spike：把圖示資源編進 DLL（不加套件）

**要驗的問題**：Rust 建出來的 cdylib 能不能嵌 Windows 圖示資源，
且不引入第三方套件（`embed-resource` / `winresource`）。

**做法**：Windows SDK 自帶 `rc.exe`，用 `build.rs` 呼叫它產生 `.res`，
再用 `cargo:rustc-link-arg` 交給連結器。新增三個檔：

```text
platform/windows/build.rs      找 rc.exe、編資源、傳給連結器
platform/windows/res/ime.rc    資源腳本（第一個 ICON 就是索引 0）
platform/windows/res/ime.ico   圖示本體
```

`build.rs` 找不到 `rc.exe` 時只發 warning 不中斷建置——沒圖示只是難看，
不該讓整包編不起來。

**結果：可行。** 用亮洋紅方塊當測試圖（好認，不會跟系統預設圖混淆），
驗證了三件事：

- `ExtractAssociatedIcon` 從 DLL 撈得到圖示
- 中心像素是 `R=224 G=0 B=200`，正是塞進去的顏色（排除誤撈系統圖示）
- `LoadImage` 指定資源 ID `#1`，16／20／24／32 四個尺寸都撈得到

**圖示規格**（工作列實際用 16×16，但要備多尺寸應付 DPI 縮放）：

| 尺寸 | 對應縮放 |
|---|---|
| 16×16 | 100% |
| 20×20 | 125% |
| 24×24 | 150% |
| 32×32 | 200%、設定頁 |

格式為 32-bit ARGB、背景透明。**Windows 不會幫圖示反色**，深色工作列
配深色圖案會看不見，配色要在深淺主題下都站得住——這句後來成了
3.6.5 整整四輪的主軸。

到此為止驗的都只是「圖示進得了 DLL」。**進得去跟顯示出來是兩件事**，
下一節就是卡在這裡。

### 3.6.4 圖示編得進去，卻還是不顯示：缺的是註冊類別

spike 過了之後接著卡住：那格（微軟注音顯示「中」的位置）**完全不出現**。
症狀極度誤導——`AddItem` 回 `S_OK`、Windows 反覆呼叫 `GetInfo`／`GetText`，
就是不畫。四個必要條件，缺一不可：

| 條件 | 原本錯在哪 |
|---|---|
| 註冊 `GUID_TFCAT_TIPCAP_SYSTRAYSUPPORT` | **主因**。只註冊了 2 個類別，開源專案都註冊 6~8 個 |
| `guidItem` 用 `GUID_LBI_INPUTMODE` | 原本用自訂 GUID，Win8 起會被無聲忽略 |
| 實作 `GetIcon` | 原本回 `E_FAIL`，註解還寫「不用圖示，用文字」——假設完全相反 |
| 設 `TF_LBI_STYLE_SHOWNINTRAY` | 官方常數說明寫「目前不支援」，但微軟自己的 SampleIME 每次 `GetInfo` 都重設一遍 |

第一條是關鍵：缺了「可在系統匣顯示」這個宣告，工作列宿主根本不把這個
TIP 登記進去，**但傳統語言列那條路照樣通**——所以才會「一直被詢問卻
不顯示」。順便補齊 IMMERSIVESUPPORT、INPUTMODECOMPARTMENT、
UIELEMENTENABLED、SECUREMODE、COMLESS，並把清單抽成常數供註冊／反註冊共用。

> 教訓跟 3.6.2 同一個形狀：**東西準備好了不代表系統會來拿**，得先宣告自己
> 供應這件事。

載入圖示時要用**本 DLL 的 module handle**（為此把 `dll_module()` 從
`dll_path()` 抽出來），理由同 CLAUDE.md 那條「唯一合法存取方式」。

順帶修掉一個自己的 bug：`OnClick` 判斷左鍵用 `TfLBIClick(0)`，條件永遠
不成立，點了沒反應。**實測編號是 1=右鍵、2=左鍵。**

### 3.6.5 正式圖示：四輪才讓它在深淺工作列都看得見

測試用的四色方塊換成真圖之後，主要的敵人只有一個——**Windows 不會幫
工作列圖示反色，同一張圖要在淺色與深色工作列上都讀得出來**。

| 輪次 | 做法 | 為什麼不夠 |
|---|---|---|
| 1 | 圓角方塊底＋白字（通／ㄅ／あ／A） | 可行。底色取自 Win11 官方色盤，跟候選視窗同一家族 |
| 2 | 換上使用者的 `doc/icon.svg` 設計稿 | 白填充＋黑細線，縮到 16~24px 時細線被平均成淡灰，淺色底幾乎看不見 |
| 3 | 字形往外膨脹一圈黑色墊底 | 可行，但 100% 濃度在深色底顯得厚重、16px 更擠 |
| 4 | 外框濃度改 65%、加寬版設計稿、先 crop 掉透明邊 | **定案**。四種濃度 × 四個尺寸 × 兩種底色實測比對過 |

幾個站得住的細節：

- **外框 1px 是量出來的**：0 完全看不見，2px 會把 16px 的字內部吃光。
  先超取樣 4 倍再加框，邊緣才不鋸齒
- **那份 SVG 其實不是向量圖**——Affinity 把一張 944×780 的 PNG 用 base64
  包在 `<image>` 裡，所以要先解出點陣圖再自己縮放。也因為沒有路徑可描，
  加框只能用形態學膨脹，不能描邊
- **ICO 容器自己組**：Pillow 的 `save` 只能從單一影像縮放出所有尺寸，
  而我們每個尺寸內容不同（小的有外框、大的沒有）
- **16px 在所有版本都偏擠**，那是線框設計在該尺寸的物理極限，不是處理
  方式的問題

**為什麼寫成產生器**：`.ico` 是二進位，改配色或換字得整組重做——五張圖
乘八個尺寸手工做太容易失手。`res/make_icons.ps1` 管三個模式圖示、
`res/make_icons_from_svg.py` 管 `ime.ico` 與 `mode_auto.ico`，**兩支分開
是刻意的**：不然重跑舊腳本會無聲蓋掉新圖，而 Python 依賴也只出現在
「換設計稿才跑」的那一支。

### 3.6.6 順手踩到的兩個坑

**`build.rs` 只監看 `ime.ico`**：改了 `mode_*.ico` 之後 cargo 認為沒事
發生，資源不重編、DLL 裡還是舊圖，**而且毫無錯誤訊息**。同一個形狀的坑
在 CLAUDE.md 的「驗證新版必須讓宿主整個行程重開」那條也出現過——
**改了沒變先懷疑東西根本沒被重建**。

**`.gitignore` 的 `DOC/` 吃掉了 `doc/`**：Windows 的 `core.ignorecase`
預設是 true，那條為了「相容性測試當次紀錄」加的規則把使用者的設計稿
資料夾整個忽略掉了——icon、主視覺、Affinity 原始檔全都不在 git 裡，
換台電腦就沒了。改成 `test-runs/`，設計稿現在都進版控。
