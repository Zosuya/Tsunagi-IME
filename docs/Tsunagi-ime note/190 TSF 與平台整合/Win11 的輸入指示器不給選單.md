# Win11 的輸入指示器不給選單

工作列那格（微軟注音顯示「中」的位置）**右鍵沒有選單**，而微軟日文
明明有。查了一輪才確定不是我們做錯。

### 3.7.1 症狀與查證

`ITfLangBarItemButton::InitMenu` **從來不會被呼叫**——用檔案 log 確認過，
零次。而且該做的都做了：

- `dwStyle` 帶了 `TF_LBI_STYLE_BTN_MENU`
- `guidItem` 是 `GUID_LBI_INPUTMODE`
- 圖示、註冊類別全部齊備，那格也**確實顯示得出來**（見 [[輸入法名稱與工作列圖示]]）
- 右鍵的 `OnClick` **收得到**（`click == 1`），只是回傳之後系統就沒下文了

查證結果：

| 來源 | 說了什麼 |
|---|---|
| [IME requirements](https://learn.microsoft.com/en-us/windows/apps/develop/input/input-method-editor-requirements) | 通篇沒提過 context menu——**選單不在合約裡** |
| 微軟官方論壇 | 有位韓國輸入法開發者問了一模一樣的兩個問題（InitMenu 不被呼叫、怎麼做出那種選單），工程師回覆後無下文，**至今無解** |
| windows-chewing-tsf、rime/weasel | 兩個成熟專案**各自獨立**採用了同一個繞法 |

微軟日文那個圓角選單是**系統內建寫死的 shell UI**（WinUI MenuFlyout），
第三方拿不到。而且那種 flyout 本來就沒辦法從無視窗的 in-proc DLL 叫出來。

也排除了幾個一開始的假設：跟 `IMMERSIVESUPPORT` 無關（小狼毫註冊了
一樣的類別、用一樣的 `dwStyle`，照樣要自己彈）；跟 LANGID 無關（中文、
韓文都中招）；**也沒有辦法讓 Windows 改用舊樣式對待我們**。

### 3.7.2 三條路與取捨

| 做法 | 外觀 | 工 | 風險 |
|---|---|---|---|
| `TrackPopupMenu` 彈傳統 Win32 選單 | 方正、無圖示 | 小 | 低，兩個專案驗證過 |
| **自繪** | 圓角、可帶圖示、跟候選視窗同一套主題 | 中 | 中 |
| 系統原生 | — | — | 拿不到 |

新酷音與小狼毫都選第一條（`TrackPopupMenu` 配 `TPM_RETURNCMD`，回傳值
直接就是選中的 ID，不必自己開視窗接 `WM_COMMAND`）。本專案選**自繪**——
已經有 Direct2D 繪圖層，不自繪的話輸入法會有兩種視覺語言：候選視窗
圓角現代、右鍵選單方正老派。

自繪有兩個沒把握的地方，所以**先做雛形驗證**再展開：

1. 右鍵點工作列時彈得出視窗嗎？（點擊來自檔案總管，情境跟打字時不同）
2. 關閉時機抓得到嗎？（輸入法沒有自己的訊息迴圈）

兩題都通過，才做正式版（`lang_menu.rs`）。

### 3.7.3 自繪的三個坑

**一、`DestroyWindow` 之前一定要先放掉借用**

它會**同步**送出 `WM_DESTROY`，而那個處理函式又要借同一份
`RefCell`——借兩次會 panic，panic 一穿過 COM 邊界就是整個宿主行程崩潰
（記事本、瀏覽器當場關掉）。雛形第一次實測就是這樣把程式弄掛的。

```rust
// 錯：借用還握著就銷毀
MENU.with(|m| { if let Some(h) = m.borrow_mut().take() { DestroyWindow(h); } });
// 對：先取出來讓借用歸還，再銷毀
let hwnd = MENU.with(|m| m.borrow_mut().take());
if let Some(h) = hwnd { DestroyWindow(h); }
```

> 更廣的教訓：**輸入法比一般程式更不能讓 panic 逃出去**。一般程式當掉
> 是自己的事，我們當掉是把使用者正在編輯的文件一起帶走。Rust 的借用
> 檢查有一部分是執行期才查的（`RefCell`），它「擋住」的方式就是停止程式。

**二、動作要在關掉選單之後才執行**

選單的動作會回頭改 `text_service` 的狀態、甚至重畫語言列。選單還活著
的時候執行容易繞回來重入。正確順序是：把回呼取出來 → 關掉選單 →
才執行動作。

**三、彈選單前要放掉 `state` 的鎖**

選單的回呼會再動同一份狀態，而那個鎖**不可重入**——還握著就卡死。
（同一個坑在 `OnKeyDown` 誤加第二次上鎖時踩過，見 [[架構決策與程式碼導覽]]。）

### 其他設計決定

- 視窗**不接受鍵盤焦點**（`WS_EX_NOACTIVATE`）——搶走的話宿主會以為
  自己失焦而藏起插入點。代價是收不到按鍵，所以**沒有 Esc 關閉**，
  全靠 `SetCapture` 攔截視窗外的點擊。
- 打勾用**小圓點**而不是「✓」——使用者可以自選字型，那個字不一定有。
- 語言項目**依設定過濾**：關掉的引擎不列出來，不然會是選了沒反應的死項目。
- `InitMenu` **留著沒刪**——傳統語言列與安全桌面（UAC）那些舊宿主還是
  會呼叫它，新酷音與小狼毫也都保留。
