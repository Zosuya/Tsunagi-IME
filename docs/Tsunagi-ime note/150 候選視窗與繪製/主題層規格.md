# 主題層規格

## 4.1 為什麼要有主題層

現在 `candidate_window.rs` 裡的顏色、字型、尺寸全是散落的常數：

```rust
FillRect(hdc, &rc, CreateSolidBrush(COLORREF(0x00F5FCFF)))
//                                          ↑ 這是「視窗背景」還是「候選列背景」？
```

同一個數值可能代表好幾種語意，看不出差別。等要做深色模式，才會發現
「背景」其實有五、六種不同角色，而程式碼裡全部混在一起。

**主題層的本質是先把「角色」命名清楚**，繪圖時取用的是名字而不是數值。
做完之後換配色、加深色模式、讓使用者自訂，都只是換一組數值進去，
繪圖程式碼再也不用動。

## 4.2 使用者的決定（2026-08-29）

| 項目 | 決定 |
|---|---|
| 檔案位置 | **兩處都支援**——內建在 `data/themes/`，使用者自訂在 `%APPDATA%`，同名時使用者的優先 |
| 缺欄位 | **補預設**。整份解析失敗就退回內建預設主題，輸入法照常運作 |
| 深淺色 | 設定內可調，**第一版先固定一套**，不讀系統主題 |
| 排列方式 | **全部維持直排**（選字與切法選單都是一行一個） |

> 輸入法不能因為配色檔有錯就打不了字——這是「缺漏補預設」的理由。

## 4.3 顏色角色

不是列顏色，是列**用途**。深色模式就是同一組角色換一組值。

| 角色 | 用在哪 | 預設值（淺色） |
|---|---|---|
| `window_bg` | 整個 popup 的底 | `#FBFBFB` |
| `border` | 視窗外框 | `#D0D0D0` |
| `text` | 候選字 | `#1A1A1A` |
| `index` | 候選字前的編號 | `#909090` |
| `highlight_bg` | 反白那一列的底 | `#0078D4` |
| `highlight_text` | 反白那一列的字 | `#FFFFFF` |
| `highlight_index` | 反白那一列的編號 | `#C8E0F5` |
| `preview_text` | 預覽列的文字 | `#0060A8` |
| `preview_bg` | 預覽列的底（跟視窗同色＝不特別畫） | `#F2F7FB` |
| `separator` | 預覽列與候選清單之間的線 | `#E4E4E4` |
| `marker` | 【】那種輔助符號 | `#A0A0A0` |

編號跟候選字**必須是不同角色**——新注音的層次感就來自這個差異，
現在兩者同色同大小是它看起來擠的原因之一。

## 4.4 字型

| 欄位 | 說明 | 預設 |
|---|---|---|
| `family` | 字族。空字串代表跟隨系統 UI 字型 | `""`（跟隨系統） |
| `size_pt` | 候選字級（點） | `12` |
| `index_size_pt` | 編號字級，刻意比候選字小 | `9` |
| `preview_size_pt` | 預覽列字級 | `11` |

現在用的 `DEFAULT_GUI_FONT` 是 Win95 時代的遺產，中文會很醜。
跟隨系統要讀 `SystemParametersInfo(SPI_GETNONCLIENTMETRICS)`。

## 4.5 尺寸與間距

**這些是「邏輯像素」，實際繪製時要乘上 DPI 縮放係數。**
高 DPI 螢幕若用實際像素會糊掉或過小；這件事一開始沒訂，之後補等於
每個數字都要找出來改。

| 欄位 | 說明 | 預設 |
|---|---|---|
| `line_height` | 每一列的高度 | `28` |
| `padding` | 視窗內距 | `8` |
| `min_width` / `max_width` | 視窗寬度範圍（內容決定實際寬度） | `160` / `480` |
| `corner_radius` | 圓角半徑，`0` 為直角 | `6` |
| `index_gap` | 編號與候選字之間的間隔 | `8` |

寬度改成**依內容計算**而不是固定 200——切法選單列的是整句，
固定寬度會截斷。

## 4.6 設定檔格式

```toml
# data/themes/default.toml

[colors]
window_bg      = "#FBFBFB"
border         = "#D0D0D0"
text           = "#1A1A1A"
index          = "#909090"
highlight_bg   = "#0078D4"
highlight_text = "#FFFFFF"
# 其餘欄位省略不寫就用內建預設

[font]
family   = ""      # 空 = 跟隨系統 UI 字型
size_pt  = 12

[metrics]
line_height   = 28
corner_radius = 6
```

顏色用 `"#RRGGBB"` 字串而非 Rust 的 `COLORREF`——後者是 BGR 順序，
寫設定檔的人會搞錯。解析時再轉。

## 4.7 讀取順序

```
1. %APPDATA%\通用語言輸入法\themes\<name>.toml   ← 找到就用
2. <專案>\data\themes\<name>.toml                ← 退而求其次
3. 程式內建的預設值                                ← 最後防線
```

三層都可能缺，每一層都不是錯誤。**任何一步失敗都靜默退到下一層**，
輸入法照常運作。

## 4.8 實作順序

分兩步，第一步做完繪圖程式碼就定型了：

1. **抽出 `Theme` 結構**（不引入任何套件，不改行為）——把散落的常數
   集中，繪圖只認欄位名稱。這一步本身就有價值：改配色只要動一個地方。
2. **加載入器** `Theme::from_file()`——引入 `toml` 與 `serde`
   （使用者 2026-08-29 已核准）。
