# 換掉 GDI：改用 Direct2D + DirectComposition

候選視窗的繪製從 GDI 換成 D2D + DComp。[[spike：Direct2D + DirectComposition]]
的 spike 在 2026-08-29 就驗過可行，但留了三個「尚待確認」的項目沒回頭決定，
就繼續在 GDI 上疊功能——直到底圖需求撞上 GDI 的天花板才回來做。

### 換之前先量

寫了 `platform/windows/src/bin/bench_render.rs`，同樣的內容各畫 300 幀：

| | GDI | D2D + DComp |
|---|---|---|
| 初始化 | 0.06 ms | **130 ms**（只做一次） |
| 每幀平均 | 1.88 ms | **0.14 ms** |
| 每幀 p99 | 2.4 ms | 0.6 ms |
| 最差 | 6–8 ms | 3–8 ms |

三次測試數字一致。

**但速度不是換的理由**——GDI 的 p99 只有 2.4ms，在
Phase 5 訂的 16ms 預算裡本來就夠用。真正的理由是畫質：

| | GDI | D2D |
|---|---|---|
| 圓角 | `SetWindowRgn`，**鋸齒** | `FillRoundedRectangle`，反鋸齒 |
| 半透明 | 無（只能混色模擬） | 原生 |
| 漸層 | `GradientFill`（msimg32） | 漸層筆刷，更平順 |
| 圖片縮放 | 最近鄰 | 雙線性 |

「最差值」兩者相當（3–8ms），那是系統排程造成的，跟繪圖 API 無關。

### 分兩階段做

| 階段 | 做什麼 | commit |
|---|---|---|
| 一 | 把 D2D 封裝成 `d2d.rs`，不動候選視窗 | `40ed6e3` |
| 二 | 改寫 `paint()` | — |

階段一可以獨立驗證（`d2d::tests` 的冒煙測試建立整條
D3D→DXGI→D2D→DComp 鏈路並真的畫一幀），確認元件可用再動正式程式碼。

### 什麼沒有動

**版面計算（`layout`）、動畫（`slide`）、主題（`theme`）全部沿用。**
換掉的只有「怎麼把東西畫到螢幕上」這一層——這正是那些模組當初
拆出來的價值。

主題尤其明顯：`theme.rs` 的顏色角色是平台無關的資料，D2D 版只是
多一個 `Color → D2D1_COLOR_F` 的轉換，深淺兩組主題完全不必重做。

### 三個踩到的坑

**一、`WS_EX_NOREDIRECTIONBITMAP` 是 DComp 的前提。**
沒有它的話系統會替視窗準備一張不透明的重導向點陣圖，把合成器畫的
內容蓋掉——看起來就是全黑。

**二、幾何型別在另一個 crate。**
`Vector2`（漸層筆刷的端點）、`Matrix3x2` 在 `windows-numerics`，
不在 `windows` 裡。spike 當時是繞過去（不用 transform），但漸層的
`startPoint` 是結構欄位，沒得繞——加了那個依賴（它本來就在
`Cargo.lock` 裡，是 `windows` 0.62 自己的相依）。

**三、`BeginDraw` 給的貼圖不保證從 (0,0) 開始。**
可能是一大塊貼圖的一角，所有座標都要加上回傳的偏移。`Frame` 型別
把這件事包起來，呼叫端用視窗座標就好。

### 量與畫必須用同一個引擎

一開始 `measure_width`（算視窗該多寬）**留著用 GDI**，理由是時機：
視窗寬度要在 `CreateWindowExW` 之前算出來，而 renderer 要有視窗
才建得起來——先有雞還是先有蛋。

當時判斷「差幾像素不影響」，**那是錯的**。差異會隨長度累積：

| 文字長度 | GDI 與 DirectWrite 的差 |
|---|---|
| 10 字 | −8px |
| 30 字 | +2px |
| 58 字 | **+35px** |

實測 log：`w=401 avail=385 full=436 scroll=51`——視窗只有 401px，
文字要 436px，預覽列就被推出可視範圍，開頭看不見。

**解法是把量測獨立出來**：`TextMeasurer` 只持有 DirectWrite 的
factory，而那個 factory **不需要視窗**。先有雞先有蛋的問題其實
繞得開。現在量寬度、量換行高度、繪製全部同一個引擎。

一般化的教訓：**同一件事用兩套實作量，誤差會累積**。這跟 [[版面高度只能有一個算法]]
是同一類問題，只是這次跨的是繪圖引擎
而不是函式。

### 初始化的時機

130ms 不能在第一次打字時付。目前做在**建視窗時**（第一次叫出候選），
實測沒有明顯卡頓。如果之後發現有感，就移到輸入法啟用（`Activate`）
時做——跟詞庫預載搭同一班車。
