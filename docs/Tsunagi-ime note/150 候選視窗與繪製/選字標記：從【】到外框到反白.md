# 選字標記：從【】到外框到反白

選字時預覽列要標出「正在選哪一格」。這個標記改過兩次：
全形括號（`【你】好`）→ 細外框 → **反白**（現行）。

### 為什麼不用【】

- **預覽列的用意是「送出去會長這樣」**。混進不會送出的符號就不誠實，
  使用者得自己在腦中把括號濾掉。
- 全形括號**很佔位置**。一格字加兩個全形符號等於三倍寬，句子長一點
  預覽列就被推爆。框不佔任何寬度。
- 標記的位置會**跟著文字跑**。括號是文字的一部分，換一格選字整句
  的字都往旁邊挪；框是畫上去的，文字不動。

### 怎麼實作

介面上多傳一個「要標哪一段」的**位元組範圍**，不是傳已經加好符號的
字串——那樣候選視窗就得反過來猜哪些字元是標記。這個切法讓標記
換了兩次長相都不必動 `text_service.rs`。

| 層 | 負責什麼 |
|---|---|
| `text_service.rs` | 算出選中那一格在預覽字串裡的位元組範圍 |
| `candidate_window.rs` | 量字寬定位、畫反白塊與反白字 |

位置靠量字寬算：標記前面那段有多寬就是左緣，加上標記那段的寬度
就是右緣。`DrawTextW` 從 `pad` 開始往右畫，所以量出來的寬度就是
實際位置。

### 一個 GDI 陷阱

`RoundRect` 會**同時填色與描邊**，兩者用的是目前選定的筆刷與畫筆。
要一整塊同色就得把兩個都換成同一個顏色，只換其中一個會多出一圈
不同色的邊。（畫空心框則相反：筆刷要換成 `NULL_BRUSH`，
否則框內會被塗滿把字蓋掉。）

### 再改一次：外框不夠顯眼，改成反白

外框解決了上面三個問題，但**小字級下太細**——使用者實測回報
「不好辨識」，得盯著找框在哪。

定案是**反白**（實心底色＋反白字），用的是**跟候選清單同一組顏色**
（`highlight_bg` / `highlight_text`）。理由是「選中」這件事在整個
視窗裡只有一種長相，使用者不必多記一個顏色的意思。

繪製順序**底色先、字後**——反過來會被蓋掉。反白那一段的字要換色，
做法是整句畫完再把那一段**在原地重畫一次**：`DrawTextW` 沒有
「從第幾個字開始」的參數，位置是靠前面那段的寬度推出來的，
補畫比自己逐段排版簡單，字距也不會跑掉。

### 三個版本的比較

| | 【】 | 外框 | 反白（現行） |
|---|---|---|---|
| 預覽列的誠實度 | ✗ 混進不送出的符號 | ✓ | ✓ |
| 佔位 | ✗ 三倍寬 | ✓ 不佔 | ✓ 不佔 |
| 換格時文字不動 | ✗ 整句跟著挪 | ✓ | ✓ |
| 辨識度 | ✓ | ✗ 小字級太細 | ✓ |

### 顏色

`highlight_bg` / `highlight_text`，跟候選清單共用。[[主題層規格]] 的表裡那個
`marker` 角色是最初的規劃，實作時已經跟 `preview_text` 合併，
現在連框都不畫了，沒有新增任何設定欄位。
