# spike 5：快捷鍵攔截

[[macOS 移植的 spike 排序：先做 Echo 輸入法，五個全部結案]] 最後一個 spike，是 §2.14 在 Mac 上重量一次。工具是
`platform/macos/src/keyprobe.rs`，**行格式刻意跟 Windows 那支一致**，
分析共用 `tools/keyprobe.py`（加了一張 `MAC_SHEET`，靠 log 裡有沒有
`Cmd+` 自動選表），兩邊的結果才並排比得了。

量測點只有一個：`handleEvent:client:`——IMK 唯一把按鍵交給我們的地方。

### 結果（TextEdit／Safari／終端機／VS Code，100 筆）

**「到得了」= 至少在一個宿主看得到**，理由見底下「這批資料的限制」。

| 組合 | 到得了？ | 備註 |
|---|---|---|
| `Tab`、`Esc`、`Shift+Space`、四個方向鍵 | ✅ | 我們自己要用的都拿得到 |
| `Cmd+C`／`V`／`X`／`Z`／`S`／`F`／`P` | ✅ | **宿主自己的快捷鍵不會擋住輸入法看到它們** |
| `Cmd+Space`、`Ctrl+Cmd+Space`、`Cmd+Tab`、`Cmd+Q`、`Ctrl+↑` | ❌ | **系統在輸入法之前就攔走**，綁上去不會有反應 |
| `Option+Q`、`F1`／`F2`／`F9` | ✅ | 三個文字宿主都到得了 |
| `Cmd+A`／`W`／`T`／`N`、`Cmd+F9`、`Ctrl+Option+J`／`K` | ❓ | 沒在任何宿主看到，但覆蓋不足，不能斷言被擋 |

跟 Windows §2.14.2 一致的一條：**宿主的快捷鍵不擋輸入法**——`Cmd+C` 到得了，
是我們主動放行才交還給宿主的。系統級那一類也一致（Windows 是
`Win+空白`／`Alt+Tab`，macOS 是 `Cmd+空白`／`Cmd+Tab`）。

### ★ 最有價值的發現：Option 系在兩個平台是相反的問題 ★

| | Windows（§2.14.2） | macOS |
|---|---|---|
| `Alt`／`Option` 系組合 | **四個宿主全沒到**——到不了，所以不能用 | **到得了**——但**更不能用** |

macOS 的 `Option+字母` **是輸入特殊字元的正規用法**（`Option+A` 打 å、
`Option+R` 打 ®、`Option+V` 打 √…）。這次清單外意外收到一整批
`Option+A/D/G/R/V/W/Z` 就是這樣來的——**它們到得了，正是因為那是使用者
真的在打字**。

> **結論相同、理由相反**：兩個平台的 `Alt`／`Option` 系都不能拿來綁快捷鍵。
> Windows 是「拿不到」，macOS 是「拿得到但那是別人的地盤，綁了會讓使用者
> 打不出 å ®  √」。

這條直接影響 Mac 版的鍵位設計：**可用的空位只剩 `F1`～`F12` 那一類**，
而 `Cmd` 系幾乎都被宿主或系統佔滿。所幸 CLAUDE.md 早就寫著「快捷鍵自訂
明確決定不做」，鍵位表由我們自己定，這個限制不致命。

### IMK 沒有「先問再送」這回事

§2.14.3 在 Windows 上最有價值的發現是**宿主分兩派**：Word 幾乎都先問
`OnTestKeyDown`，記事本幾乎都直接送 `OnKeyDown`，因此「任何依賴那個回答
的邏輯，兩個入口都要各做一次」。

**macOS 沒有這個問題**：IMK 只有 `handleEvent:client:` 一個入口，這次
100 筆全部是「直接送」。少一個要處理的分歧。

### 這批資料的限制（照 §2.14.2 的規矩，說清楚哪裡不採信）

各宿主按到的相異組合數差很多——TextEdit 19 種、Safari 13 種、終端機 6 種、
**VS Code 只有 1 種**。所以**「某個宿主沒到」這一格同時混著「被擋掉」與
「根本沒按」兩種意思**，逐宿主的表不能拿來比較宿主之間的差異。

這是**探針設計上的缺陷，不是操作問題**：它只記「看到了什麼」，無從知道
「什麼沒被按」。所以上表一律用**聯集**（至少一個宿主看得到就算到得了），
那個方向是安全的——看得到就一定不是被系統擋掉。

要拿逐宿主的差異當結論，得先有一個**照著清單逐格提示、記錄進度**的測法。
留給日後真的要加鍵位時做，跟 §2.14.2 對 Brave／Firefox 的處置同一個道理。

### 順手修掉的：方向鍵，兩個問題疊在一起

量測時發現按方向鍵組字區會冒出看不見的東西。原因是 `on_key` 只擋
`is_control()`，而 **macOS 把方向鍵、F1～F12、Home/End 對應到
U+F700～U+F8FF 的私用區**，那一段 `is_control()` 是 false，於是被當成一般
字元收進緩衝。

**但只擋掉還不夠**——擋掉等於讓回宿主，而宿主收到方向鍵就去移動自己的
游標，**組字區當場被打斷**（實測：按方向鍵組字狀態整個消失）。我第一次
只解了一半。

正解是**組字中一律吃掉，沒組字才讓回宿主**，跟 Esc／Enter／Backspace
同一個模式。Home／End／PageUp／PageDown 一起處理——它們同樣移動游標，
後果一樣。Echo 沒有候選清單也沒有組字區內游標，所以先單純吃掉不做事；
**接 core 之後這些鍵要拿來在組字區內移動、或在候選清單裡選字**。
