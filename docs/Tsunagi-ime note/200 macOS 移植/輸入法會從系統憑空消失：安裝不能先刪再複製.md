# 輸入法會從系統憑空消失：安裝不能先刪再複製

spike 4 量到一半（測完第 3 個宿主 Safari 網頁欄位）**輸入法整個從系統
不見了**——選單裡沒有、打不出字。

**現場證據**（每一條都當場量的）：

| 檢查 | 結果 |
|---|---|
| `~/Library/Input Methods/Tsunagi.app` | 在，內容完整 |
| `codesign -v` | 有效 |
| `plutil -lint Info.plist` | OK |
| 輸入法行程 | **還活著**（成了孤兒——系統認為這個輸入法不存在） |
| `TISCreateInputSourceList(nil, true)` | **318**（原本 320），第三方 **0** |

**修復只要一行**，不用登出、不用重開機：

```
TISRegisterInputSource(bundle URL)      # tisq register
```

叫完立刻 318 → 320，啟用狀態也一起回來。

### 成因（2026-09-08 稍後查明）：FSEvent 的重掃比我們晚落地

**先前這裡寫的是「`rm -rf` 到 `cp -R` 之間的空窗被掃到」——方向對、機制錯，
而且照那個推論做的修法（縮短空窗）根本沒用。** 底下是四個受控實驗量出來的：

| 實驗 | 結果 |
|---|---|
| 只跑 `tisq register`，不換 bundle | **60 秒紋風不動** |
| 只換 bundle（不重編、不 `pkill`、不 `open`），換完立刻 register | **3 秒後掉** |
| 換 bundle 之後**完全不 register** | **5 秒後就不見了** |
| 換 bundle → **等 5 秒** → 才 register | **60 秒紋風不動** ✅ |

所以：

> **替換 `~/Library/Input Methods/` 底下的 bundle 會發出 FSEvent，系統因此
> 重掃一次輸入源——而那次重掃寫出來的快取「不含我們」，並且比我們的
> `TISRegisterInputSource` 晚 3～5 秒落地，把好的結果蓋掉。**

判準是檔案大小：含我們的快取是 **139752** bytes，不含的是 **139252**。
掉出去之後那個檔就是 139252。

**「換完立刻登記」擋不住它**——順序是「我們先寫對的、系統後寫錯的」。
這也解釋了為什麼縮短 `rm`／`mv` 空窗沒有用：問題不在空窗多長，在那次
重掃的**結果**與**時機**。

（那次重掃為什麼會寫出不含我們的結果，還沒查到——追蹤裡看不到它，
推測是做重掃的行程沒有帶到 `AppleTISTraceCacheRebuild` 這個旗標，
或它拿的是事件當下的目錄快照。**不影響修法**，所以停在這裡。）

### 對策（已經做了，並且驗證過）

`build-app.sh` 的登記改成三件事：

1. **先讓它掉**——換完 bundle 之後 `sleep`，等 FSEvent 的重掃落地
2. **再登記**
3. **登記完要驗證**，沒站穩就重試（最多五次）

驗證這一步不能省：時間差不保證固定，不驗的話又會變成「大部分時候可以」
的東西。實測跑完整建置後盯 45 秒，穩定。

另外兩件仍然保留，它們是對的：

- **先複製到旁邊再 `mv` 換過去**，空窗縮到一瞬間
- `tools/tisq.swift` 跟 `.app` 一起建到 `target/tisq`

### 這條會跟到正式版

**不是只有開發時會踩。** 使用者那邊同樣可能因為別的原因掉出快取（升級、
第三方工具清快取、或是這次還沒查明的那個觸發點）。所以：

- **安裝流程是「複製完再換」→ 等 FSEvent 的重掃落地 →「才註冊」→「驗證」**。
  ~~換完立刻註冊~~ 是錯的，會被那次遲到的重掃蓋掉
- **設定頁要留一個「重新向系統登記」的按鈕**。症狀（輸入法在選單裡憑空
  不見）跟解法（按一下）之間毫無關聯性，使用者自己絕對想不到，而這是
  目前唯一已知的修法。列進 Phase 6 的 macOS 待辦
