# 執行模型的根本差異

Windows 的 DLL 被載進**每一個宿主行程**；macOS 的輸入法是**一個獨立的
`.app` 行程服務所有 App**。連帶影響：

- mmap 省多行程記憶體的好處消失（無害，單行程本來就只一份）
- 崩潰隔離的意義變了：panic 不會帶垮宿主，但會讓輸入法整個掛掉、系統
  自動重啟。`catch_unwind` 那套照做，目的從「保護宿主」變成「保住組字
  狀態」。unwinding 穿過 `extern "C"` 一樣會 abort，每個 ObjC 方法覆寫
  都要包
- `build-ime.ps1` 那個「DLL 被鎖」的坑不存在，換成殺掉輸入法行程讓系統
  重啟；「宿主要整個重開」這條也不存在
- 修飾鍵：macOS 的修飾鍵走 `flagsChanged`、**不自動重複**，§2.44 那類
  bug 消失，但 `CtrlTap` 的偵測要改寫
