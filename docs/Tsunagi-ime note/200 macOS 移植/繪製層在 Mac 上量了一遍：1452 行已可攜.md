# 繪製層在 Mac 上量了一遍：1452 行已可攜

接著 [[spike 1 在真的 Mac 上重跑：core 原生過，但翻出三個靜默的洞]]，把「繪製層」在真機上量清楚。**先講結論**：繪製的**決策**
幾乎全部已經是可攜的，而且今天在 Mac 上跑過了；真正要重寫的只有 `d2d.rs`。

**怎麼量的**：在暫存區開一個小 crate，用 `#[path]` 指到 repo 裡的**真檔案**
（不複製、不搬動），在 macOS 上編譯並跑它們自己的測試。量的是「原封不動
搬過去會怎樣」。

| 檔 | 行數 | 測試 | 碰 Windows 的地方 | 在 Mac 上 |
|---|---|---|---|---|
| `core/src/render.rs` | 381 | 13 | 無（本來就在 core） | **過**（已含在 532 裡） |
| `slide.rs` | 345 | 12 | **0 處** | **過，一個字都沒改** |
| `width_bar.rs` | 388 | 18 | **0 處** | **過，一個字都沒改** |
| `theme.rs` | 338 | 9 | **1 處**：`to_colorref` | **過**，餵一個只含 `COLORREF` 的假 crate |
| `candidate_window.rs` | 2399 | 33 | 37 處 | 沒編（見下） |
| `d2d.rs` | 1129 | 1 | 115 處 | 不用試，本來就要重寫 |

**1,452 行、52 個測試已經證實在 macOS 上跑得起來**（render 381＋slide 345
＋width_bar 388＋theme 338）。[[移植前的程式碼盤點：平台層 11700 行重寫，約 1900 行可上搬 core]] 當初估「約 1,900 行純邏輯可上搬」，
量下來是同一個量級。

**`theme.rs` 只卡在三行**：整份唯一碰 Win32 的是

```rust
pub fn to_colorref(self) -> COLORREF {
    COLORREF((self.b as u32) << 16 | (self.g as u32) << 8 | self.r as u32)
}
```

——`COLORREF` 是 **BGR** 順序，那是 Win32 的特性，本來就該留在 Windows 側。
Mac 那邊對應的是轉成 `CGColor`／`NSColor`。**其餘 335 行照搬。**

### 候選視窗：33 個測試全是純幾何，但卡在一個具體型別

`candidate_window.rs` 的 33 個測試**全部是版面幾何**——命中測試、捲動、
螢幕邊緣翻轉、多螢幕負座標、高度計算、捲軸滑塊長度。這些正是「繪製的
決策」，跟平台無關；`layout` / `layout_with` 的簽章也已經是純整數：

```rust
fn layout_with(pad: i32, line_h: i32, has_preview: bool,
               list_h: i32, empty: bool, has_hint: bool) -> (i32, i32)
```

**卡住的是文字量測**。`layout_preview` 直接吃具體型別：

```rust
fn layout_preview(renderer: &Renderer, text: &str,
                  font: &IDWriteTextFormat, gap: f32) -> Vec<(usize, usize, f32, f32)>
```

而 `TextMeasurer` 是**具體結構**（包著 `IDWriteFactory`），不是 trait——
所以版面程式碼是被具體型別綁住的，不是被抽象綁住的。

**好消息是綁得很淺**。整條版面路徑對 DirectWrite 的需求數得完，就 4 個：

| 方法 | 做什麼 | macOS 對應 |
|---|---|---|
| `measure` | 量寬（**不含尾端空白**，見 §2.46 的坑） | CoreText |
| `measure_advance` | 量前進寬度（**含**尾端空白） | CoreText 另有 `CTLineGetTrailingWhitespaceWidth`，同一個區分它也有 |
| `clusters` | 切字素叢集（`👩‍💻` 算一個、注音聲調不分家） | CoreText |
| `measure_wrapped` | 給最大寬度，量換行後的尺寸 | CoreText |

**所以繪製層要上搬 core，關鍵動作是把 `TextMeasurer` 從具體結構換成
trait**，兩個平台各實作一份。做完之後 `candidate_window.rs` 那 2,399 行
裡的版面決策（含 33 個測試）就能跟 `render.rs` 併在一起，兩平台共用。

**還沒驗、也驗不了的**：CoreText 那一欄是**查文件推的，沒有實測**——
真的要量得先寫 Rust↔CoreText 的綁定，那要 `objc2` 系列依賴，卡在
[[macOS 移植的六項待決：四項裁決，不做語言鎖定一天就推翻]] 待決 2。**§2.46「DirectWrite 的 width 不含尾端空白」那個坑在
CoreText 上會不會以另一種形式再咬一次，目前是未知數**，spike 3 要一起量。
