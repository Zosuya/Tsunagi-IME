# 設定的行為稽核：領域包與 enter_in_select 在 macOS 都沒接

外觀那半稽核完（[[設定頁依平台隱藏無效的欄位]]／[[設定頁的預覽字型：跟系統要表，不要檔案]]）之後把「行為」也對一遍，方法是拿
Windows 的 `background::apply_config`／`refresh_config` 逐行比對 macOS 的
`settings::apply_to`。又是同一類：**設定頁改得動，輸入法不理它**。

| 設定 | macOS 現況 |
|---|---|
| 全半形預設、啟用的引擎、倒退鍵刪整格、鎖定注音的標點 | 有接 |
| **領域包**（`behavior.packs`／`packs_dir`） | **整個沒接**——`pack::load` 從來沒被呼叫過，設定頁的擴充包分頁在 macOS 上等於裝飾 |
| **`enter_in_select`**（選字時 Enter 往下一格／直接退出） | **沒接**，一律當成「往下一格」 |

### 領域包：時間戳要跟設定分開記

包是**獨立的一層**，換掉索引就生效，不必重建詞庫（詞庫是 `OnceLock`，
重建不了）。所以它的重載判斷不能掛在「設定檔變了嗎」底下——**使用者可能
直接編輯包檔案而沒動設定**，只看設定的時間戳就會漏掉那種情況。Windows
那邊本來就是分開的兩個時間戳，macOS 照抄。

預載包目錄（`paths::bundled_packs_dir`）對應 Windows 的
`registration::bundled_packs_dir`，兩條路：`.app/Contents/Resources/packs`
（正式安裝），或**詞庫目錄的隔壁**（開發用——詞庫是 `$ROOT/data`，包就在
`$ROOT/packs`）。開機印出來，因為找不到的症狀是「擴充包開了沒作用」，
從畫面上看不出是路徑錯還是包壞了。

### Enter：數字鍵與滑鼠刻意不看這個設定

`enter_in_select` 接在 Enter 這條路上。**數字鍵與滑鼠那兩條路仍然一律
「選完就收掉清單」**——那是明確指名某一個候選，跟方向鍵逐格慢慢挑不是
同一回事。（Windows 那邊三條路都看這個設定，這是刻意的分岔，不是漏抄。）

### 使用者裝的包放哪：位置沒錯，但「開啟資料夾」按了沒反應

實測回報「`~/Library/Application Support/tsunagi-ime/packs` 這位置對嗎，
現在他說資料夾不存在」。**位置是對的**——那跟 `config.toml` 同一個資料夾，
是 `config::user_dir()` 決定的，兩個平台同一條規則（Windows 是
`%APPDATA%\tsunagi-ime\`）。它一開始不存在很正常，那是給使用者自己裝的
包用的；**內建的兩個包不走這裡**（走 bundle 的 `Resources/packs` 或開發時
的 `$ROOT/packs`），所以符號照樣能用。設定頁本來就有「建立」按鈕。

但旁邊那個「開啟資料夾」在 macOS 上**按了完全沒反應**——三處都寫死
`explorer`。收成一支 `reveal_folder`，依平台換指令（`explorer`／`open`／
`xdg-open`），順便**不存在就先建**：按了說「找不到」比什麼都不做更讓人
困惑，而按這個按鈕的意思本來就是「我要把東西放進去」。

「找不到可用的位置（%APPDATA% 讀不到？）」這句也改成不提平台。

### 這四節的共同教訓

[[設定頁依平台隱藏無效的欄位]] 起連著四節，抓到的全是同一個形狀：**設定頁改得動、輸入法或預覽
不理它**。而且每一個都是「沒有錯誤訊息、看起來很正常」的失敗。跨平台移植
的檢查清單因此要加一條：

> 移植一個平台層時，**逐項對照另一邊怎麼消費設定**，不是只看功能會不會動。
> 功能會動、設定不生效，是不會有任何症狀的一種壞掉。
