# Mac 送出時把沒成字的注音也送出去：追了五輪的定位過程

> **狀態**：**已修（`ca9ec05`），2026-09-27 使用者 Mac 實機驗過。**以下是當時的狀態：根因確認，修法待兩件查證（文末）。2026-09-19～20 使用者實測回報。

**症狀**：鎖定注音打「你好」，按一次倒退鍵，**直接送出**——

| | 送出的結果 |
|---|---|
| Windows | 「你」 ✅ |
| macOS | **「你ㄏㄠ」** ❌ |

## 根因：一支函式兩種用途，而兩種用途的需求相反

`platform/macos/src/echo_ime.rs` 的 `commit()` 用 `self.composition()`
當送出內容，而那支的實作是

```rust
let mut t = s.text();
t.push_str(&s.pending_symbols());   // ← 還沒湊成字的注音
t
```

`pending_symbols()` 就是那個 `ㄏㄠ`——退格之後退回音節緩衝、還沒成字的殘渣。

對照 Windows：送出走 `EndKind::Commit(&text)`，而 `text` 來自
**`state.session.text()`**，不含 pending。

`composition()` 本來是**給組字區顯示用的**——顯示時當然要把還在打的注音畫出來，
不然使用者看不到自己按了什麼。**Mac 把它拿來當送出的內容了。**

> **這支已經咬過兩次**：設定頁「怎麼打」欄拿到國字也是它
> （[[Mac 設定頁的按鍵欄拿到國字：兩平台刻意不一致，撞在一起]]）。
> 同一個地方、兩個不同的 bug，值得一次掃乾淨。

## ★ 追了五輪才對上，過程比結論值錢 ★

這條從回報到定位走了五輪，**每一輪都被某個東西誤導**。記下來是因為
下次遇到同一類問題可以少繞幾圈。

| 輪 | 當時的判斷 | 被什麼誤導 |
|---|---|---|
| 1 | 「Mac 沒有組字區」 | 使用者的描述——Mac **有**組字區，只是顯示國字 |
| 2 | 「Shift+Backspace 該刪整個字」 | 鍵位記錯。鎖定注音用的是**單獨倒退鍵**，`Shift+` 那個是自動模式選字層的三態設定 |
| 3 | 「Mac 反白框沒建立」 | 合理但錯。兩平台的框機制其實對稱 |
| 4 | 「程式碼說兩邊都該壞」 | 調查把 `slots().len() - 1` 看成「刪一個注音符號」，**實際是刪掉整格** |
| 5 | 「Windows 也是 `你ㄏㄠ`，沒有 bug」 | **看圖看錯了**——畫面上的 `ㄏㄠ` 是殘渣不是格，送出才知道差別 |

### 三條可推廣的判準

**① 鎖定注音下判斷退格行為，要看「送出結果」不是看組字區。**
組字區會顯示未成字的注音殘渣，看起來像「沒刪乾淨」，實際上格已經刪了。
`你ㄏㄠ` 在 Windows 送出是「你」——**畫面會騙人**。

**② 使用者描述與程式碼推論衝突時，不要挑一邊相信。**
兩邊都可能錯：描述可能記錯鍵位或記錯平台，推論可能漏看一條路。
**要用固定步驟在兩個平台各跑一次**，把體感換成可比對的事實。

**③ 「沒看到實際畫面就用文字描述推論」是這次最大的時間浪費。**
第 5 輪是使用者貼了截圖才翻案的，而截圖之後**又**因為誤讀畫面錯一次，
直到問出「直接送出會是什麼」才定位。
**下次遇到組字／顯示類的症狀，第一件事就是要圖，第二件事是問送出結果。**

## 兩件都查完了（2026-09-20）

### ① 只有一個誤用，而且**不能改 `composition()` 本身**

`composition()` 在 macOS 平台層只有三個呼叫點：

| 位置 | 用途 | 判定 |
|---|---|---|
| `select_candidate()`（滑鼠點候選字後重畫） | 顯示 | ✅ 正確 |
| `refresh()`（唯一的重畫入口，約 20 處都收斂到它） | 顯示 | ✅ 正確 |
| **`commit()`** | **送出** | ❌ **就是這個 bug** |

**兩個顯示呼叫點依賴它含 pending**——`set_marked()` 拿那個字串算
游標位置（要停在含 pending 的整串尾端）與面板空判斷（跟 core 的
`Session::is_empty()` 把 pending 算進去同一條規則）。**所以要改的是
`commit()` 不是 `composition()`。**

好消息：送出有**六個入口**（Enter、`commitComposition:`、切走輸入法、
數字鍵先送出、選最後一格自動送出、段選單走完自動送出）**全部經過
`commit()`**——改一行六條路一起修好。

### ② 三個情境只有注音受影響

| 情境 | pending 裝什麼 | 送出該不該保留 |
|---|---|---|
| **鎖定注音** | `ㄏㄠ` 注音符號 | ❌ 不該送——**這就是本篇的 bug** |
| **鎖定日文** | 湊不成 mora 的字母（`sush` 的 `sh`） | ⚠️ 另案，見下 |
| **符號 `\名字\`** | **空字串** | 不適用，**完全不受影響** |

符號那條**根本不經過 pending**：符號輸入永遠走 `Input::Cascade`，
`pending()` 對它硬編碼回空字串。`\` 與名字全部進 `keys`，由
`compose::merge_symbols` 在切段階段處理。

### ③ 順帶挖出一個**兩平台共有**的資料遺失

鎖定日文打半個 mora 直接送出，那幾個字母會憑空消失——**Windows 也一樣**。
性質不同、要裁決、要兩平台一起改，所以獨立成案：
[[鎖定日文打半個 mora 直接送出，那幾個字母會消失]]。

## 修法

1. **必修**：`commit()` 的 `self.composition()` → `session.text()`
2. **不要動** `composition()` 本身（理由見①）
3. **順手做**：`composition()` 的 doc 補一句「**只給組字區顯示用，
   送出請用 `session.text()`**」。考慮改名成 `display_text()` 之類，
   從命名上堵掉下一次誤用——**這支已經有一次誤用紀錄，名字不夠明確**
4. 加測試釘住

> **修完值得回頭補一句**：開發文件裡記錄「macOS 刻意用
> `text() + pending_symbols()`」的兩處**都沒有限定「僅供顯示」**，
> 那正是當初讓 `commit()` 誤用的土壤。
