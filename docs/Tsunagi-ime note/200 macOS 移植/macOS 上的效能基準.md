# macOS 上的效能基準

在 Mac 上跑一次三支效能量測，當作 macOS 的基準。**先前所有記錄下來的數字
都是 Windows 開發機的**，換平台之後沒有可比的基線。

### `bench_typing`（打字熱路徑）

跑三次看離散度（**單次數字不足以判斷是不是雜訊**）：

| | 值 | 判準 |
|---|---|---|
| p50 | 2.6～2.7ms | |
| p95 | 7.2～7.7ms | |
| **p99** | **8.9／9.4／9.6ms** | < 16ms（一幀）✓ |
| 最慢一鍵 | 15.6／17.0／17.3ms | 超長日文 110 鍵那一句 |

離散度約 0.7ms，所以這個水準是穩的。

十個案例裡只有「超長（日文 110 鍵）」超出一幀。日文長句候選數 800（`ALIVE_LIMIT`
的上限），那是最壞情況。

### `bench_segmenu`（段選單，`bench_typing` 量不到的那條路）

| 操作 | p99 | 最慢 |
|---|---|---|
| 開選單（TAB） | 0.53ms | 1.0ms |
| 換段（→） | 0.36ms | 1.2ms |
| 換候選（↓） | 0.59ms | 1.8ms |
| 推邊界（Shift+→） | 0.53ms | 1.7ms |
| **定案（Enter）** | **9.60ms** | 18.2ms |

**只有定案會重算**（前面凍結、後區重跑），所以它是唯一接近預算的。
15172 次操作裡 6 次超過一幀（**0.04%**），全都是 88～90 鍵的三語混合長句。

### `bench_dict`（詞庫載入）

英文 23ms、注音 0ms（133101 條，mmap）、**日文 674ms**（745965 條），合計
697ms。日文佔 97%。

這也是為什麼 macOS 版**一定要背景載**（`echo_ime::run` 開一條執行緒）：
宿主等輸入法連上線只等 3 秒（[[系統不再自動拉起輸入法：是工作階段內的累積效應]]
的 log 裡看得到那個逾時），在主執行緒載會直接撞上去。

### 跟 Windows 比：輕量操作一樣，重路徑慢 15～50%

| | Windows | macOS 9/8（spike 1） | macOS 今天 |
|---|---|---|---|
| 打字 p99 | **7.9ms**（§2.57.8） | 8.6ms | 8.9～9.6ms |
| 詞庫載入 | 672ms | 650ms | 697ms |

段選單逐項 p99（Windows 的數字見
§2.70）：

| 操作 | Windows | macOS |
|---|---|---|
| 開選單 | 0.51ms | 0.53ms |
| 換段 | 0.38ms | 0.36ms |
| 換候選 | 0.56ms | 0.59ms |
| 推邊界 | 0.54ms | 0.53ms |
| **定案** | **6.35ms** | **9.60ms** |

三件事：

- **輕量操作幾乎完全一樣**（0.36 vs 0.38、0.53 vs 0.51…）。那是預期的——
  `core` 是純 Rust、沒有平台程式碼，成本本來就該一致。**這反過來證明量測
  本身可信**：如果連這幾項都差很多，那就是量法有問題而不是效能有差
- **重路徑 Mac 慢 15～50%**（打字 p99、段選單定案）。M2 8GB 對那台 Win11
  的單核差異，加上這台同時跑著輸入法自己與開發工具
- **「最慢」那一欄不能比**。Windows 記的 24.5ms 出自 `long` 節的兩句
  **189 鍵**長句，今天最慢的是 **88～90 鍵**——測資在這中間改過（現在
  1423 筆），最壞情況根本不是同一句

> **唯一乾淨的對照是 Mac 對 Mac**：9/8 那次 p99 8.6ms，今天 8.9～9.6ms，
> 漂了約 0.7～1ms。那段期間 core 加了中文選字接 bigram、台語、段選單改法，
> 所以傾向是真的成本而不是雜訊——但仍在預算的六成以內，不處理。
>
> 要真的 head-to-head，只有**在 Windows 上用同一個 commit 重跑一次**。
> 現在記的 7.9ms 是 §2.57.8 當時的數字，測資與引擎都已經不同了。

### 沒有被量到的部分

**這三支量的都是 `core`，不含 macOS 的繪製層。** 候選面板每次顯示都對每一格
做 `sizeWithAttributes` 量字寬（`candidate_panel::layout`），展開成多欄時
格數可達數十個，那條路沒有任何數字。目前打字沒有可感知的卡頓，但**那是體感
不是量測**——真要動面板的版面演算法之前，得先補一支能量它的東西。
