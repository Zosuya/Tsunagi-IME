# 設定頁的預覽字型：跟系統要表，不要檔案

接著 [[設定頁依平台隱藏無效的欄位]] 的稽核。字型
是同一類問題的第三個：**輸入法會跟著換，設定頁的預覽不會**——
`preview_font::family_font` 在 macOS 是回 `None` 的空殼，預覽於是退回介面
自己用的那套字（蘋方）。預覽不跟著換，這一支就失去存在的意義。

### 走錯的第一條路：問檔案路徑

`kCTFontURLAttribute` 問得出字型檔在哪，看起來就結案了。**不行**，而且失敗
的方式很陰險：

- 那給的是**檔案**，但一個檔案裡有幾十個字面，「哪一個」對不回來
- 實測 `PingFang TC` 的路徑指向 **`PingFangUI.ttc`**，那個集合裡的字面叫
  `.PingFangUITextTC-Default`，跟 `NSFont::fontName()` 回的
  `PingFangTC-Regular` **根本不同名**
- 拿名字比對一律落空 → 統統退回字面 0（**簡體版**）。檔案格式完全正常、
  看起來也像模像樣，只有字形悄悄是錯的

第一版的測試本來只斷言「index != 0」，跑出來就紅了——**那條測試值回票價**，
不然這個錯只會在使用者眼裡表現成「預覽的字有點怪」。

### 正解：`CTFontCopyTable` 逐表撈出來重組

一張表一張表地要出來，自己拼回一個完整的 sfnt（`rebuild_sfnt`）。
**CoreText 已經解析好是哪一個字面**，撈到的表就是那個字面的，「哪一個」
這個問題從結構上消失。

這跟 Windows 用 `GetFontData` 的理由是同一個——讓系統照它自己的規則挑，
我們只負責把資料要出來。所以 macOS 這條路的 `index` **永遠是 0**：拼出來
的是單一字型檔，沒有集合。

拼檔要注意的三件事：表目錄按標籤遞增排序、每張表的內容對齊 4 位元組、
有 `CFF ` 表的簽章要用 `OTTO`（PostScript 輪廓）而不是 1.0。

**沒有多拉套件**：手宣告了幾支 CoreText／CoreFoundation 的 C 函式，跟
`echo_ime.rs` 呼叫 Carbon 的 `TISRegisterInputSource` 同一個做法。有一個
地方不能偷懶——`CTFontCopyAvailableTables` 回的 `CFArray`
**不能當成 `NSArray` 用**：裝進去的元素不是物件，是四位元組的表格標籤
直接塞在指標欄位裡，交給 objc2 的容器會被當成物件去 retain，當場爆掉。

### 測試守的是「字面對不對」，不是「解析得動」

最後的斷言是**從重組出來的字型裡把 PostScript 名字讀回來、確認含 `TC`**。
理由如上：格式正確但挑錯字面的檔案，任何「解析得動」的檢查都會過。

### 後續：改成用選的

預覽接上之後，輸入框本身變成新的問題——**能用但要背字型名字**，而且打錯
只會靜靜地退回系統預設，看不出是打錯還是那台機器沒裝。使用者要求改成用
選的。

`NSFontManager::availableFontFamilies` 就是那份清單（這台機器 254 項），
做成附搜尋的下拉選單：清單兩三百項，一路捲下去找「蘋方」不現實，而使用者
通常知道自己要的是什麼開頭。三個細節：

- **開頭是點的過濾掉**（`.SF NS`、`.PingFangUI` 那些系統內部字型）——選了
  多半不是他要的樣子，有些根本畫不出中文
- 「（系統預設）」永遠排第一且**不受搜尋影響**——它是回到預設的出口，
  找不到它會讓人以為只能一直選著某個字型
- 搜尋字串放 egui 的暫存區，不進 `Font`——它是控制項的臨時狀態，不是設定

清單**只算一次**（`OnceLock`）：設定頁開著的期間它不會變，每幀跟系統要幾百
個字串太浪費。撈不到（拿不到主執行緒標記之類）就退回打字並印一行診斷——
**那種失敗從畫面上看不出來**，不留線索的話下次只會看到「怎麼變成輸入框」。
