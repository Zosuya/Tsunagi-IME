# 提示列與全半形提示面板

[[鍵位對照稽核：macOS 缺的兩處當天補完]] 盤點出的三件事——`Shift+空白` 沒接、指令提示無處可放、鎖定／
引擎停用的狀態看不見——其實是同一個洞：**macOS 沒有提示的地方**。
補完之後三件一起結案。

### 兩塊東西，照 Windows 的結構分

| | Windows | macOS |
|---|---|---|
| 底部那行小字 | 候選視窗裡的一列（`paint_hint`） | 候選面板裡的一列 |
| 全半形三態 | **獨立視窗**（`width_window.rs`） | **獨立面板**（`width_panel.rs`） |

全半形獨立出來的理由照抄 Windows：它跟候選是兩回事（候選是「你要選哪個
字」，這個是「輸入法現在什麼狀態」），混在一起的話候選清單的高度會忽大
忽小，而且**沒在組字時得為了顯示它硬開一個空的候選面板**——而全半形
恰恰是「沒組字也要能切」的功能。

### 動畫：這次是 macOS 佔便宜

滑動與淡出的**決策**在 `ime_core::render::width_bar`，兩個平台同一份
（ease-out 曲線、滑動 110ms／停留 500ms／淡出 180ms）。差別在誰來推：

- Windows 得開 `SetTimer`，而那個計時器**跑在宿主行程的訊息迴圈裡**，
  所以動畫刻意壓在 1.3 秒內結束——不能一直佔著記事本的迴圈
- macOS 的輸入法是自己的行程，`NSTimer` 跑在我們自己的 run loop 上。
  [[執行模型的根本差異]] 講的執行模型差異，這裡是站在我們這邊的那一面

淡出的實作也不同：Windows 的視窗不透明，得把每個顏色往底色混；macOS
直接調 `NSWindow` 的 `alphaValue`，**連陰影一起淡**，那才是對的。

### 刻意放掉的一個細節：`WidthBar::held`

`WidthBar` 有「Shift 還按著就不淡出」的設計（使用者可能還要再按空白切
下一個模式）。那需要收到修飾鍵**放開**的事件，而 IMK 預設只送 keyDown，
要收 flagsChanged 得覆寫 `recognizedEvents:`。**為了這個細節去改事件遮罩
不划算**——連按時每一下都會重新開始動畫（`start_at` 會從目前位置接著
滑，不是跳回起點），使用者仍然看得到自己切到哪。所以 macOS 這邊當作
「按下就放開」，一律 `release()`。

### 提示列的三選一

判斷跟 Windows 的 `ui.rs` 一字對一字：指令 → 鎖定 → 停用的引擎。其中
**鎖定那條在 macOS 實務上不會出現**（使用者裁定不做語言鎖定），但判斷
留著——`Session` 有那個狀態，漏掉就是兩個平台默默分岔。

版面上有一處要注意：**提示列可能比候選還寬**（「↑↑↓↓ ⚙ 開啟設定」比
一個字長得多），面板寬度要取兩者的最大值。還有「只有提示、沒有候選字」
是**合法狀態**——打了 `config` 但還沒有候選字可選時就是那樣，所以
`layout` 的列數不能再用 `clamp(1, …)` 硬撐一列出來。

### 順帶：`Shift+空白` 在段選單裡也吃

Windows 的鍵位表把 `ToggleWidth` 綁在 Typing／Idle／Selecting 三個模式，
**沒綁 SegMenu**。macOS 這裡放在所有模式之前一併吃掉——段選單開著時切
全半形一樣有意義，而且不吃的話空白會掉進段選單的預設路徑。這是刻意的
分岔，不是漏抄。
