# 設定頁依平台隱藏無效的欄位

使用者回報「主題頁面中有些東西不能改」。核對之後確實如此——設定頁是跨
平台的同一份程式，但兩邊的繪製層做的事不一樣，**macOS 上有一半的欄位改
了不會有任何反應**：

| 欄位 | macOS 為什麼無效 |
|---|---|
| 預覽列文字／底色／漸層、分隔線 | **組字區是宿主畫的**（marked text，[[接上引擎：詞庫定位、Session 取代自己記的緩衝]]），我們沒有自己的預覽列，也就沒有那條分隔線 |
| 漸層下緣 | 面板畫的是單色圓角底 |
| 文字描邊 | 還沒接（它主要是為背景圖上的可讀性） |
| 背景圖 | 面板還沒畫它（[[設定頁的五處平台缺口：對話框接上了]]） |
| 反白樣式（高光帶／只有高光） | 面板目前只畫實心 |
| 「選擇字型…」按鈕 | 對話框在 macOS 回 `None`，**按了完全沒反應** |

**按了沒反應的控制項比沒有還糟**——使用者會以為是壞了，而不是「這個平台
沒做」。

### 做法：一張「這個平台用得到什麼」的表

`settings/src/platform.rs`，全部是 `cfg!()` 算出來的 `const bool`。UI 照它
決定畫不畫，**不是 `#[cfg]` 灑在各處**——常數版讀起來像一份規格，而且兩個
平台的程式碼都還會被編譯器檢查到（cfg 掉的那半在另一個平台上是啞的）。

macOS 補上對應功能時把那一項改成 `true` 就好，UI 不必再動。

**隱藏不等於清掉**：設定檔裡的值照樣留著，同一份 `config.toml` 帶回
Windows 仍然有效。頁尾加一行說明講這件事——不講的話使用者會以為選項不見了。

字型那一項不是隱藏而是**換一種控制項**：沒有系統對話框的平台改成直接打
字型名稱。打錯或那台機器沒裝，繪製時會自己退回系統字型。

### 展示區：macOS 那張「打字中」整個拿掉

Windows 的展示區有三張卡，其中「打字中」那張畫的**整個就是預覽列**——在
macOS 上沒有對應物，不是拿掉幾列的問題。改成兩張：選字的候選面板、TAB 的
段選單，並補上底部的提示列（`index` 這個顏色在 macOS 上就靠它跟編號現身）。

提示列的字級走 `render::hint_font_pt`，**跟實際繪製同一條公式**——那條公式
本來就是為此才搬進 core 的（[[提示列與全半形提示面板]] 之後）。

> 附帶效果：上一節做的「選圖片」對話框（`NSOpenPanel`）在 macOS 暫時沒有
> 入口了，因為背景圖那一區整個隱藏。程式留著，背景圖接上時就會回來。

### 藏控制項不夠：值還在，展示區照樣畫出來

第一版只藏了控制項，使用者馬上回報「漸層效果也不能用了，但現在預覽有
漸層」。**隱藏不會讓值消失**——以前調過的漸層、描邊、反白樣式都還在設定
檔裡，而且套用主題也會寫進去。展示區照原始設定畫，就會出現實際面板不會
有的效果，那比不畫還糟：使用者正是靠展示區判斷「改了會變成什麼樣」。

改成**一處正規化**：`platform::effective(cfg)` 把這個平台用不到的欄位改成
「等於沒設」（漸層下緣＝底色、描邊 0、背景圖空、反白樣式實心），展示區
一律先過這一關。在每個繪製點各加一個 `if` 的話，漏掉一個就是一個不一致
——漸層那個就是這樣漏掉的。回傳的是複本，**不碰使用者的設定檔**。

### 順手抓到的第二個不一致：編號的顏色

macOS 面板未反白時用 `colors.index`（淡灰）畫編號，**Windows 早就改成跟
候選字同色**了（理由：同一個東西在兩種狀態下換顏色，看起來像兩種資訊，
見 `candidate_window.rs` 的 `row_color`）。展示區跟的是 Windows，所以
macOS 是漏抄的那一邊，改成同色。

改完之後 `index` 在 macOS 上**只剩提示列與全半形提示面板在用**，跟設定頁
把它標成「提示文字」一致。
