# spike 4：插入點座標 7 個宿主都拿得到

[[macOS 移植的 spike 排序：先做 Echo 輸入法，五個全部結案]] 排第 2 順位的 spike，要回答的是「候選視窗畫不畫得出來、畫在哪」。
**結論：`attributesForCharacterIndex:0 lineHeightRectangle:` 在量到的
7 個宿主全部回了有效座標，一個零矩形都沒有。**

| 宿主 | 索引 0 的矩形 (x,y,w,h) | 判定 |
|---|---|---|
| TextEdit（原生 AppKit） | (151, 771, 1, 14) | ✅ 螢幕內 |
| Safari 網址列 | (419, 849, 1, 16) | ✅ |
| **Safari 網頁裡的輸入框** | (360, 733, 1, 19) | ✅ |
| 終端機 Terminal | (533, 698, 1, 14) | ✅ |
| VS Code（Electron） | (211, 783, 1, 15) | ✅ |
| Microsoft Word | (249, 548, 1, 43) | ✅ |
| Obsidian（Electron） | (390, 673, 1, 15) | ✅ |

**Windows §2.38 那個 `TS_E_NOLAYOUT` 的災情，macOS 沒有對應物。** 那邊網頁
欄位常常回「還沒排版好」、要另外準備 `GetScreenExt` 退路；這邊 Safari 的
網頁輸入框老老實實回了座標。退路的程式碼還是要寫（防零矩形），但**它不是
常態路徑**，這跟 Windows 的設計前提差很多。

### 量到的三件事，都會影響 spike 3 的設計

1. ~~**只有索引 0 可信。**~~ **這條後來被推翻了**，見底下「補量」——
   當時是拿越界的索引去問，難怪拿到垃圾。**範圍內的索引每一個都老實。**
2. **矩形是組字區的起點，不隨字數移動**（同一輪裡 1／2／3 個字回的 x 都
   一樣）。這對候選視窗反而是對的語意——視窗釘在組字起點，不會邊打邊跑。
3. **`selectedRange` 跨宿主不一致，不要用。** 終端機回的是整份文件的位移
   （70、71、72…），其他宿主回 (0,N)。要知道組字長度就自己記，別問宿主。

矩形的**高度就是行高**（13～19，Word 因為字大是 43），候選視窗要貼在行下方
就靠它，不必自己猜字級。寬度一律是 1——那是游標線，不是字的寬度。

### 這次量法的一個瑕疵（結論不受影響）

探針放在 `set_marked` 的**開頭**，也就是 `setMarkedText:` 送出**之前**，
所以當下宿主手上的組字內容比記錄檔的標籤少一個字。**索引 0 的結論不受
影響**（索引 0 永遠是組字起點，跟長度無關），但索引 1 那半的資料因此
混著「越界查詢」，不能拿來斷言「索引 1 一定不能用」——只能說**它不可靠、
不要用**。要乾淨的資料就把探針移到 `setMarkedText:` 之後，並改查
索引 0 與索引「目前長度」。

### 補量：把索引問對之後，兩個結論一個成立一個被推翻（2026-09-08）

探針移到 `setMarkedText:` 之後、索引改問 `0` 與 `長度-1`（都在範圍內），
在 TextEdit 重量兩輪：

```
組字1字 sel=(6,1)  [idx0] (787,628,1,14)   [idx0] (787,628,1,14)
組字2字 sel=(6,2)  [idx0] (787,628,1,14)   [idx1] (794,628,1,14)
組字3字 sel=(6,3)  [idx0] (787,628,1,14)   [idx2] (801,628,1,14)
組字1字 sel=(9,1)  [idx0] (449,635,1,14)   [idx0] (449,635,1,14)
組字2字 sel=(9,2)  [idx0] (449,635,1,14)   [idx1] (455,635,1,14)
組字3字 sel=(9,3)  [idx0] (449,635,1,14)   [idx2] (462,635,1,14)
```

- **「矩形是組字區起點、不隨字數移動」成立**——同一輪裡 idx0 的 x 一直是
  787（或 449）。而且**不是排版沒跟上**：同一次呼叫裡另一個索引已經給出
  新位置了，所以宿主的排版是即時的，idx0 就是**語意上**指組字起點
- **「只有索引 0 可信」被推翻**——索引 1、2 分別回 794、801，
  一個字約 7pt，正是游標往右走的位置。**前一輪之所以拿到零矩形，是因為
  問了越界的索引**（探針在 `setMarkedText:` 之前跑，宿主手上的組字內容
  比標籤少一個字）
- 換位置重新組字，idx0 跟著換（787 → 449）——**面板會跟著輸入位置走**

所以候選視窗**兩種定位都做得到**：釘在組字起點（idx 0）或跟著游標
（idx = 長度-1）。這是設計選擇不是能力限制。

原始資料留在 `core/testdata/` 之外的地方沒有意義，量完就丟；
`caret_probe.rs` 與它在 `set_marked` 的呼叫點**接 core 之前要拿掉**。
