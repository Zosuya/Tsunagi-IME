# 新酷音的輸入與選字：哪些值得借

> **狀態**：只讀原始碼對照、沒動程式，九件待借的依價值排好

把 libchewing（引擎）與 windows-chewing-tsf（TSF 層）的原始碼整個讀過
一遍，逐項對照我們的 `session/`、`compose.rs`、`learn.rs`、`keymap.rs`。
**只看輸入與選字的互動**，排序演算法（§2.15 已試過否決）與資料
（§2.41 只借做法）不在此列。

讀的版本：libchewing master（0.11 之後、未發布的 NEWS 含
`auto_snapshot_selections` 與 `chewing-deleted.dat`）、windows-chewing-tsf
26.7.2.0（2026-07-20）。關鍵檔案：

| 主題 | 檔案 |
|---|---|
| 編輯器狀態機（Entering／Selecting／Highlighting） | `src/editor/mod.rs` |
| 選詞器（多長度詞候選） | `src/editor/selection/phrase.rs` |
| 組字區的縫（斷點／黏點）與使用者選擇 | `src/conversion/mod.rs` |

| 學習曲線 | `src/editor/estimate.rs` |

| 按鍵處理順序 | `crates/chewing_tip_host/src/text_service/chewing.rs` |

已經借過、不再重列的：四格覆寫（[[輸入層拆三條路：自動、鎖定注音、鎖定日文]]）、分層字典（§2.17）、

回報學到的」）、同一個詞收多份讀音（§2.41）。

### 2.42.1 最值得借的九件（依價值排）

**一、選字時當場「剔除」一個候選。** 在候選清單裡按 `Ctrl+Delete`
（可自訂）就把那個詞反學掉（`unlearn_phrase`），而且記進一份獨立的
排除詞典 `chewing-deleted.dat`——之後**連自動學習都不會再把它學回來**
（`auto_learn` 先問 `is_excluded`）。我們現在打錯學進去只能去手改
`learned.txt`。§2.17 已經記了「排除條目做成獨立一層」，這件事就是它的
使用者入口；排除層要能擋系統詞庫的爛詞，不只擋學習層。

**二、凍結使用者「看過」的字。** `auto_snapshot_selections`（Windows 版
26.4.1 起預設開）：游標一離開尾端（Home、方向鍵、Shift+方向鍵），那一刻
已轉出的每一個字都被寫成 selection 鎖住，引擎之後不再改動。這是他們對
「前面的字突然改了」的正式解法。我們 §2.28 量過目前沒病，但如果日後
真的出現，答案在這裡：**凍結的判準是「使用者的游標動作」，不是
「距離尾端幾格」**——游標移過去代表看過了。

**三、在字與字的縫上標「這裡斷」或「這裡連」。** 游標停在中間按 Tab，
那個縫會被記成 `Gap::Break`（不許成詞）或 `Gap::Glue`（一定要連），
之後不管怎麼重算都尊重（`find_best_phrases` 跨過斷點直接回空）。
設斷點時會順手清掉跟它衝突的既有選擇。我們的 Shift+方向鍵文節伸縮
（§4.18）只在日文有，中文的「新世紀 vs 心事＋紀」現在只能靠逐格選字
繞。在「框是游標」的模型裡，**框的左邊界就是一個縫**，長出這件事很
自然。它也是 §2.21「刪完不要重切」的原型：斷點是意圖標記，重算要保留。

**四、候選清單列「從這一格起的詞」，不只單字。** `PhraseSelector` 進
選字時先找從游標起最長能成詞的範圍（到下一個非音節符號為止），候選
翻完最後一頁再縮短一級（三字詞→二字詞→單字）。我們的 `candidates_for`
只列單字（`chars_for`），使用者想改「服務費」得逐格改三次。學習層
（§2.22.5.2）已經在記 2～4 字子段，選字介面卻沒有對應的表達——
**學得到的東西，介面上要選得到**。

**五、選完自動往右移一格。** `advance_after_selection`，Windows 版預設
開；libchewing 0.11 修成「移到下一個詞」而不是下一個字。逐格修一整句
時省掉一半的按鍵。我們選完框停在原地，要再按右鍵。

**六、組字區的長度上限。** `auto_commit_threshold`（引擎預設 39、TSF 層
設 50 個音節）：超過就把最前面的詞自動送出，直到降回門檻以下。我們
沒有上限，而且累加式切法對長串是整串重算（§2.7）。這既是效能保險，
也是「前面的字自然不再變」的機制。

**七、單按切換鍵不要吃掉。** 他們 26.4.2 修過：Shift 單按切中英文時
把 Shift 攔下來，結果**遠端桌面與 UltraEdit 壞掉**；改成「處理但不
消耗」。我們放開 Ctrl 時 `OnTestKeyUp` 對 `VK_CONTROL` 回「要」
（`text_service/mod.rs`），跟他們修之前同型。**放進相容性測試清單**，
遠端桌面那一列現在是空的。

**八、單按切換要有時間門檻。** `shift_key_sensitivity`（預設 200ms）：
按超過就不算單按。我們的 `CtrlTap` 只看「中間有沒有按別的鍵」，
長按 Ctrl 想一下再放開會被切語言。

**九、學會的時候講一聲。** 學進一個詞會寫 `notice_buffer`
（「加入：XX」／「已有：XX」／「加詞失敗：字數不符或夾雜符號」），
TSF 層用通知視窗閃一下。我們的兩刀學習完全靜默，使用者不知道這次
選了會不會記住。全半形提示視窗（§4.17）那套已經能當 toast，跟
§2.22.7「學習檔沒入口」互補。

### 2.42.2 原則層級：不動程式碼也值得記

**Tab 一鍵扛兩件事會出事。** 他們的 Tab 在尾端是「循環第 N 條整句
路徑」（`nth_conversion`，Yen's K 最短路徑，K＝10），在中間是「標斷點」。
26.7.1 與 26.7.2 連修兩版「Tab 循環不穩」。我們的 Tab 只開切法選單，
是對的。日後若要做「同一切點下第二種日文分詞」（我們的 Viterbi 只出
一條，§2.23），要塞進切法選單的日文代表列展開，**不要再給 Tab 新語意**。

**候選視窗搬到獨立行程。** 26.5.1 把候選視窗與更新檢查移到
`chewing_tip_host.exe`，DLL 只剩薄殼走 named pipe。這等於解掉「DLL 被
宿主鎖住、升級要重開所有程式」那個痛點（§2.35 升級階段、CLAUDE.md
`build-ime.ps1` 的整段緣由），也把 UI 崩潰隔離開（我們的 §2.33 是用
`catch_unwind` 在行程內擋）。工程量大，列為長期方向。

**自動學詞用虛詞表切邊界。** 他們送出時把連續單字拼成詞學進去
（`collect_new_phrases`），用 39 個虛詞（的、了、是、我、你、他、們、
年、月、日……）當邊界，夾著虛詞的還會學「含」與「不含」兩版。我們的
`learn.rs` 是「選過才學」、不猜詞界、靠重複出現自然過濾，設計理由
站得住（§2.22.5.2）。但那份虛詞表可以拿來**對照我們學到的子段裡有
多少是「的服務」這類垃圾**——是量測工具，不是行為。

**UILess 模式。** 全螢幕遊戲畫不出候選視窗，他們提供
`chewing_cand_string_by_index` 讓宿主自己畫，Minecraft 因此能用。
我們沒有這條路，相容性測試清單可以加一項「全螢幕遊戲」。

**per-app 怪癖集中一個檔。** `quirk.rs` 依 exe 名查表（目前只有
MyAB 一條），Excel 的「焦點抖動導致提前送出」也是同類。我們的
§2.38 網頁欄位 `TS_E_NOLAYOUT` 是同性質的東西，日後第二條出現時
照這個形狀收。

### 2.42.3 看過但不借的

| 他們有的 | 為什麼不借 |
|---|---|
| 簡拼（`FuzzyPartialPrefix`）與許氏鍵盤的替代音節（`alt_syllables`） | 鎖定注音沒有這個需求 |
| Esc 預設只清正在打的半個音節、不清整句（`esc_clear_all_buffer` 預設關） | 我們 Esc 是 Cancel 整個組字；鎖定注音可以考慮，但影響很小 |
| Shift+方向鍵拉選取範圍、Enter 學成詞（`Highlighting` 狀態） | §2.22.3.1 決定過不做手動教詞。這是「框長出選取」的現成範例，只記著 |
| `Ctrl+2`～`Ctrl+9` 把游標前 N 個字學成詞 | 同上，那是沒有格子模型的補償 |
| ㄅ半模式（`SimpleEngine`：每個音節打完就選、選完就送） | 給老派使用者的模式，我們沒有這批使用者 |
| 空白鍵叫候選（`space_is_select_key`） | 我們的空白是注音一聲 |
| Shift+字母在中文模式直接出大寫英文、不進組字（`upper_case_with_shift`） | 我們大寫要進組字才打得出 GitHub |
| 排序用長度先驗、條件機率 | §2.15 已試過否決 |
| 分層字典取各層最大詞頻（避免每次學習把系統詞頻重複加進使用者詞頻） | 我們的學習層是計數不是加頻，沒有這個病 |

### 2.42.4 這輪的方法

回報「某個互動不順」之前，**先去讀同類成熟輸入法怎麼做**，而且要讀
原始碼不是讀說明——`auto_snapshot_selections` 與排除詞典都還沒進
發布版的 NEWS，只在 master 上。這輪一個檔案都沒動，純對照；
要做的話從 2.42.1 的第一件開始，它接在 §2.17 已經留好的位置上。
