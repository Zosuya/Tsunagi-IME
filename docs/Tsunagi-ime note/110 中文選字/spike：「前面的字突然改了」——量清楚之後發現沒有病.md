# spike：「前面的字突然改了」——量清楚之後發現沒有病

CLAUDE.md 從新酷音使用者回報學到的第一條：「連續打出一句話以後，前面的
字突然改了」。`check_rewrite` 量到 24～26% 的句子會發生，看起來很嚴重。
**把形狀量出來之後，那個數字量的是意圖行為。**

### 2.28.1 判準是觸及範圍，不是次數

`apply_word_context` 的設計就是「打『擬郝』選了『你』，『郝』跟著變
『好』」——那是使用者定的規則。問題只在於「使用者已經滿意前面的字時
它不該再動」。兩者**從結構上分不出來**：`擬→你` 與 `冊→策` 都是
「後面多一個音節、湊成詞、把前一格改掉」，距離都是 1 格。所以「距離」
與「一次改幾個字」這兩個直覺判準都切不開。

分得出來的是**觸及範圍**：意圖內的修正永遠發生在游標旁邊（使用者正在
打的那個詞），而使用者抱怨的是**早就打完、看過、也接受了的字**突然變。

### 2.28.2 量出來的形狀

`check_rewrite` 加了形狀統計。判準比總次數嚴——要求前一步的每一格
**按鍵都原封不動還在原位**，分段一變整步跳過（總次數那邊只對齊尾端
那一刀，中間的邊界動了也算進去）。

| 觸及範圍 | 次數 |
|---|---|
| 倒數第 1 格（緊鄰游標） | 107（95.5%） |
| 倒數第 2 格 | 5（4.5%） |
| **倒數第 3 格以上** | **0** |

| 被改掉的字撐了幾鍵 | 次數 |
|---|---|
| 1～3 鍵 | 111（99.1%） |
| 4 鍵以上 | 1（0.9%） |

**112 次改寫全部是意圖行為。**唯一一次久存的是 `便→變`（撐了 5 鍵、
倒數第 2 格）。

第一版探針量錯過一次，值得記：用「按鍵結束位置」對齊，把**分段邊界移動**
也算成改寫，得到 269 次、還有 13 次假的遠距事件（`ありがとう→王`、
`→search` 這種）。那正是 §2.22.6.1 記過的第二種量錯法，同一個坑。

### 2.28.3 為什麼這個結論不受詞頻資料影響

量的時候手上沒有教育部字頻與國教院詞頻（那兩個站在遠端開發環境連不
出去）。但 `word_for` 的**命中與否只看 `BPMFMappings.txt`**——`WORDS`
是「按鍵串 → 一個詞」，詞頻只決定同音詞裡挑哪一個。改寫能伸多遠取決
於哪些按鍵跨度匹配得到詞，那是資料無關的；會隨資料變的只有次數。

### 2.28.4 結論：不加抑制規則，改成把尺磨利

沒有東西要修——加一條「離游標超過 N 格就不准改」的規則，在現有語料上
是純粹的 no-op，等於為量不到的問題加機制。

改成讓尺報得出形狀：**「倒數第 3 格以上」那一格必須是 0**。它變成非 0
就代表 `apply_word_context` 開始動使用者早就看過也接受的字，那時候才
需要規則。總次數那個數字**不要拿來當健康指標**，它大部分是意圖行為。

順帶確認 `picked` 沒有破洞：格子每按一鍵重建，但 `session` 的
`reapply_picks()` 會用按鍵比對把手動選擇還原回去，撐得過重建。

### 2.28.5 本機複量：結論成立（2026-09-02）

上面的數字是在缺字頻／詞頻的環境跑的，當時標了「待複量」。本機
（i7-14700KF、完整詞庫）跑出來：

| | 缺資料的環境 | **本機** |
|---|---|---|
| 改寫次數 | 112 | **151**（每百鍵 1.94） |
| 倒數第 3 格以上 | 0 | **0** |

次數不同是預期的——詞頻決定同音詞裡挑哪一個，換一份資料就換一批改寫。
但**觸及範圍那一格仍然是 0**，正如 §2.28.3 推的：改寫能伸多遠取決於哪些
按鍵跨度匹配得到詞，那是資料無關的。

**結論成立，不用修。**
