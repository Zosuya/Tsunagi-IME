# 單按 Ctrl 當語言鎖定鍵：修了兩次最後整個退休

單按 Ctrl 當語言鎖定鍵**只活了十天**（2026-08-30～09-09）。中間修過
**修飾鍵的自動重複**（按著 Ctrl 超過 0.5 秒，重複的 key-down 把「用過了」
標記洗掉，複製貼上會意外切換語言）與**連帶吃掉 Ctrl 放開**這兩個真的
bug，但誤觸還是在——因為「單按」這個設計**天生要靠猜**，那個旗標已經
踩過三次坑。最後換成明確的組合鍵 `Shift+空白`，那層猜測整個消失，
`keymap::CtrlTap`（含 7 個測試）一起刪掉。

## 試過的路

### 一、複製貼上會意外切換語言：修飾鍵的自動重複（原 2.44）

> **當時的狀態**：單元測試 8 條綠，TSF 行為要使用者真機驗（**後來整個
> 退休，沒有再驗**）。

使用者回報：「**有時候**按複製貼上會意外觸發鎖定語言」。

#### 「有時候」是關鍵線索

`CtrlTap` 的規則是「Ctrl 按著時只要看到別的鍵，這一輪就不算單按」，
而它的註解已經記了**這條規則錯過兩次**（把按下 Ctrl 本身算成用過、
標記只做在 `OnKeyDown`）。這是第三次，形狀不同：

```text
按下 Ctrl   → used = false   （新一輪）
按下 C      → used = true    （用過了）
Ctrl 重複   → used = false   ← 被洗掉
放開 Ctrl   → 誤判成單按 → 語言被切走
```

**Windows 對按著不放的修飾鍵會持續送 key-down**，而重置寫在
「看到 Ctrl 的 key-down」這件事上，重複的那些就把標記洗掉了。

「有時候」正是因為要按著 Ctrl **超過自動重複的延遲**（預設約 0.5 秒）
才會發生——快速的 Ctrl+C 不會，停頓一下的就會。

#### 先寫失敗的測試，再修

`CtrlTap` 是純邏輯，不必真機就能重現：

```rust
t.key_down(CTRL, true, false);
t.key_down(C, true, false);
t.key_down(CTRL, true, true);   // 自動重複
assert!(!t.ctrl_released());    // 修之前這裡是紅的
```

修法是拿 `lparam` 的**第 30 位元**（前一次的鍵狀態，1 ＝ 本來就按著）
判斷是不是重複，重複的那些不重置。兩個標記點（`OnTestKeyDown`、
`OnKeyDown`）都要傳，它們本來都把 `lparam` 寫成 `_lparam` 丟掉。

**拿不到訊號時退化成現況**：`repeat` 一律傳 false 的話行為跟修之前
一樣，不會更糟。

#### 連帶修掉「吃掉 Ctrl 放開」

查的時候發現按下與放開**不對稱**：

```rust
// OnTestKeyDown：按下 Ctrl
if is_modifier_down() { return Ok(BOOL(0)); }   // 不吃，宿主收得到

// OnKeyUp：單按 Ctrl 成立
Ok(BOOL(1))                                      // 吃掉，宿主收不到
```

宿主眼裡 Ctrl 就一直按著，之後每個鍵都變成組合鍵。**這跟誤判是連動的**
——誤判成單按時不但切了語言，還順手把 Ctrl 卡在宿主那裡。

新酷音踩過同一個坑（26.4.2）：單按 Shift 切中英文時把 Shift 攔下來，
遠端桌面與 UltraEdit 因此壞掉，修法是「**處理但不消耗**」。照做，
`OnKeyUp` 尾端改回 `BOOL(0)`——該做的事都在那之前做完了。

#### 還沒排除的另一種可能

如果修完仍然偶爾發生，下一個要查的是**那個字母鍵根本沒到我們這裡**
（宿主先吃掉 `Ctrl+C`）。那時 `used` 一樣是 false，症狀相同但成因不同，
而且我們看不到自己沒收到的東西。查法是 `keyprobe`（[[快捷鍵攔截：哪些組合根本到不了輸入法]] 那套），
補救方向是**時間門檻**（新酷音的 `shift_key_sensitivity`，預設 200ms）。

#### 驗證

單元測試 8 條（含新的自動重複與位元判讀），`cargo test` 588 綠、
clippy 乾淨，三支計分器不受影響（改的是平台層）。

**真機驗證要使用者做**——TSF 行為單元測試碰不到。（**沒驗完就退休了**，
見下一節。）

## 根因：單按修飾鍵天生會誤觸——換成 `Shift+空白`（原 2.73）

**單按 Ctrl 用了十天就退休。** 使用者的兩個抱怨：
**會誤觸**、**跟別的軟體衝突**（那些軟體自己要用單按 Ctrl）。

換完的鍵位：

| 功能 | 舊 | 新 |
|---|---|---|
| 語言鎖定輪替 | 單按 Ctrl | **`Shift+空白`** |
| 全半形 | `Shift+空白` | **`Ctrl+Shift+空白`** |

### 為什麼單按修飾鍵天生會誤觸

不是實作沒寫好，是這個設計**要靠猜**。「單按」的定義是「按下到放開
之間沒碰別的鍵」，所以得記一個旗標，而那個旗標踩過兩次坑
（[[語言鎖定：單引擎模式]] 的「單按修飾鍵怎麼判斷」），上一節是第三次。

改成明確的組合鍵之後**這層猜測整個消失**——按下就是按下，沒有
「這一輪算不算數」的問題。`keymap::CtrlTap`（含 7 個測試）跟著刪掉。

### 候選鍵位是實測選的，不是推論的

推論不出來——同一個組合在系統、宿主、輸入法三關都可能被吃掉。
用專案裡的探針（`keyprobe`，[[快捷鍵攔截：哪些組合根本到不了輸入法]]）量：

| 組合 | 結果 |
|---|---|
| `Ctrl+Shift` | ✗ **系統攔走**——按下去在兩個輸入法之間跳，log 裡一行 Shift 都沒有 |
| `Ctrl+空白` | ✗ 系統攔走（§4.17 早就量過） |
| `Alt+Shift` | ✗ 系統的「切換輸入語言」熱鍵 |
| `Shift+空白` | ✓ 到得了 |
| `Ctrl+Shift+空白` | ✓ **到得了**——`Ctrl+空白` 有主人，加了 Shift 之後系統就不比對了 |

> **Windows 的熱鍵設定對話框不可信**。那張表顯示「切換輸入語言 =
> Left Alt+Shift」，看起來 `Ctrl+Shift` 是空的——**但它其實有主人**，
> 那個對話框根本不顯示它。差點因此判斷錯誤，是使用者實際按下去
> 發現輸入法在跳才知道。**熱鍵能不能用，只有按過才算數。**

### 探針補了兩個量測點

原本的探針只記 `OnTestKeyDown`（按下），這次不夠用：

- **放開也要記**（`OnTestKeyUp`）——`Ctrl+Shift` 切輸入法是在**放開**時
  生效的，只量按下會得到「到得了」的錯誤結論
- **焦點變化也要記**（`OnSetFocus`）——鍵盤配置真的被切走時輸入法會
  失去焦點，那是比「按鍵沒到」更嚴重的情況，log 裡看得到就不用猜
- **修飾鍵標左右**（`LCtrl`／`RShift`…）——Windows 的切換熱鍵只綁其中
  一邊，不分左右就量不到那個差別

`tools/keyprobe.py` 的輸出跟著分成「按下」「放開」兩欄。**兩者不能混
在一起算**，混了會蓋掉「按下到得了、放開被攔走」這種情況。

### 換成按下觸發，帶進一個新問題：自動重複

舊的單按 Ctrl 在**放開**時觸發，而放開只會發生一次。新的 `Shift+空白`
在**按下**時觸發，按著不放系統會持續重送 key-down——**語言會瘋狂輪替**，
放開時停在哪一格全看運氣。

修法是在動作分派前擋掉重複，只擋輪替型的動作（`CycleLock`、
`ToggleWidth`）。一般打字相反，按著注音鍵本來就該連續輸入。

判準用的還是 `is_repeat`（`lparam` 第 30 位元）——**那條規則一個位元
都沒動**，只換了用途。它已經錯過三次（上一節就是第三次），
動它之前先看測試。

### 順帶修掉的：組字中的 `Ctrl+C` 以前會被吃掉

`lookup` 最後有一條「組字中沒綁定的鍵一律吃掉」（游標跑出組字區的話
組字會散）。那條規則**沒有排除 Ctrl 組合**，所以組字中按 `Ctrl+C`
不會複製——按鍵被輸入法吞了。

這次讓 Ctrl 組合走進查表流程時一併修掉：按著 Ctrl 的組合不吃掉，
放行給宿主。組字散不散由宿主自己負責——它本來就知道自己那個快捷鍵
會做什麼。

另一個同源的修正是「Shift 版沒綁就退回無 Shift 版」那條退路
**按著 Ctrl 時不走**——不擋的話 `Ctrl+Shift+X` 會誤中 `X` 的綁定，
把一堆宿主快捷鍵吃掉。

### 代價

`Ctrl+Shift+空白` 在 VSCode 是「觸發參數提示」、部分 IDE 也有綁，
**那些會被輸入法吃掉**。使用者確認可接受（很少用）。

`is_modifier_down()` 改名成 `defer_to_host(mode, vk)`：Alt 系一律讓給
宿主，Ctrl 系原則上讓、綁定表裡有的例外。**之後新增 Ctrl 組合只要動
綁定表**，不必回來改這個函式。
