# 退格的新規格沒效果：邏輯掛在動作裡，分派表還指著舊動作

實作「自動模式沒有反白框時，退格退掉一個輸入單位」（使用者裁定
2026-09-20，見 [[反白刪除用在自動模式：先否決，重查後段與格都做了]]）
之後，Mac 實測回報**完全沒效果**——倒退鍵照樣只退一個按鍵。

引擎那一半是對的，測試也是綠的。**錯在按鍵分派表**，而且兩平台共用
同一份，Windows 一樣壞。

## 根因：那個前提自己保證了走不到

新規格寫在 `Session::delete_marked_cell()` 裡：沒有框就轉去
`backspace_unit()` 退一個音節／mora。而那支**只有 `Action::DeleteCell`
會呼叫**。

分派表那端：

| 模式 | 倒退鍵送誰 |
|---|---|
| `Mode::Selecting` | `Action::DeleteCell` |
| `Mode::SegMenu` | `Action::DeleteSeg` |
| `Mode::Typing` | ~~`Action::Backspace`~~ ← **直接刪一個鍵** |

而 `mode()` 的判斷是「`select_index()` 有值才算 Selecting」。所以
**「沒有反白框」這個前提，本身就保證了分派表不會轉到新程式碼那裡去**
——兩端各自都對，接縫沒接上。

## 為什麼 728 條測試全綠

`0e16750` 加的三條測試長這樣：

```rust
let mut s = typed("su3cl3");
assert!(s.delete_marked_cell(), "沒有框該退一個單位");
```

**直接呼叫函式，跳過了分派那一步**。CLAUDE.md 那條「測試要走產品真正
跑的那條路」再一次：自己組一條等價的路來測，把 bug 放回去照樣過。

判準沿用既有的那條——**故意把修正還原，看測試會不會紅**。舊的三條
不會紅（它們測的是函式本身，函式本來就沒錯）。

## 修法：改分派表一行，平台層不動

```rust
(Mode::Typing, Combo::plain(Key::Backspace), Action::DeleteCell),
(Mode::Typing, Combo::shift(Key::Backspace), Action::DeleteCell),
```

平台層一個字沒改。`DeleteCell` 的分支本來就是「三態設定說不要、或
`delete_marked_cell()` 回 `false`，就退回 `session.backspace()`」，語意
剛好吻合，所以三條舊行為原封不動：

| 情境 | 走到哪 | 跟改動前 |
|---|---|---|
| 設定 `Off` | `want` 為假 → `backspace()` | 一樣，刪一個鍵 |
| 鎖定注音／日文 | `delete_marked_cell()` 開頭回 `false` → `backspace()` | 一樣，鎖定模式自己那條路 |
| 自動模式、沒有框 | `backspace_unit()` | **新行為** |

`Shift+`倒退鍵那條是補的：設定成 `ShiftBackspace` 時打字中本來**沒有
任何綁定可查**，會漏回宿主。

## 守法：測試改從分派表那端問

`binding.rs` 的 `打字中的倒退鍵` 兩條走完整的 `lookup()`，問的是
「打字中按倒退鍵會轉給誰」。故意把修正還原，**兩條都紅**。

平台層的坑測資鎖不到（引擎本來就是對的），只能在這種地方守——
同一個道理見 [[怎麼系統性抓出平台層漏接：解構與 API 反查]]。

## 留下來的

`Action::Backspace` 現在**沒有任何鍵綁它**，平台層兩支的分支成了備而
不用。刻意留著（改鍵位表的人可能會用到），要清再說。

## 教訓

**新規格掛進某個動作的內部時，回頭確認分派表有沒有把那個情境轉過去。**
症狀是「功能寫完、測試全綠、實測零反應」，而且讀那段實作看不出任何
問題——因為問題不在那段裡。
