# 選字框與切法選單的互動調整：偏好語言與按鍵數挑代表都被否決

這一節記的是使用者實際用起來之後回報的一批調整。多數改動本身很小，
**值得留下的是理由與量測** ——尤其有兩個想法是實測之後才發現行不通的。

## 2.13.1 選字：框是游標，候選清單是要看才叫的

原本的行為：按 Enter 選中之後就離開選字，反白整個消失、插入點跳到組字
尾端；想再改別的字得按方向鍵，而且**從第一格重新跑**。改完第五個字想
改回來，等於整段重走一遍。

改成一組互相配合的規則：

| 按鍵 | 行為 |
|---|---|
| `←` `→` | 移動反白框，**候選清單不出現** |
| `↑` `↓` | 叫出候選清單；**第一下只負責打開**，不順便換字 |
| `Enter` | 選中，框留在原地 |
| 數字鍵 | 只在清單開著時有效 |

背後是一個概念上的拆分：**框是「現在在改哪一格」的游標，清單是「這一格
有哪些字」**。混在一起的話，只是想把框移過去看看，候選視窗就一直彈出來
擋著。

幾個彼此牽連的細節，改動時不能只看其中一條：

- **離開選字不等於忘記位置**。`exit_select` 把位置記進 `last_select`，
  用在兩處：框留在畫面上（`marked_index`）、下次方向鍵從那裡接續。
- **又打字就把框收掉**。那個標記的意思是「你剛改了這一格」，繼續打字
  之後就過期了，留著會是個沒人管的框。
- **「重新進入選字」是內部細節，使用者不該感覺得到**。框就在畫面上，
  按右鍵的意思當然是「移到下一格」——第一版沒吸收掉這件事，變成要按
  兩下才動一格。三種狀態收進 `arrow_right` / `arrow_left` 一個入口。
- **從打字直接按上下鍵是一次到位**（框與清單一起出來），因為那個動作
  本身就是「我要挑字」。只有左右鍵是純移動。
- **什麼都沒有時第一下只叫出框、不移動**。那時框還沒出現，連那一下都
  往右移的話，框會憑空出現在使用者沒預期的位置。

## 2.13.2 進選字的落點：不要寫死在函式裡

方向鍵進選字改成落在**最後一格**——剛打完字，插入點就在尾端，最可能
要改的是最後一個字，落在最前面等於要一路按回來。

一開始想直接改「進選字」的預設落點，實測**會弄壞 17 個測試**——而那些
測試沒有錯，它們測的是「從第一格開始」的移動機制。

> **進入點是政策，不該寫死在函式裡。** 改成兩個名字對稱的原始操作
> （`enter_select_first` / `enter_select_last`），由呼叫端決定用哪個。
> 原本 `enter_select` 這個名字會讓人以為它是「預設」，改名之後就沒有
> 這個誤導，日後想讓左右鍵有不同落點也不必再拆。

## 2.13.3 切法選單：4～6 名固定放三種語言的代表

使用者心裡常常是「我這句其實想打的是純日文」或「這串就是英文，別轉」。
但那種切法在排序裡不見得靠前——**尤其整串英文 passthrough 沒有任何詞典
依據，翻很久都翻不到**。

| 語言 | 代表 |
|---|---|
| 注音 | 該引擎認可字數最多的那一種切法 |
| 日文 | 同上 |
| 英文 | **整串 passthrough——直接造一個，不從清單裡找** |

**前三名一動也不動**，第一名仍是引擎算的最佳解（也就是預設會送出的
東西）；已經出現在前三名的代表不重複列，只是標上記號。

選單上標成「（中）你好」「（日）すし」。一種切法可能同時是兩個語言的
代表，那就標「（中日）」——用覆蓋的話畫面上會少一個記號，使用者反而
找不到。記號用「中日英」不用「注日英」：選單顯示的是**輸出的文字**。

### 兩個被實測否決的做法

**一、「偏好某個語言」行不通。**

原本要做的是「偏好日文就把日文的切法整批往前移」。做出來一量：

```
su3cl3（你好）  無偏好 → ["你好", "す3c襖", "你cl3"]
                偏日文 → ["す3c襖", "す3cl3", "你好"]   ← 正解掉到第三
```

這正是 §2.7 記載的陷阱：
**任何夠強的偏好都會波及其他句子**。改成「保證看得到，但不動已經排好
的」，兩個目的就不衝突了。

**二、挑代表不能看「按鍵數」，要看「引擎認可的字數」。**

第一版用「這個語言的段落裡有幾個按鍵」，結果 `check u vu84` 的中文代表
挑到「ちぇ喝一下」而不是「check 一下」——前者的注音段按鍵比較多，但那些
根本不是詞。

> **「標成什麼語言」跟「引擎認可它是合法的詞」是兩回事。** 這個區別本來
> 就在排序層裡（`rank::claimed`：注音要查得到詞、日文要是合法羅馬字串、
> 英文要是常見詞），只是沒開放出來用。補了 `rank::covered_by` 之後同一個
> 輸入就正確挑到「check 一下」。

**鎖定模式不補代表**——既有測試「鎖定時只有一種切法」抓到的：鎖定的整個
意義就是「只有一種切法、不要給我選」。

## 2.13.4 ↑↑↓↓ 可以開關語言引擎

打「日文」再比手勢就切換日文引擎，跟既有的「開啟設定」一樣三種語言都能
觸發（`japanese` / `b4jp6` / `nihongo`、`nihonngo`）。注音的按鍵串是從
詞庫**反查**出來的不是用推的——「注音」的一聲是空白鍵，用猜的會錯。

三個決定：

- **做成切換不是停用**。只能關不能開的話，關掉日文之後得跑去設定頁才
  回得來；而日文關掉後英文的 `japanese` 仍然打得出來，不會把自己鎖在
  門外。
- **英文沒有對應的指令**。它是瀑布的最後一站，關掉之後什麼都打不出來，
  連要開回來的指令都打不了。有測試釘住這件事。
- **會真的寫進 `config.toml`**。引擎開關存在那裡，而 `refresh_config` 會
  定期重讀再套回 session。只改記憶體的話下次重讀就被蓋回去，症狀是
  「關掉了，過幾秒又自己開回來」。

狀態顯示在候選視窗底部的提示列，不彈浮動視窗——那是**持久的設定**，
浮動視窗閃一下就沒了，而使用者是「下次打字時」才會想起「咦怎麼打不出
日文」。提示列沿用既有原則：全開是預設不顯示，有東西被關掉才提示。

## 2.13.5 三個小的，但各有一個坑

**數字鍵盤**原本完全失效（`typed_char` 只認主鍵盤那排）。修的時候關鍵是
**兩排數字的語意不同**：主鍵盤的 `5` 是注音的ㄓ，數字鍵盤的 `5` 就是 `5`。
接到現有的輸入路徑會被切點引擎當注音鍵，所以走獨立的一條路。順帶解掉
一個老限制：選字時數字鍵盤可以拿來選候選，主鍵盤那排做不到。

**開頭打符號直接送出**，不進組字區。判準不能憑「看起來像標點」——
**半形標點有一半是注音鍵**（`,`ㄝ `.`ㄡ `/`ㄥ `;`ㄤ `-`ㄦ），一律放行的話
那幾個音就打不出來。而且只管開頭：組字中間的標點是硬切點，要留在按鍵
串裡參與切法判斷。

**複製貼上會誤觸語言切換**。本來就有「按著 Ctrl 按了別的鍵就不算單按」
的防呆，但它只做在 `OnKeyDown`，而**那個方法在我們對修飾鍵回「不要」
之後根本不會被呼叫**——`Ctrl+C` 的那個 C 從頭到尾沒看到。標記移到
`OnTestKeyDown`（TSF 一定會問的一步）。

> 這條規則錯過兩次（第一次是把「按下 Ctrl 自己」也算成用過，單按永遠
> 沒反應），所以抽成 `keymap::CtrlTap` 這個小狀態機，六個測試釘住。
> **`State` 直接改用它**——測試守的才是實際跑的那份，不是一份平行的
> 複製品。
