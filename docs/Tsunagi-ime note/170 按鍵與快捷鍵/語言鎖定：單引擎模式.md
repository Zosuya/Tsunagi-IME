# 語言鎖定：單引擎模式

> **狀態**：鎖定機制本身現行；觸發鍵已於 2026-09-09 換成 Shift+空白（CtrlTap 那套已刪）

**`Shift+空白`** 輪替四個模式（`core/src/binding.rs` 的 `Action::CycleLock`，
打字中、沒組字、選字中都能按）：
**自動 → 注音 → 日文 → 英文 → 自動**。
（2026-08-30～09-09 原本是**單按 Ctrl**——按下放開、中間不碰別的鍵，換掉的原因見下方「按鍵換過四輪」。）鎖定之後停止自動辨識，
接下來打的都算那個語言。

## 鎖定之後就是一般的輸入法

這是使用者的原話——鎖定的語意不是「優先猜這個語言」，而是
**行為完全等同對應的單語輸入法**：

| 鎖定 | 行為等同 |
|---|---|
| 注音 | 微軟新注音——打 `hello` 就是照注音鍵解讀（ㄘㄍ…），不會變英文 |
| 日文 | Google 日本語入力（羅馬字） |
| 英文 | 關掉輸入法直接打字（passthrough） |

這個定義讓實作簡單很多：**沒有 fallback**。原本擔心「鎖定注音時
打英文怎麼辦」，答案是「跟新注音一樣，那就是注音」——要打英文
就切到英文模式，而不是靠引擎猜。

## 按鍵換過四輪

原計畫（§2.1 Phase 3）寫的是 `Ctrl+Shift+B/J/E` 三個獨立鍵。
實際定案繞了好幾圈：

| 版本 | 為什麼不行 |
|---|---|
| `Ctrl+Shift+B/J/E` | 要記三個鍵＋解鎖規則，使用者改成單鍵輪替 |
| `Ctrl+空白` | **系統層攔截**——那是 Windows 的輸入法切換鍵，log 顯示連 `OnTestKeyDown` 都沒被問過 |
| 單按 Shift | **觸發相黏鍵**——連按五次 Shift 會跳出協助工具對話框，而輪四個模式很容易連按 |
| 單按 Ctrl（2026-08-30～09-09） | 誤觸：要靠旗標分辨「單按」與「`Ctrl+C` 的 Ctrl」，那套邏輯踩過兩次坑；宿主自己需要單按 Ctrl 時也會被吃掉 |
| **`Shift+空白`**（現行，2026-09-09） | 見 [[單按 Ctrl 當語言鎖定鍵：修了兩次最後整個退休]] |

換了四輪但**核心邏輯一行都沒改**——`Session` 那層只認「鎖定成哪個
語言」，跟按什麼鍵無關。這是把狀態與輸入分開的好處。

## 單按修飾鍵怎麼判斷（已退休，2026-09-09）

> **這一節記的是 `CtrlTap` 那套判斷，程式碼已經刪掉**（換成
> `Shift+空白` 之後不需要了，見 [[單按 Ctrl 當語言鎖定鍵：修了兩次最後整個退休]]）。
> 留著是因為兩個坑本身有價值——任何「靠旗標判斷修飾鍵怎麼被用」的
> 設計都會遇到同樣的問題。

「單按」＝按下、放開，中間沒碰別的鍵。作法是一個布林旗標：

- 每個 `OnKeyDown` 問「Ctrl 按著嗎」，是的話標記為用過
- 放開 Ctrl 時，只有沒被標記過才算單按

兩個實作上的坑：

**一、標記要寫在擋鍵之前。** `Ctrl+C` 會在「Ctrl 組合留給宿主」
那一關被 return 掉，標記寫在 return 之後就永遠執行不到——
複製一次就切一次語言。

**二、按下 Ctrl 自己不算「用掉」。** `OnKeyDown` 對 Ctrl 本身
也會被呼叫，而那一刻 `ctrl_down()` 已經是 `true`——不排除的話，
按下 Ctrl 就把自己標記成用過，放開時永遠 `alone=false`，
單按完全沒反應。

## 除錯教訓：log 埋錯位置會導出錯誤結論

追第二個坑時，log 裡完全看不到 `vk=0x11`（Ctrl）的 `KeyDown`，
於是我推論「TSF 不送修飾鍵自己的 KeyDown」——**那是錯的**。

真正的原因是 log 埋在 `is_modifier_down()` 擋掉之後的位置，
Ctrl 的 KeyDown 早就被 return 掉了。把 log 移到函式最前面，
`vk=0x11 ctrl_down=true` 立刻就出現了。

**log 沒印不代表事件沒發生，只代表它沒走到你埋的那一行。**
這跟 §3.3 那條「S_OK 只代表呼叫合法」是同一類的陷阱——
證據的缺席不是缺席的證據。

## 切點引擎在鎖定時不切

鎖定的語意是「接下來都打這個語言」，那就沒有「哪裡換語言」的問題。
`refresh()` 在鎖定時走另一條路：整串就是一段，不跑累加式切法。

因此**切法選單在鎖定時直接不開**（`Tab` 沒反應）——只有一種切法，
開一個只有一項的選單只會擋住畫面。

唯一的例外是**標點**：它不屬於任何語言，鎖定時仍自成一段
（新注音打逗號也是獨立的一個符號），`compose` 那層才不會拿它去查詞庫。

## 提示視窗與全半形共用

語言鎖定的提示（自／注／日／英）跟全半形的（自／半／全）
是**同一個視窗實作**——動畫、版面、淡出完全一樣，差別只有格數與標籤。

作法是把「要畫哪幾個標籤」變成狀態（`LABELS`），而動畫層
（`WidthBar`）本來內部就是用索引在算，只是介面吃 `Width`；
加一個 `start_at(from_idx, to_idx)` 就通用了，型別轉換留在呼叫端。

**沒有複製一份幾乎相同的視窗**——那是兩份要同步維護的繪圖程式碼。

## 鎖定注音＝完整的新酷音互動

鎖定注音**不只是「只用注音引擎」**，整套輸入互動都換掉了：

| | 自動模式 | 鎖定注音 |
|---|---|---|
| 組字區 | `su3cl3`（原始按鍵） | `你好ㄋㄧ`（已完成的字＋正在打的注音） |
| 打錯聲母 | 按 Backspace | **直接打正確的就換掉** |
| 非法組合 | 留著當候選 | **按下去就擋掉** |
| 切法選單 | Tab 開 | 沒有東西可選，不開 |

架構上這是**另一條輸入路徑**，不是同一套的參數差異，見
[[輸入層拆三條路：自動、鎖定注音、鎖定日文]]。

### 退格要退回整個音節

刪已完成的音節時，**整個音節退回編輯狀態**：

```text
你ㄏㄠ →(退格)→ 你ㄏ →(退格)→ 你 →(退格)→ ㄋㄧ
                                          ↑
                                「你」退回可編輯的注音
```

原本只做 `keys.pop()` 砍一個字元，`su3` 變成 `su` 不成音節，
切段產出爛段落，畫面就從「你」跳回「su」——看起來像整個輸入法
退回自動模式了。

實作上要從按鍵串尾端找出最後一個音節的邊界。注音一律以聲調鍵
收尾，所以往前找到前一個聲調鍵的下一位就是。

### 非法組合按下去就擋

ㄈ 之後按 ㄩ 直接不收，緩衝維持 ㄈ。不擋的話會累積成非法音節，
收尾時查不到字，顯示退回原始按鍵（`你zm ` 而不是注音符號）。

**判準是詞庫不是結構**——這是查證過程中的一個發現：

```text
check("zm3")  → Valid    ← 引擎說 ㄈㄩˇ 結構合法
chars_for("zm3") → 0 個字  ← 但中文根本沒這個音
```

引擎的 `check` 只驗結構（聲介韻調的順序），那在自動辨識時是對的
（寬鬆才不會漏候選），但鎖定注音要擋非法組合就不夠。

所以另外寫了 `syllable::viable()`：窮舉補全（3 介音 × 13 韻母 ×
5 聲調 ＝ 195 種）去查詞庫，有一種湊得出字就算有救。詞庫沒載入時
一律放行——那時無從判斷，擋掉會讓使用者什麼都打不出來。

被擋的注音鍵要**完全丟棄**，不能塞進按鍵串當標點處理——
那會變成 `mㄈ` 這種東西。

## 鎖定英文＋半形＝完全不組字

鎖定英文的語意是「等同關掉輸入法」，中間隔一層組字只是干擾。
所以那個狀態下打字**直接進文件**——不組字、沒底線、不必按 Enter，
走 `InsertTextAtSelection` 而不是 composition。

**全形模式例外**：`ａｂｃ` 那種轉換是在組字階段做的，不組字就沒
機會轉。所以條件是「鎖定英文**且**非全形」。

選字不受影響——英文段的 `selectable` 本來就是 `false`（英文沒有
同音字要選），跳過候選框不會少任何功能。

切換的瞬間如果手上還有組字，那串字要**先送出去**：

- 打到一半按 Ctrl 輪到英文 → 先 commit，之後直接輸入
- 鎖定英文＋全形打了字 → 切到半形 → 同樣先 commit

不處理的話會留下一串永遠送不出去的底線文字：使用者接著打的字
直接進文件，組字區卻還掛在那裡。

## 唯一放行的 Ctrl 組合

`OnKeyDown` 原本一律擋掉所有 Ctrl/Alt 組合（留給宿主的快捷鍵）。
現在開了一個例外：`is_reserved_combo()` 只放行 `Ctrl+空白`，
其餘照舊。

`OnTestKeyDown` 也用同一個判斷——**兩邊分岔的話會出現「說要卻不處理」
（按鍵消失）或「說不要卻處理了」（宿主收到兩份）**。
