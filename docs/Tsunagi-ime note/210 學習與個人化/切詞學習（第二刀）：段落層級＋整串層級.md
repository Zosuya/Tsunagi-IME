# 切詞學習（第二刀）：段落層級＋整串層級

> **已實作**（commit `08a334f`，2026-09-02）。下面 2.26.1～2.26.4 是實作前的
> spike 與規劃，保留原貌；結果見文末「實作結果」。

> 第一刀「選字學習」已完成（[[選字學習：純文字儲存、k^n 指數權重、記 2～4 字子段]]）。這一刀處理另一類訊號：
> **使用者按 Tab 換了切法**。

### 2.26.1 spike：這條路通不通（先量再做）

`check_compose` 的 20 句切法錯裡，**19 句是同一種病**——英文詞尾跟後面
的注音母音黏成合法日文：

```text
footeru3  → フォオテ己   （該是 footer|已）
widgetaj4 → widげた誤     （該是 widget|目）
```

拿**領域包**當「已經學會這些英文詞」的替身（包影響切點這條線本來就通），
塞 12 個英文詞下去量：

| | 沒有包 | 有那 12 個詞 |
|---|---|---|
| 文字命中 | 650/720（90%） | **658/720（91%）** |
| **切法錯** | **20 句** | **11 句** |
| 錯字率 | 4.2% | **3.3%** |
| en_split | 46/50 | **50/50** |

中文、日文、`cutpoint` 全部持平，**沒有任何一項退步**。

結論：**「這串按鍵是一個英文詞」這個段落層級的訊號，就能修掉將近一半
的切法錯**，而且管道現成。為此給 `check_compose` 加了 `--pack`。

**量到的極限**：`serveru3`、`tokenu3` 修不掉——`serve` 與 `server` 兩邊
都是英文詞，光靠「這是不是詞」分不出來。那是 §2.7 點名的最難區域。

### 2.26.2 使用者定的方向（2026-09-01）

- **兩種粒度都做、都量**：
  - **段落層級**：`語:footer → en`。會推廣到別的句子（學一次 `footeru3`，
    `footer已`／`footer早` 都受惠）。
  - **整串層級**：`切:<按鍵串> → 切點位置`。只認這一整串，不推廣，
    但吃得下 `serveru3` 那種段落層級分不出來的。
- **目標有兩個**，不只一個：
  1. 正解在候選裡越靠前越好；
  2. **把「明顯不是正常句子」的切法壓下去**（`這種fu/6況就是藥用`、
     `這種情dj盎就是藥用` 那種露出沒轉換按鍵的）。
- **門檻先做成可調**，量完再定（選字那一刀是 2 次）。
- **檢視／刪除的介面這一刀不做**：學習檔是純文字、位置公開，要清掉
  直接刪檔或手動編輯——跟領域包同一套「能被肉眼審查」的哲學。

### 2.26.3 存法：沿用同一個檔，用鍵的前綴分型別

`learned.txt` 的格式是 `按鍵串 <TAB> 文字 <TAB> 次數`，三種記錄共用：

```text
footer      footer      3     ← 選字（第一刀）
語:footer   en          3     ← 段落層級
切:footeru3 6           2     ← 整串層級（切點位置）
```

前綴用中文字**是刻意的**——按鍵串只會是鍵盤打得出來的 ASCII，
中文字永遠不會跟真的按鍵串撞。次數、門檻、淘汰三套機制原封不動沿用。

### 2.26.4 生效點與效能

段落層級接在**領域包已經走通的那條線**上（`english::rank` 回 0、
`claimed` 認得），整串層級在 `rank::sort` 之後把學過的那一種提名。

**成本要壓到「沒學過就是零」**：切點排序是熱路徑（400 種切法 × 每段
各查一次詞典），不能每次都多一次雜湊查詢。做法跟 `pack::any()` 同一招
——衍生索引 ＋ 一個原子旗標，沒有任何切詞記錄時一次都不多查。
用 `bench_typing` 驗 p99 沒退。

### 實作結果

commit `08a334f`（2026-09-02）照 2.26.2～2.26.4 的設計落地，程式碼在
`core/src/learn.rs`：`record_cutting` 一次記兩種粒度——`LANG_PREFIX`（`語:`）
段落層級、`CUT_PREFIX`（`切:`）整串層級，共用 `learned.txt`；門檻是可調的
`LEARNED_CUT`（預設 3，跟選字分開），沒有切詞記錄時被 `cut_any()` 原子旗標短路。

`bench_cut_learn` 模擬「打一輪、在選單挑正解、下一輪再打」，720 句
**650 → 664**（兩種都開，單開任一種都比較差），其他計分器一個數字沒動，
p99 10.9 → 11.4ms。量測細節與兩個坑（提名要放在 `normalize` 之後、
`rank` 與 `is_word` 都要掛）見 [[切法學習的實作結果與兩個坑]]。

後續：commit `2fd1455`（2026-09-08）讓**段選單定案過的段也進切詞學習**
（`Session::learn_seg_choice` 接 `record_cutting`），原本只有 Tab 換整句切法會學。
