# 切法學習的實作結果與兩個坑

### 2.26.5 實作結果（2026-09-02）

`bench_cut_learn` 模擬「使用者打一輪、在切法選單裡挑正解、學起來，
下一輪再打一次」，720 句：

| | 命中 |
|---|---|
| 學習前 | 650/720（90.3%） |
| 只有段落層級 | 660/720（91.7%） |
| 只有整串層級 | 663/720（92.1%） |
| **兩種都開** | **664/720（92.2%）** |

**兩種都要**——單獨開任一種都比兩種都開差。選單裡本來就找得到正解的
有 14 句，兩種都開之後 14 句全部學會。

門檻掃描：在第 `門檻+1` 輪收斂（門檻 2 → 第 3 輪、門檻 3 → 第 4 輪），
終局命中一樣。**預設維持 3**——切錯詞會讓整句重新斷句、前面的字跟著
變，比選錯字貴，多要一次確認划算。

沒有任何一項退步：三支計分器（650/720、570/570・560・551、測資 0 錯）
一個數字都沒動——學習庫是空的時候整條路被 `cut_any()` 那道原子旗標
短路掉。按鍵延遲 p99 10.9ms → **11.4ms**（塞 500 條切詞記錄之後量的，
目標 16ms）。

### 2.26.5.1 兩個踩到的坑

**一、提名要放在 `normalize` 之後。**
第一版把「把學過的切法提到第一名」寫在 `rank::sort` 裡，結果 14 句
可修的只修好 6 句。原因是 `sort` 之後還有 `normalize`（相鄰同語言的
段會合併），而學習記下來的是使用者在選單上看到的、**正規化之後**的
位置——在 `sort` 裡比對等於拿正規化前的位置去對正規化後的紀錄。
改到 `input.rs` 組出最終清單之後才對。

**二、段落層級只掛 `rank` 不夠，`is_word` 也要掛。**
只改 `english::rank` 的話 720 句只多對 1 句。查出來是因為
`footer`、`widget` 這些**根本不在 en_50k 裡**——`rank` 回 `None`、
`is_word` 回 false，於是 `claimed` 不認、那條切法排不上去。
`spike` 用領域包做替身時之所以有效，靠的正是包同時改了這兩個入口。

**順手修掉一個既有的潛在 bug**：`rank` 的分數快取用詞庫版本號當有效期，
而 `pack::set_index` 從來沒有讓版本號 +1——使用者中途換包會拿到舊分數。
學習也有同一個需求，兩邊都補上 `dict::bump_generation()`。

### 2.26.6 第二個目標：壓掉「明顯不是正常句子」的切法

使用者定的第二個目標（2026-09-01）。典型長相：

```text
這種fu/6況就是藥用      ← `/6`（ㄥˊ）合法，但沒有字念這個音
```

判準是**顯示不出來**：注音段切得出音節、卻有音節查不到任何字，
畫面上就是一串原始按鍵夾在中文裡。新增 `Score::fewer_unreadable`。

**整串的最後一個音節不算**——那可能只是還在打（聲調還沒按），
罰它會把候選推向日文，那正是 `fewer_split_syllable` 在修的病。
所以「前面的音節」與「最後一個音節」要分開判。

結果：三支計分器一個數字沒動，那一列從第 3 名消失。
按鍵延遲沒有量得出來的變化（機器忙的時候 p99 在 11.6～14.5ms 之間跳，
改前改後同一個區間）。
