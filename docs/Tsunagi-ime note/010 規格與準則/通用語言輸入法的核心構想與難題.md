# 通用語言輸入法的核心構想與難題

### 核心矛盾
語言辨識需要「足夠長的內容」才準確，但輸入法需要「即時反應」——兩者互相衝突。
例：打 `j` 可能是英文、拼音、越南文開頭，短序列下無法判斷。

### 三種技術路線
1. **延遲判斷 + 緩衝區**：等打完一個詞（遇空白/標點）才判斷語言，但犧牲即時候選字體驗
2. **平行跑多套引擎**：同時用各語言引擎解析同一段輸入，各自產生候選字，依信心分數排序（較實際的做法，但候選欄可能混雜多語言，UX 需精心設計）
3. **上下文輔助判斷**：用前幾個詞的語言作為先驗機率，提升準確度但無法完全消除模糊情況

### 現實難點
- 鍵位系統重疊（尤其拼音 vs 英文，羅馬字日文 vs 英文）
- 切換成本 vs 誤判成本：手動切換已經是零延遲、零誤判，自動辨識一旦誤判，修正成本可能更高
- 少數語言資料蒐集困難（若要做到「通用」）

### 建議切入點
不追求「完全自動判斷」，改做**降低切換成本**：
- 輕量分類器做「建議」，保留使用者一鍵覆蓋機制
- 先鎖定 2-3 種語言組合做 MVP，驗證準確率與接受度
