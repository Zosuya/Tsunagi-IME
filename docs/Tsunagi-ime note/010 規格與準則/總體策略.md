# 總體策略

筆記中的核心結論直接決定本計畫的方向：

1. **不追求完全自動判斷語言**，而是「降低切換成本」——輕量分類器給建議、候選排序，保留一鍵覆蓋與語境鎖定。
2. **平行跑多套引擎**（路線 2）為主幹，輔以**上下文先驗**（路線 3）調整信心分數；不採用純延遲判斷（路線 1），避免犧牲即時候選體驗。
3. **MVP 平台鎖定 Windows（TSF）**——開發環境即 Windows，且 TSF 是三平台中市佔最大的一塊。核心引擎與平台層徹底分離，之後移植 macOS IMK / Linux Fcitx5 時只重寫整合層。

### 架構分層（跨平台的關鍵）

```
┌─────────────────────────────────────────────┐
│  平台整合層（每平台各一套）                    │
│  Windows: TSF TIP (DLL, COM)                │
│  macOS: IMK Bundle（後期）                   │
│  Linux: Fcitx5 addon（後期）                 │
├─────────────────────────────────────────────┤
│  IPC / FFI 邊界（穩定的 C ABI 或 protobuf）   │
├─────────────────────────────────────────────┤
│  核心引擎（跨平台、無 UI、純邏輯，可獨立測試） │
│  ├─ 按鍵事件正規化                            │
│  ├─ 語言辨識層（特徵 + FSM 過濾 + 詞頻評分）   │
│  ├─ 三個語言引擎（注音 / 英文 / 日文羅馬字）   │
│  ├─ 候選合併與排序（信心分數）                │
│  └─ 狀態機（組字緩衝、語境鎖定、快捷鍵語意）   │
└─────────────────────────────────────────────┘
```

### 技術選型（建議）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 核心引擎 | **Rust** | 記憶體安全（IME 常駐所有程式的行程內，崩潰代價極高）、跨平台、易做純邏輯單元測試 |
| Windows 平台層 | Rust（`windows-rs` 實作 COM/TSF）或 C++ 薄殼 | 先以 `windows-rs` 嘗試；若 TSF COM 介面卡關，退回 C++ 薄殼 + FFI 呼叫 Rust 核心 |
| 候選視窗 UI | 先用 TSF 內建 UI-less 模式 + 自繪 Win32 視窗 | 避免過早引入重型 UI 框架；自繪視窗才能完全控制定位與快捷鍵提示 |
| 詞庫格式 | 編譯期打包成 FST / trie 二進位 | 啟動快、記憶體省；來源見 [[詞庫來源候選與授權顧慮：MIT 優先、LGPL 需隔離]] |
| 設定/詞頻儲存 | 使用者目錄下 SQLite 或平面檔 | 個人詞頻學習需要持久化 |

**參考的開源實作**（讀碼用，注意授權）：

- 日文：Google mozc（Romaji 轉換表與詞庫結構）、SKK 字典
