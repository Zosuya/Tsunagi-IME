# 輸入法開發的一般門檻

### 平台 API 門檻
- **Windows**：TSF（Text Services Framework）為主流，概念抽象（Context、Range、EditSession），學習曲線陡；舊式方案為 IMM32
- **macOS**：Input Method Kit（IMK），需寫成 Input Method Bundle，使用 `IMKServer`、`IMKInputController`
- **Linux**：IBus 或 Fcitx，兩套協定互不相容，跨平台需分別維護
- 跨平台 = 三套完全不同的系統整合層

### 技術門檻
- 組字階段（composition）：打字過程中顯示候選字、暫存字串，需與系統 IME 框架即時互動
- 候選字視窗 UI：自行繪製或呼叫系統元件，需處理游標定位、跟隨輸入框位置
- 應用程式相容性：遊戲、Electron App、部分瀏覽器對 IME 支援不完整，易有跳字、候選視窗定位錯誤等問題

### 輸入邏輯本身
- 拼音、注音、倉頡等規則明確的輸入法：轉換邏輯不難
- 智慧選字/預測（新酷音、搜狗等級）：需語言模型或詞頻統計，工作量大增

### 簽署與安全性
- macOS：IME 需 code signing，未簽署會被系統擋下
- Windows：企業環境可能限制未簽名驅動/服務層元件
