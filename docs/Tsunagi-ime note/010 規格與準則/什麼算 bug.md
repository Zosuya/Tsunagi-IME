# 什麼算 bug

**核心原則：驗證合法性，不是猜出唯一正確答案。**

一串按鍵常常同時是多種語言的合法輸入（`sushi` 是英文也是日文、
`0` 是注音「安」也是數字）。引擎的職責是把**所有合法解讀都放進候選**，
排序只是建議，最終由使用者選。

這條原則直接決定了「什麼算 bug」：

| 現象 | 是 bug 嗎 |
|---|---|
| 使用者按的鍵沒顯示出來 | **是**，按鍵不能憑空消失 |
| 某個合法解讀不在候選裡 | **是**，那是排除而非排序 |
| 合法解讀排到第 30 名 | **是**（實務上等於找不到） |
| 第一候選猜錯，但正解排第二 | 不是，排序問題可接受 |
| 罕見組合切詞切錯 | 不是，記錄取捨即可 |

目標是**通用**，不是百分之百正確。

## 這個專案最反直覺的一件事

**注音鍵位就是 QWERTY 字母鍵**（`t`=ㄔ、`a`=ㄇ、`k`=ㄜ…），所以任何英文
字串都「切得出注音音節」——`hello` 會被切成 h/el/l/o。

於是「結構上合法」完全不能當作「這是注音」的證據。整個專案有大半的規則，
都是在處理這個重疊帶來的歧義。
