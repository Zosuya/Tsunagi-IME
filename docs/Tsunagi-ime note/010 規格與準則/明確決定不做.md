# 明確決定不做（不要重新提議）

| 項目 | 為什麼不做 |
|---|---|
| ⛔ **快捷鍵自訂** | 鍵位表已經很擠（十個數字全是注音鍵），綁錯就打不了字，而衝突偵測的工程量比功能本身大。要調鍵位直接改 `core/src/binding.rs` 的 `DEFAULT_BINDINGS`（2026-09-13 從 Windows 的 `keymap.rs` 上搬，兩平台共用一份） |
| ⛔ **誤判回報** | 隱私敏感度最高——輸入法看得到使用者打的每一個字 |
| ⛔ **學習檔的完整檢視／刪除介面** | 個人專案，成本遠大於效益 |
| ⛔ **維特比 DP ＋ 長度先驗** | **實測否決**，不要再試一次（跟[[做過但按護欄還原]]的 lattice 是兩件事：那個是修好了被護欄擋，這個是量完不成立）。見 §2.61 |
| ⛔ **`covered` 對單音節注音算按鍵數** | **實測否決**：模擬說 +2，實作是**漏斗 -102**（四個門檻全負）。根因是模擬只重排候選、看不到「切法名次一變，選字層的上下文也變」。根本問題（`covered` 對單音節隱形）仍在，但要換別的解法，見 [[正解常在第二名：covered 隱形，四個病因都沒過關]] |
| ⛔ **抄 libchewing 的學習曲線** | 它第一次選就給最高分＋10，一次就翻到第一——太激進 |
| ⛔ **學習權重「只贏一個身位」（相對競爭）** | **實測否決**：綁對手原始分數會讓原本的第一名永遠爬不回去（反悔 28.6 次、287/301 卡死），綁加權後分數會互相封頂。根因是「誰在前面」本身由次數決定，拿它當基準是循環的。見 [[學習曲線：改的是記法，不是曲線（加減分＋次數封頂）]] |
| ⛔ **注音 bigram（用詞頻推字對）** | 推出來的字對不夠好，[[spike：注音 bigram——用詞頻推出來的字對不夠好]] |
| ⛔ **背景自動下載替換 DLL** | DLL 換不掉（已開的行程還是舊版），而且沒簽章之前那是攻擊面，[[自動更新：只做「檢查並提示」，不做背景替換]] |
| ⛔ **擴充包的下載／一鍵安裝** | 時機不對：還沒有量，而且會把「純文字肉眼可審」這條防線變成名存實亡，[[擴充包要放哪：獨立 repo，與兩個量出來的洞]] |
| ⛔ **ARM64 發布** | 沒有測試機，x64 IME 在 ARM64 能服務哪些宿主沒查證過——**盲發比不發更糟** |
