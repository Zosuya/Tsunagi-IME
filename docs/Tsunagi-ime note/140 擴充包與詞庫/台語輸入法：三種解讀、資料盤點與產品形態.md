### 2.64.1 「打中文字轉台語」有三種意思，難度差三個量級

| | 使用者在打什麼 | 本質 | 難度 |
|---|---|---|---|
| A 拼音式 | 台羅或白話字（`guan2` → 阮） | 跟注音引擎同構，換一份音節表 | 中，但市面上已經有 |
| **B 華語詞轉台語詞** | 用注音打「他們」，候選出「𪜶」 | 注音輸入法＋一份華台對照表 | **低，使用者選這個** |
| C 整句華語轉台語 | 打「你吃飽沒」出「你食飽未」 | 機器翻譯 | 高，而且不該做成輸入法 |

**A 已經有人做了**（信望愛台語客語輸入法、Android 的 PhahTaigi、RIME 的
台羅方案），再做一套要有特別的理由；而且使用者得會拼台羅，那是極少數。

**C 不適合做成輸入法**：華語與台語的語序、語法都不同（「你有沒有吃飯」
對「你食飽未」），詞對詞查表湊不出來。更根本的是**互動衝突**——要打完
整句才能轉，中途沒辦法逐字修正，跟輸入法「邊打邊看」的模型天生打架。
要做這件事該做成翻譯工具接現成模型，不是輸入法。

**B 服務的是腦中已經有台語句子、只是不知道怎麼打出「毋」「袂」「佮」
「𪜶」的人。**難的部分（TSF、候選視窗、注音引擎、選字、學習層）這個
專案已經做完了。

### 2.64.2 資料盤點：一個開源資料庫就收齊了

ChhoeTaigi 找台語資料庫（`github.com/ChhoeTaigi/ChhoeTaigiDatabase`）把
十本辭典整理成統一欄位的 CSV。有「對應華文」（`HoaBun`）欄位的三本：

| 來源 | 筆數 | 授權 | 適不適合 |
|---|---|---|---|
| **iTaigi 華台辭典** | 19,046 | **CC0** | **最適合**——它本來就是「華語查台語」的眾包詞典，授權零負擔 |
| 台華線頂辭典 2002 | 91,339 | CC BY-SA 4.0 | 量最大，可當補充，分開標示出處就能用 |
| 教育部台語辭典 | 24,608 | CC BY-ND 3.0 TW | **禁止改作**，拿來當詞庫有灰色地帶，建議先不用 |

共同欄位：`PojUnicode`／`PojInput`（白話字）、`KipUnicode`／`KipInput`
（教育部台羅）、`HanLoTaibunKip`（漢羅台文）、`HoaBun`（對應華文）。

**iTaigi 的用字跟教育部推薦字體系一致**，所以「該用哪一套用字」這個問題
自動解掉——B 路線只要漢字，不碰讀音，連腔調差異（漳泉、`hî`／`hû`）都
避開了。

> 授權以各官方頁面為準，實際採用前要再確認一次。這是 §2.31 那次盤點的
> 同一條規矩：**資料的授權比程式碼難**。

### 2.64.3 做法：三步，引擎本身不用動

1. **建表**：從 CSV 抽「華語詞 → 台語漢字」，一個華語詞可能對到多個台語詞
2. **華語詞變按鍵串**：使用者是用注音打華語的，所以表的鍵要從「他們」變成
   `wj/ k/`。這步查現有的注音詞庫就行，**跟 `mkkeys` 是同一件事**
3. **接進候選**：打完那串按鍵，候選裡出現台語詞

工程量大約等於**一個領域包**（[[領域包：從「合併進詞庫」改成「獨立的一層」]] 的 `Layered`），多的只是「候選裡標示
這是台語詞」的顯示層。

### 2.64.4 沒把握的三件事（要先做小規模測試）

- **華語詞轉按鍵串的覆蓋率**。iTaigi 的華語詞不一定都在注音詞庫裡，查不到
  的要逐字拼，碰到多音字會拼錯——**這正是 CLAUDE.md 警告過的「整句丟進
  `mkkeys` 會逐字拼、多音字全錯」**。要實際量：兩萬條裡多少能可靠轉出來
- **`HoaBun` 欄位乾不乾淨**。眾包資料常有「他們；他人」這種多義、或夾註解
- **候選視窗畫不畫得出台語字**。「𪜶」在 Unicode 擴充區，很多字型沒有，
  打出來是方框。這不是輸入法能解的，但使用者會怪到輸入法頭上

### 2.64.5 「乾脆抽出去做獨立專案」——量過，可丟的只有兩成

使用者的直覺是「把注音相關的抽出去、加入台語字」。方向對，但比例反過來
——不是「把注音抽出去」，是**「把整個輸入法帶走、只拔掉多語辨識」**。
實測行數（不含 `bin/` 與 `tests.rs`）：

| | 行數 | 獨立台語輸入法要嗎 |
|---|---|---|
| 平台層（TSF、候選視窗、D2D、語言列、崩潰隔離） | 12,234 | **全部要** |
| 設定頁 | 2,552 | 要 |
| `core` 扣掉下面那列 | 13,130 | 要（注音引擎、詞庫、選字、學習、擴充包、設定、主題、全半形、符號） |
| `core` 的 `romaji/`＋`cutpoint/`＋`english`＋`language` | 7,099 | **可以丟** |

**帶走約 80%，能丟的只有 20%。**核心引擎那部分確實跟直覺一樣簡單
（鎖定注音本來就是獨立的輸入路徑，見 [[輸入層拆三條路：自動、鎖定注音、鎖定日文]]，接台語詞表就能用），
**代價不在抽，在之後**：這份 CLAUDE.md 記的十幾個 TSF 坑會變成兩份，
修一個要改兩邊，忘記另一邊的機率很高。

### 2.64.6 折衷：一份程式碼、兩個產品

專案裡已經有一模一樣的先例——`panic-test` 那個 cargo feature，測試觸發點
常駐在程式碼裡、正式版編不進去（§2.33）。台語照這個做：

- **同一個 DLL 註冊兩個 profile**：一個 DLL 向系統登記「通譯」與「台語」
  兩個輸入法，使用者在語言列看到兩項，各有圖示與名字。連編譯開關都不用，
  註冊時多登記一筆。缺點是安裝包一定帶著日文詞庫
- **編譯開關切出獨立變體**：編譯時決定要不要帶日文英文，切出「只有注音
  ＋台語」的 DLL，另一組 GUID、另一個名字、另一個安裝程式

**這不是取巧，是這個圈子的主流做法**：RIME 一個引擎配注音／粵拼／台羅等
方案；libchewing 一份引擎接 Windows TSF 與 Linux ibus 兩個前端；微軟內建
的注音／拼音／日文／韓文共用同一套 TSF 框架各自註冊 profile。輸入法以外
有 VS Code 對 VSCodium、Android 的 build flavor。

**三個要先付的成本**：測試矩陣變兩倍（開關數壓到最少，只做一個「精簡版」
開關，不要做成任意勾選）、品牌相關的東西（名字／GUID／圖示／安裝路徑）
現在散在 `guids.rs`、註冊、安裝腳本裡要先收攏、兩個產品同機共存需要兩組
GUID 不然互相覆蓋註冊。

### 2.64.7 台語本身的坑（引擎解不掉的那些）

- **一對多沒有正解**：華語「我們」對台語是「阮」還是「咱」，看包不包含
  聽者，詞表分不出來，只能列出來讓使用者選。B 路線的使用者會台語，可以接受
- **字型顯示**：擴充區漢字（𪜶）很多字型沒有
- **用字有好幾套**：選定 iTaigi ／教育部推薦用字這一套就好，不要混

**B 路線避開的**：腔調差異、變調——因為不打台語的音

### 2.64.8 待決事項

1. **產品形態**：三選一——(a) 分開 repo（要維護兩份平台層）、
   (b) **同一份程式碼＋編譯開關切出獨立產品（建議）**、(c) 只當通譯的
   第四種語言
2. **互動形式**：鎖定模式（單按 Ctrl 輪到「台」，不干擾平常打華語，**建議
   優先**）還是混進候選（打「他們」時多一個標「（台）」的「𪜶」，方便但
   候選變擠）
3. **資料來源**：只用 iTaigi（CC0，19,046 條，建議先這樣把流程跑通），
   還是加上台華線頂（量大五倍但用字較舊）
4. **要不要先跑 2.64.4 那三個小測試**——它們不受 1～3 的決定影響，可以先做
