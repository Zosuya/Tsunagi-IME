# 擴充包編輯器的實作與收尾

> **狀態**：主體做完、兩件收尾修好，但「zh 兩個注音出一長串」等使用者裁決，這一輪沒跑漏斗

### 2.75.10 實作了什麼（2026-09-11）

`settings/src/pack_editor.rs`（編輯器）＋ `pack_list.rs`（上半部的清單），
兩者合成**一個「擴充包」分頁**——舊的 `packs_page` 從 `main.rs` 移走。

**core 這邊加的**：

| 東西 | 做什麼 |
|---|---|
| `pack::Editable`／`Entry` | 把 `.txt` 讀成可編輯的形狀，改完照原樣寫回去 |
| `pack::read_editable`／`write_editable` | 讀寫。**覆寫前備份成 `.bak`**、一律寫使用者自己的資料夾 |
| `pack::bopomofo_to_keys`／`keys_to_bopomofo` | 注音與按鍵互轉。**一聲要補空白**（見 2.75.12） |
| `pack::zh_word` | 給選詞層問「這串按鍵在包裡是什麼」（[[擴充包的中文詞被 bigram 推翻]]） |
| `pack::Meta::readonly` | 檔頭 `# readonly: true`，整包唯讀 |
| `reverse::keys_for` | 詞 → 按鍵的反查 |
| `dict_bin*::iter_words`／`iter_chars`／`key_at` | 掃詞典建反向索引 |

**UI 的決定**（都是使用者定的）：

- 清單與編輯器**合在同一分頁**：上面選一個包，下面就是它的內容。
  勾選框管「啟不啟用」、點那一列管「現在看哪一個」，**兩件事分開**
  ——常常要看一個沒啟用的包裡有什麼，綁在一起的話得先啟用才看得到
- 欄位順序：**輸出擺第一個**（那才是使用者心裡想的），接著「怎麼打」、
  語言。語言是**算出來的**，不是選的
- 「怎麼打」**顯示用人話、編輯用按鍵**：平常中文顯示注音、日文顯示假名，
  點進去才變成按鍵讓他打
- 管整個包的操作（新增／刪除／編輯）排在**基本資料上面**；儲存與取消
  跟編輯**同一個位置**
- 清單固定 10 列、內容固定 20 列，**超過就捲、不足就空著**——高度固定，
  畫面才不會跟著資料量跳動
- **欄位一律不放提示文字**：欄位窄的時候會被切成「打一個」「按鍵（」，
  而表頭與標籤已經說了那一欄是什麼

### 2.75.11 名稱就是檔名

新增一個包時，「名稱」欄決定檔案叫什麼，內部登記的名字跟檔名相同。
不再有「沒填就用檔名」這種後備——兩個名字一致，使用者就不必去想
「我在清單上看到的跟磁碟上的是不是同一個」。

代價是名稱要擋掉檔名不允許的字元（`\ / : * ? " < > |`），空著也不給存。

### 2.75.12 踩過的坑（都是實測回報的）

| 症狀 | 病因 |
|---|---|
| 「今天」的語言辨識不出來 | **一聲的空白被 trim 掉了**。注音的一聲就是空白鍵，`rup wu0 ` 少了結尾空白，後半 `wu0` 被當成英文。而且**檔案裡的注音一聲不標符號**，逐字元轉的話每個一聲都會掉——音節邊界的判斷要交給 `dict::symbols_to_keys` |
| 欄位被切成「打一個」「按鍵（」 | `allocate_ui_with_layout` 的尺寸是「**最多**用這麼多」，裡面的 Label 只用文字實際需要的寬度，那一格就縮到文字大小。要用 `allocate_exact_size` |
| 清單怎麼點都沒反應 | 兩層原因：① 整列的感應區範圍算錯（Grid 裡 `ui.cursor()` 指的是下一格要畫在哪、`ui.min_rect()` 是整個表格，都不是「這一列」）② egui 的 `Label` 預設可以拖曳選字，**那會吃掉點擊** |
| 勾選框點不到 | 整列的感應區是**後畫的**，在 egui 裡後畫的在上層，把勾選框蓋住了。感應區要避開它，底色仍然塗整列 |
| 台語包（9 萬條）整個卡死 | 三個「資料一大就爆炸」的寫法：① 讀檔時每條都跑一次完整的切點引擎（一條幾毫秒 × 9 萬）② 9 萬列全部建 widget（改用 `show_rows` 只建看得見的）③ 欄寬每幀量 9 萬條的文字寬度（改成抽樣前 300 條） |
| 兩支捲軸疊在一起 | 內層的捲動區撐滿到最右邊，跟整頁那支重疊。**整個捲動區要往左退一個捲軸寬**（`max_width`） |
| 兩支捲軸**又**疊在一起（2026-09-11） | 退讓還在，但**整頁被清單撐得比視窗寬**——`description` 在 Grid 裡不換行。無視窗重現不了，追了三輪，見 [[擴充包編輯器的符號支援，與追了三輪的捲軸重疊]] 2.80.3 |

### 2.75.13 兩件收尾，一件等裁決（2026-09-11）

**一、舊包的日文鍵存成羅馬字：修好了，也看得見、修得掉**

編輯器把**羅馬字**存進檔案（`ja asee game`），但載入層期望的是**假名**
（`ja あせえ game`）——中文那條有轉回注音，日文漏了，於是整條查不到。

存檔那一端先修好（`to_entry` 轉假名、`to_row` 轉回按鍵，
`pack::編輯::日文的鍵是假名` 釘住），但**使用者手上已經存錯的包不會
自己好**——他只會看到「設定頁顯示得明明是對的，怎麼打不出來」。

所以載入時數一遍：**檔案裡 `ja` 那欄有 ASCII 字母就是舊格式**
（假名裡不會有字母）。有的話在包的上方出一行橘字，旁邊一顆「修正」
——**就是原樣重存一次**，`write_editable` 覆寫前本來就會備份成 `.bak`。
唯讀的包不給修（它隨程式發布，下次更新就被覆蓋，`save` 那邊也擋著）。

語氣是「幫你修」不是「你填錯」：**這不是使用者做錯事**。

**二、`ja` 只有兩欄：病根在 `render`，不在編輯器**

原本以為是「編輯器該擋下來」，查下去發現不是——`render` 有這條：

```rust
// **英文省略第三欄**：輸出等於輸入時第三欄沒有意義
if e.output.is_empty() || e.output == e.input { 寫兩欄 } else { 寫三欄 }
```

**那條只對英文成立**。純假名的日文詞（`すごい`、`ありがとう`）讀音
與表記本來就一模一樣，於是被寫成兩欄，而 `parse` 對 `ja`／`zh`／`tw`／
`sym` 都要求第三欄——**整條在載入層靜靜消失**。症狀跟第一件一樣：
設定頁看起來好好的、打字沒作用。

修法是把那條收窄成「只有 `en` 省得掉」。**擋在編輯器是治標**——同一個
檔案別人手寫、或未來多一種語言，一樣會踩。

編輯器那邊另外補一條擋：**日文的按鍵拼不出假名的列不給存**
（`to_kana` 回 `None`）。那種列存得進去、載入時消失，跟上面同一類。

**三、`zh` 做不到「兩個注音出一長串」——✅ 走選項②做完了（2026-09-14）**

> **結果**：`pack::build_index` 分流（對得上進 `zh`、對不上進新的
> `Index::zh_long`），`compose::merge_pack_long` 把那幾格**併成一格**。
> 漏斗 1320 跟改動前一模一樣，core 728 全過連跑 10 次穩定。
> 實作經過見本節末的「後來怎麼做的」。

以下是當時的評估（2026-09-11），保留當作決策紀錄：

選項沒變（見下），但先把風險查清楚了，**比原本估的低**：

- 現在 `build_index` 那條「字數要跟音節數對得上」是**整條丟掉**，
  所以包裡的長輸出條目今天就是死資料。放寬**不會改變任何現有行為**
- **漏斗量不到這件事**：`testdata.rs` 寫死 `__不存在的資料夾__`，
  中文包一條都不載（[[擴充包的中文詞被 bigram 推翻]] 2.78.4 記過同一件事）。跑它是為了「沒弄壞別的」
- 現成的路仍然是 `compose::merge_symbols`：好幾格併成一格、輸出任意
  字串、`cands` 留退路。要加的是一條「包的長輸出」合併路徑

三個選項原封不動：① 維持現狀、編輯器標紅擋下來 ② 放寬限制讓 `zh`
也能一對多 ③ 使用者要的其實是符號那種行為，改做編輯器的符號支援。

**③ 後來做了（[[擴充包編輯器的符號支援，與追了三輪的捲軸重疊]]），但實測證明它答不了這個需求**：`split_symbols`
對沒有空白的長字串是逐字元拆（`我請你喝一杯` → 六個一字的候選），
一個名字出不了一整串。要長輸出仍然只剩 ②。

#### 後來怎麼做的（2026-09-14，選項②）

**病根不是「限制太嚴」，是「只有一條路」。** 詞層
`apply_word_context` 逐格填字（`slots[i+k].text = c`），字數對不上
**根本填不回去**——那是物理限制不是規定。所以放寬不能靠拿掉檢查，
要另開一條路。

| 改哪裡 | 做什麼 |
|---|---|
| `pack::build_index` | 分流：字數對得上的進 `zh`，對不上的進新的 `Index::zh_long`（以前是整條丟掉） |
| `compose::merge_pack_long` | 把那幾格**併成一格**，跟 `merge_symbols` 同一個模式 |

**台語層早就不套這條限制了**（「他們→𪜶」兩字換一字），理由一樣是
「整個換掉、不逐格填」——這次等於把同一個道理補給 `zh`。

三個位置的決定：

- **排在詞層之前**：包是使用者的明確表態，優先權高於詞庫統計。排在
  後面的話詞層已經把那幾格填成別的字，還要再拆掉重來
- **併成的那格 `selectable: false`**：內容是整串文字不是同音字，給它
  選字會拿到不知所云的候選。也因為這樣，後面的 `apply_fuzzy_tone`／
  `apply_lm`／`recut_tail` 全部自然跳過它——那幾關只看 `selectable`
  的注音格，不必各自加判斷
- **`cands` 放兩條退路**：長輸出與字面原樣，跟 `merge_symbols` 把
  `literal` 放最後同一個道理

**寫測試時最長優先那條先掛了**，查出來是測資把「ㄏㄤˊ」的按鍵寫成
`c;4`（那是四聲 ㄏㄤˋ），程式是對的——順手證明最長優先真的有在運作。
教訓同 CLAUDE.md 那條「按鍵序列不准手敲，一律 `mkkeys`」：我當時
手改了 `mkkeys` 給的音。
