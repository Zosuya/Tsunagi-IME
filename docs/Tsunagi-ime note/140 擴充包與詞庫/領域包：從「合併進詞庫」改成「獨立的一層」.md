# 領域包：從「合併進詞庫」改成「獨立的一層」

領域包的核心早就做好了，但**在真正的輸入法裡從來沒有作用過**——
`pack::load()` 只有 `show_ime` 這支命令列工具在呼叫，Windows 的 TSF
層從頭到尾沒有載過包。之前驗證的「hololive 變成 hololive」是在工具
裡驗的，不是在打字時。

要補上這一段時，先撞到一個架構問題。

### 2.17.1 原本的做法擋住了 Phase 4

原本是**載入時把包合併進詞庫的表**。問題在於詞庫是 `OnceLock`，
一個行程裡建好就不能重建，而 DLL 只要宿主程式活著就不會被卸載
（見 §3.3 的 DLL 生命週期）。合起來就是：

> 在設定頁改了啟用的包，**要把正在打字的那個程式整個關掉重開**才生效。

切換輸入法沒有用，開新分頁也沒有用——跟「改了程式碼要重開瀏覽器」
是同一個坑。

更關鍵的是，這條路**長不出 Phase 4 的個人化學習**。學習的本質是
「使用者剛選了這個字，下一次立刻要不一樣」，而每學一個詞就重建
整份詞庫是不可能的。

### 2.17.2 新酷音怎麼做的：分層字典

去讀了 libchewing 的實作，它的答案很明確——**不合併，疊層**：

- `Layered` 結構持有 `dicts: Vec<Box<dyn Dictionary>>` 和一個
  `user_dict_index`，系統詞庫排前面、使用者詞庫在後。
- 查詢時每一層都查再合併：同一個詞出現在多層就取詞頻**最大值**。
- 使用者層贏；`add_phrase`／`remove_phrase` 直接寫進使用者詞庫。
- 還有**第三種層：排除清單**（`ExcludeList`）。刪詞時往排除層寫一筆，
  免得它又從系統詞庫冒出來。

這順帶回答了本專案原本掛著的待決項「包要不要支援排除條目」：
**排除是獨立的一層，不是包裡的特殊語法**。現在可以先不做，但架構
要留得下。

（來源：[layered.rs](https://raw.githubusercontent.com/chewing/libchewing/master/src/dictionary/layered.rs)、
[loader.rs](https://raw.githubusercontent.com/chewing/libchewing/master/src/dictionary/loader.rs)）

### 2.17.3 量測：多一層要多少錢

改之前先量。`bench_typing` 的 429 鍵樣本，p99 各跑三次：

| 情況 | p99 | 對比 |
|---|---|---|
| 改動前 | 11.2 / 11.5 / 11.3 ms | — |
| 分層・沒啟用包 | 11.4 / 11.6 / 11.5 ms | +0.2ms，在雜訊裡 |
| 分層・2000 條的包 | 11.7 / 12.2 / 12.1 ms | +0.6ms |
| 分層・10000 條的包 | 12.1 / 11.7 / 11.8 ms | +0.5ms |

一幀 16ms，餘裕很大。**包的大小幾乎不影響**——2000 條和 10000 條
量不出差別，因為查雜湊表跟表多大無關。記憶體 224MB → 225MB。

### 2.17.4 量出來的兩件事

**一、「可替換」本身有成本。** 要能換設定就生效，索引就得放在可換的
容器（`RwLock<Arc<Index>>`）裡，而那代表每次查詞都要拿一次讀鎖＋
複製一個 `Arc`。第一版量到**沒啟用包的人也在付這個錢**。解法是在最
前面加一道 `AtomicBool`（`pack::any()`），沒啟用包就直接跳過，成本
回到雜訊裡。

**二、有兩個函式的回傳型別被迫改。** 詞庫載一次就固定，字串借得出去；
包是可換的，借出去的東西活不過換表。`word_for` 與 `best_kana_word`
改成回傳 `Cow<'static, str>`——**查不到包的常路徑仍是零複製的借用**，
只有真的命中包才複製一次。這點很重要：`best_kana_word` 當初就是為了
避免複製才特地寫成借用的（複製版曾讓 p99 從 13.5ms 衝到 26.9ms，
見 §2.11）。

### 2.17.5 現在的形狀

| 層 | 性質 | 誰寫 | 狀態 |
|---|---|---|---|
| 系統詞庫 | 唯讀、`OnceLock` 載一次 | 隨程式散布 | 不變 |
| 領域包 | 唯讀、**可換** | 使用者放檔案 | 這次做的 |
| 個人學習 | 可寫、隨時更新 | 引擎自動累積 | Phase 4 |

三個查詢入口接上包層：英文的 `is_word`／`is_common_word`／`rank`、
中文的 `word_for`／`is_bopomofo_word`、日文的 `best_kana_word`。

**哪些會影響切點**（原本掛著的另一個待決項，現在有明確答案）：

- `zh` **會**——`is_bopomofo_word` 餵給 `rank.rs` 的 `claimed`
- `ja` **不會**——切點看的是 `KANA_WORDS`，包只接在 `KANA_BEST`
- `en` **會**，那正是 hololive 案例的關鍵

這是重構前後都一樣的行為，不是這次改的。

### 2.17.6 平台接線：包的時間戳跟設定檔分開記

`refresh_config` 原本是「設定檔時間戳變了才重讀」。包不能跟著這條走
——**使用者直接編輯包的內容不會動到 `config.toml`**，而「加一個詞
進去就想馬上能打」正是最常見的用法。所以 `State` 多記一個
`pack_stamp`（啟用中那些包檔案的最大修改時間），變了就重載索引。

### 2.17.7 設定頁

新增「擴充包」分頁：列出資料夾裡的包、勾選啟用、顯示每包的英日中
條數，附建立／開啟資料夾的入口與格式說明。

### 2.17.6.1 記事本實測通過（2026-09-01）

平台層那段是全新的程式，而**單元測試碰不到它**——`refresh_config` 要在真的
TSF 行程裡被宿主呼叫才會跑。使用者在記事本實測通過，兩條路都走了：

- 設定頁勾選啟用 → 重開宿主 → 打得出包裡的詞
- **直接用記事本編輯包的檔案、加一個詞、存檔，不碰設定頁** → 回去打字新詞就在

第二條是這次特地為它多記一個 `pack_stamp` 的理由（見上一小節），也是最可能
出錯的一條，實測過才算數。

### 2.17.7.1 包的檔頭：基本資料

包要能流通就得自我介紹。檔案開頭可以寫一段基本資料：

```text
# name: Hololive 詞庫
# version: 1.2
# author: Zosuya
# description: VTuber 名字與常見的梗
# license: CC0
# updated: 2026-09-01
# homepage: https://example.com/packs
```

三條設計規則，每一條都有理由：

- **寫成 `#` 註解**，不另創語法。舊包沒有這一段也要照樣能用——認不得
  的版本當註解跳過，行為完全不變；換成 `[meta]` 之類的語法就得先判斷
  是不是舊格式。
- **只認開頭那一段連續註解**，遇到第一行詞就停。包的內容裡出現
  `# name:` 不會被誤讀，掃描也不必讀完整個檔。
- **檔名才是身分**。設定檔存的是檔名，`name` 只影響顯示——使用者改了
  顯示名稱不會讓已啟用的包突然失效。

認不得的鍵一律忽略，所以之後加欄位，舊版程式讀到不會壞。

### 2.17.7.2 資料夾：可自訂，而且沒有隱形的後備

路徑做成可編輯的欄位，留空就是預設位置 `%APPDATA%\tsunagi-ime\packs\`
（存進 `behavior.packs_dir`）。旁邊有「瀏覽…」「建立」「開啟資料夾」
「用預設位置」。

**原本有一個專案內的後備位置 `data/packs`，拿掉了。** 它是開發時方便用的，
但會**默默搶走**預設位置：專案資料夾裡剛好有 `data/packs` 時，設定頁就指向
那裡，使用者把包放進 `%APPDATA%` 反而看不到——這件事在實際使用時真的發生了。
要在別的位置測就明講，把路徑填進設定裡，畫面上看得見。

「瀏覽…」走**系統 API**（`IFileOpenDialog` 加 `FOS_PICKFOLDERS`，Vista 之後選
資料夾的正規做法），不是叫 PowerShell。第一版寫成叫 PowerShell 是為了「不要多
一個相依」，但那個顧慮根本不存在——**設定頁本來就相依 `windows` crate**
（字型對話框、背景圖的 WIC 解碼都在用），只要多開一個 `Win32_UI_Shell` 功能。
換掉之後對話框是現代樣式、立刻跳出來、不必開新行程，還能用 `SetFolder` 從目前
的位置開始逛。

**教訓**：「為了省一個相依而繞路」之前，先確認那個相依是不是早就在了。

兩個實作細節值得記：`CoInitializeEx` 的回傳值**故意不看**——視窗框架多半已經在
這條執行緒初始化過 COM，這時會回 `S_FALSE` 或 `RPC_E_CHANGED_MODE`，兩種都不
影響後續呼叫，當成錯誤反而讓按鈕永遠沒反應。`GetDisplayName` 拿到的字串是 shell
配置的，要用 `CoTaskMemFree` 還回去。

### 2.17.7.3 版面

版面是 `egui::Grid` 的表格，不是一行一個 `horizontal`——名字長短不一
時「詞彙數」那欄才對得齊。每列最後補一格撐滿寬度，不然隔行底色會斷
在半路，看起來不像一整列。空包（解析後零條）的勾選框停用：勾了也沒
作用，讓它可勾只會讓人以為壞掉。設定裡啟用了但檔案不見的包也排進
清單（刪除線＋紅字），附「從清單移除」。

**清單要快取**——egui 每一幀都重畫，直接在畫的時候掃資料夾＋讀檔
等於每秒摔硬碟幾十次。掃一次存起來，按「重新整理」才重掃。

**順序調整先不做**（使用者定）：清單依**顯示名**排序，衝突時就照這個
順序。包不多的時候夠用，真的撞到衝突再說。

依顯示名而不是檔名，是因為使用者看到的是包名——照檔名排會看起來
像沒排序（`devterms.txt` 顯示成「程式術語」）。而且**設定裡的順序要跟
畫面一致**：勾選改變時把 `config.toml` 的清單重排成畫面的順序，不然
優先序等於「勾選的先後」，那是使用者完全看不見的東西。
