# 擴充包編輯器：不必再開記事本（設計與量測）

> **狀態**：spike 與量測都做完了；實作與收尾見另一篇

**起因是使用者的體驗訴求**：現在要加一個詞，得離開輸入法去開記事本、
記得存成 UTF-8、手打 Tab、還要自己拼出注音符號。**格式很容易弄壞，
而且注音符號是引擎的內部格式，本來就不該外洩給使用者。**

這一節記錄設計決定與 spike 的量測結果。**實作待做。**

### 2.75.1 設計：新分頁「擴充包編輯」，預覽與編輯兩態

頂端下拉選現有的包，或「＋新增包」。**預設是預覽**（唯讀，看得到裡面
有什麼），上面一顆「編輯」；按下去進入編輯狀態，同一顆按鈕變成「儲存」。

分成兩塊：**基本資料**（對應檔頭那幾行 `# name:`）與**內容**（詞的清單）。

清單三欄，**輸出擺最前面**——那才是使用者心裡想的東西：

```text
輸出          怎麼打            語言
胡桃          ㄏㄨˊㄊㄠˊ       中文
hololive      hololive          英文
ホロライブ    ほろらいぶ        日文
```

**語言那欄是算出來的、不是選的**。使用者不必知道 `en`／`zh`／`ja`
這些代號，那些只存在於檔案裡。按鍵一改就重算——引擎的
`Input::from_keys` 現成就在做「一串按鍵 → 語言段落」。

**「怎麼打」那欄顯示用人話、編輯用按鍵**：平常中文顯示注音符號、
日文顯示平假名（`cj6wl6` 對使用者就是一串亂碼）；點進去編輯才變成
按鍵讓他打，跳出來又變回去。使用者能打的是按鍵，看得懂的是注音。

**新增一條**：打「胡桃」→ 程式自動填按鍵、算出語言 → Enter 送出，
游標留在輸入框等下一個。填不出來就**留空**，Tab 過去自己填；
**空的不給儲存**。

### 2.75.2 格式不動，只是換一種產生方式

存出來還是 `%APPDATA%\tsunagi-ime\packs\*.txt`，一樣的三欄 Tab、
一樣的 `# name:` 檔頭、一樣 UTF-8。`pack.rs` 的 `parse`／`parse_meta`
**一行都不用改**。

好處是既有的包不必轉檔，別人分享的包照樣能用編輯器打開來改。
而 Tab、UTF-8、`zh` 標籤這三個坑一次全消失——**檔案是程式寫的，
不是人寫的**。

代價：夾在詞中間的手寫註解存回去時會消失（檔頭的保留）。**決定不保留**
——會用編輯器的人不會手寫註解，兩邊都要會讓實作複雜很多。

### 2.75.3 量測一：中文反查，比預期好得多

原本擔心多音字（「重來」是 `ㄓㄨㄥˋ` 還是 `ㄔㄨㄥˊ`），所以設計上
準備了「猜一個、游標跳過去讓使用者改」。**實測發現多音字幾乎不是問題**。

關鍵是 `BPMFMappings.txt` 是**整詞的讀音表**（139,640 筆），不是逐字拼：

```text
詞表抽樣 3000 筆：整詞查到 3000 / 逐字拼 0 / 查不到 0  → 100.0%
```

整詞查得到就沒有歧義。手挑的 23 個真實例子（遊戲名、專有名詞、
技術詞）**全部查得到**，其中 17 個是整詞命中：

```text
胡桃        [cj6wl6]        ㄏㄨˊㄊㄠˊ        (整詞)
重來        [tj/6x96]       ㄔㄨㄥˊㄌㄞˊ      (整詞)  ← 多音字，整詞查對了
重要        [5j/4ul4]       ㄓㄨㄥˋㄧㄠˋ      (整詞)  ← 同一個字，另一個讀音
銀行        [up6c;6]        ㄧㄣˊㄏㄤˊ        (整詞)
薛丁格      [vm, 2u/ ek6]   ㄒㄩㄝˉㄉㄧㄥˉㄍㄜˊ (整詞)
```

只有詞表沒收的才落到逐字拼（`刻晴`、`提瓦特` 這種生造的專有名詞），
那才需要使用者 Tab 過去改。**「留空讓使用者填」的退路仍然要做，
但實際會用到的次數比原本估的少很多。**

### 2.75.4 量測二：日文反查，往返驗證 99.6%

日文沒有現成的「假名→羅馬字」（`kana.rs` 的表是單向的），要自己
建反向表。**驗證方式是繞一圈回來**：轉出羅馬字再用引擎的 `to_kana`
轉回假名，跟原文比對——自己寫的反向表對不對，往返一次就知道。

拿 mozc 詞庫的 5000 個純假名讀音跑：

```text
4978/5000 往返一致（99.6%）
轉不出羅馬字 0、轉回來不一樣 22
```

過程中翻出三個洞，前兩個是我的反查寫錯，修掉了：

- **撥音／促音／長音不在 mora 表裡**（`to_kana` 那邊也是分開處理的）。
  `ん` → `nn`、`ー` → `-`、`っ` → 重複後面那個 mora 的頭一個子音
- **`っ` 後面接母音時不能重複**：`がっこう` → `gakkou` 對，但
  `あっあっ` 重複成 `aa` 會被讀成長音「ああ」，促音就消失了——
  這種只能用直接打法 `ltu`

### 2.75.5 量測三翻出的是引擎的既有缺陷：`にゃ` 打不出來

剩下 22 筆全是同一種：`にゃ`／`にゅ`／`にょ`。一開始以為是反查寫錯，
補成 `nnya` 之後**更糟**（切成 `nn`+`ya`，出「あんや」）。直接測引擎：

```text
      nya -> None
     anya -> None
    annya -> Some("あんや")   ← 誤配，不是「あにゃ」
   annnya -> None
   kinyou -> None
konnnyaku -> None
```

**引擎本身打不出 `n` 系的拗音**。切 mora 時撥音優先（規格規定一律打
`nn`），`nya` 的頭一個 `n` 先被當成「ん」吃掉，剩下 `ya` 接不回去；
補幾個 `n` 都一樣。`にゃんこ`、`こんにゃく`、`メニュー` 這些詞現在
打不出來。

**這是既有缺陷，跟擴充包編輯器無關**——反查照實產出 `nya`，缺陷修好
之後往返就自動一致。**另案處理，不併進這一輪。**

### 2.75.6 決定不做的

- **日文含漢字的詞不反查**（`東京` → `toukyou`）。`KANA_BEST` 是
  讀音→表記的單向表，反查要另外建索引。這種詞留空、使用者手填，
  填的時候那欄會即時顯示成 `とうきょう`，看得到對不對
- **「輸入 toukyou 反推出東京」不做**（使用者決定）。那等於在編輯器裡
  塞一套選字流程，複雜度跟收穫不成比例——打字時本來就選得出來，
  貼進輸出欄就好
- **台語與符號第一輪不做**。台語的鍵是華語國字、跟中文包形狀不同，
  而且自動辨識分不出「這是中文詞還是台語對照」；符號沒有語言也沒有
  按鍵，自動辨識完全用不上。兩者**穩定之後再說**，但**預覽要看得到
  符號**——不然打開一個符號包會顯示空的，像壞掉。
  **→ 符號 2026-09-11 做了**（[[擴充包編輯器的符號支援，與追了三輪的捲軸重疊]]），
  台語仍然不給編

### 2.75.7 還沒驗的：egui 的按鍵欄收不收得到原始按鍵

**唯一沒把握的技術點**。使用者在按鍵欄要打 `cj6wl6`，但他的系統輸入法
很可能就是通譯自己——那樣 `cj6` 會被輸入法組成「胡」，按鍵根本打不進去。

spike 已備好（`settings/src/bin/spike_keyfield.rs`），畫面上並排顯示
文字框內容、本幀的 `Event::Text`、本幀的 `Event::Key`，**要在輸入法
開著與關著兩種情況下各實測一次**。這件事單元測試驗不了（跟 TSF 那條
一樣），得真的打字。

### 2.75.8 量測四：按鍵欄收得到原始按鍵（實測通過）

2.75.7 的疑慮**排除了**。實測兩種情況：

**輸入法關著**——乾淨的原始按鍵，文字框裡就是 `cj6wl6`：

```text
Key(C) Text("c")
Key(J) Text("j")
Key(Num6) Text("6")
```

**輸入法開著**——按鍵被組成「胡桃」，但**組字過程中的原始按鍵串
看得到**：

```text
Key(C) Ime(Enabled) Ime(Preedit("c"))
Key(J) Ime(Preedit("cj"))
Key(Num6) Ime(Preedit("cj6"))
...
Key(Enter) Ime(Commit("胡桃"))
```

**結論：按鍵欄讀 `Ime(Preedit)` 的內容**，不管輸入法最後 commit 出
什麼。比「自動關掉輸入法」穩——不依賴輸入法肯不肯被關。

日文那條也一起驗了（打 `iitennki`）：

```text
→ 假名：いいてんき             ✓
→ 語言辨識：Romaji:iitennki    ✓
```

中文打 `cj6wl6` 判成 `Bopomofo`、日文打 `iitennki` 判成 `Romaji`
——**語言欄自己算得出來**，使用者不必選。

順帶記一個現象：日文那次 `Ime(Commit(""))` 送出的是空字串（沒裝
日文輸入法，組字被 Tab 中斷）。**但 `Preedit` 的串是完整的**，
`i`→`ii`→…→`iitennki` 一個字元都沒漏——這正是上面那個結論的依據。

### 2.75.9 顯示規則：依判定出的語言只顯示那一行

spike 三行全列是為了驗證，**編輯器不會這樣**。同一串按鍵在注音鍵盤上
一定對得出符號（`iitennki` → `ㄈㄈㄔㄍ ㄙㄙㄜㄜ`），全列出來只會干擾。

判成中文就顯示注音、判成日文就顯示假名、判成英文就顯示原字串。
