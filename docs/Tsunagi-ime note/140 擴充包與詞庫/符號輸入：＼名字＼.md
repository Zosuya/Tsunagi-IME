# 符號輸入：`\名字\`

使用者提的：想要 ★♥→※ 這類常用符號，但**不要破壞現有輸入**——
「只要在候選中能顯示有這個可以選就好」。

### 2.48.1 為什麼要獨立的命名空間

第一個想法是把符號混進同音字清單（打「星」的時候候選裡多幾個 ★☆）。
使用者自己先否決了：**中文沒辦法用**——常用字的候選本來就已經很擠，
再塞符號進去是每天都在付的成本，換一個偶爾用一次的功能。

而且英文那邊更糟：`star` 這個詞會**再也打不出原文**。

所以走 `\` 開頭。這件事的性質跟標點不同——標點是打字時真的會用到的
（`width::variants`），符號是「我知道有這個東西，但不知道怎麼打」。
兩種需求的頻率差三個數量級，不該共用同一條路。

### 2.48.2 為什麼是 `\名字\` 而不是 `\名字`

使用者一開始提的是 `\星` 加空白。改成前後包起來是使用者自己想到的，
理由成立：**收尾的 `\` 就是名字的邊界**。

沒有邊界的話，「名字到哪裡結束」得靠猜——`\星星` 是「星星」還是
「星」後面接一個「星」字？包起來就完全不必問。夾在句子中間
（`你好\星\好`）也一樣清楚。慣例上跟 Discord／Slack 的
`:star:` 是同一件事。

順帶解掉的是**打完就轉**：使用者要求「打完後面那個 `\` 就變成符號，
不用再切換一次」。有結尾的話這件事是自然的，沒有的話得多一個確認鍵。

### 2.48.3 名字是「組出來的文字」，不是按鍵

這是這個設計唯一比較巧的地方。名字如果存按鍵，中日英就得各存一份表；
存**組出來的文字**的話三種語言天然共用同一份：

```text
\vu/␣\   注音組出「星」  ─┐
\hoshi\  日文組出「星」  ─┼→ 都是「星」這個鍵
\star\   英文就是 star   ─┘（另一個鍵，指向同一組符號）
```

前兩個查的是同一列，第三個是另一列指向同一組符號。

### 2.48.4 預設永遠是原樣

`\star\` 的第一個候選是 `\star\` **自己**——不按方向鍵就不會變。

這條讓「表裡剛好有你的資料夾名」不再是安全問題：`C:\star\file`
打出來仍然是 `C:\star\file`。跟 §2.24（英文段補日文候選）、
§2.40（日文段補英文原文）同一條規則——**新增候選不改預設**。

### 2.48.5 表自己列，不抄新酷音

新酷音的 `symbols.dat` 是 LGPL 資料（§2.31 標過需隔離），不能直接搬。
「有哪些常用符號」是事實不是創作，這份表自己列，內容自然會跟它重疊。
內建 40 組（星、心、箭頭、勾叉、數學、圖形、音樂、天氣、貨幣、撲克……），
每組中英各一個名字。

### 2.48.6 接上擴充包

查詢層順序跟詞一致：**先問包、再問內建**。使用者自己加的應該贏過我們
列的。沒啟用包的話 `pack::any()` 那道原子旗標直接短路，一次查詢都不多做
（跟 [[領域包：從「合併進詞庫」改成「獨立的一層」]] 同一條路）。

包的第一欄多一種 `sym`，第二欄是名字、第三欄是一串符號。**不分語言**
——名字是組出來的文字，中文的「星」跟日文的「星」本來就是同一個字串。

### 2.48.7 兩個 bug

**開頭的 `\` 進不了組字區。** §2.47 給平台層加的閘門是「沒有標點變體
的符號直送」，而 `\` 沒有變體，於是一行開頭打的那個 `\` 直接送出去，
符號**永遠起不了頭**（夾在句子中間才打得出來）。核心層一直是對的，
問題只在那道閘。判準放在 `symbol::is_prefix`，不讓平台層自己寫死字元。

**只放符號的包裝不進去。** `pack::Info::total()` 沒把 `sym` 算進去，
於是純符號包顯示「0 條」，而設定頁「空包不給勾」的規則會停用勾選框。
兩個各自都對的規則撞在一起，結果是功能整個不可用——**新增一種內容
的時候，要掃過所有「這個包有多少東西」的問法**，跟 §3.3 對 `dict.rs`
說的是同一件事。
