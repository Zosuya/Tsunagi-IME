# 擴充包的中文詞被 bigram 推翻

**使用者實測回報**：包裡寫 `zh ㄋㄧˇㄏㄠˊ 擬郝`，設定頁顯示正確、
檔案存的也對，**但打出來還是「你好」**。

### 2.78.1 病因：選詞層拿語言模型挑，包沒有豁免

先用一支 spike 把每一層拆開看：

```text
word_for  = Some("擬郝")            ← 包有生效，查得到
words_for = ["擬郝", "你好", "妳好"] ← 排第一
compose   = 你好                     ← 但選詞出來的是別的
```

**查詢層是對的，錯在選詞層**。§2.53 把中文選字接上 bigram 之後，
詞層不再取 `words_for` 的第一個，改成在同讀音的候選之間用語言模型
挑（`lm_pick_word`），維特比重切那條路（`recut_span`）也一樣。

而「擬郝」是生造的組合，bigram 分數極低；「你好」是常見詞。
名次先驗（`LM_PICK_W_RANK`／`RECUT_W_RANK` 都是 3.0）**遠遠不夠抵**。

### 2.78.2 修法：包是使用者的表態，不受統計推翻

跟 `Slot::picked`（手動選過的字不可覆蓋）**是同一條原則**，只是表態
的方式不同——一個是當場選、一個是事先寫進包裡。

`pack::zh_word(keys)` 給選詞層問「這串按鍵在包裡是什麼詞」，兩處各自
處理：

- **詞層**（`apply_word_context`）：包裡有的話直接用，不進 `lm_pick_word`
- **重切**（`recut_span`）：`PACK_BONUS = 1000.0`，大到一定贏。
  bigram 是對數機率，單項約 −1 到 −20，一個詞最多幾對——不必精算，
  只要「無論如何都壓過統計」

**兩處都要改**：只改詞層的話重切會再翻回去（實測，改完第一處
`compose` 仍然是「你好」）。

### 2.78.3 測試的坑：全域包索引 × 並行

第一版測試自己 `pack::set_index` 注入假索引，跑完復原——**隨機掛**。
`--test-threads=1` 跑得過，正是 CLAUDE.md §2.64.16 記的那個判準：
「測試隨機掛、每次不同那個 → 先想並行」。包索引是全域的，別的測試
同時在換。

**修法是讓載入只做一次**（不是把測試序列化）：包放進
`core/testdata/packs/lm_override.txt`（進版控、內容釘死），由
`compose` 測試共用的 `load()` 一次載好。

還有一個小坑：一開始用 `su3cl3`（你好）當測資，**撞到既有的測試**
（第 1746 行那個就在測 `su3cl3` → 你好）。改用包裡另一組
`ㄊㄧㄢˉㄑㄧˊㄅㄨˋ → 酟耆㧫`，三個生僻字，沒有別的測試在用。

### 2.78.4 驗收

| 項目 | 結果 |
|---|---|
| `cargo test -p ime-core` | 670 全過，**連跑 10 次穩定** |
| 漏斗 | 1291，通過率 90.2%，**跟基準比 +5**（那 5 筆是別的對話新增的 regression 測資） |
| 改寫硬指標 | `⚠10` 不變（既有，見 §2.74.12） |

**漏斗量不到這個修正**：它只載內建符號包（`testdata.rs` 寫死
`__不存在的資料夾__`），中文詞的包一個都沒載，`pack::zh_word` 永遠
回 `None`、`PACK_BONUS` 不會觸發。所以漏斗持平是**預期**的——
它證明的是「沒弄壞別的」，不是「修好了」。修好與否看單元測試與實測。
