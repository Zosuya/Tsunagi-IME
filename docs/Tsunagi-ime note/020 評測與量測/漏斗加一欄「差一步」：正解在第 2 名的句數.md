# 漏斗加一欄「差一步」：正解在第 2 名的句數

**判定不變**，只是把「還差多少」顯示出來。總計 +54——1264 句通過，
另外 54 句使用者按一次鍵就拿得到。

```text
節                    句數 │  ①不合法  ②切不出   ③排序   ④字錯 │  ✓通過    通過率    差一步 │  排名  改寫  錯字率
long                 60 │     0    18     5    11 │   26  43.3%    +14 │  1.38  18⚠1   4.7%
```

### 2.62.1 為什麼不放寬「通過」的判定

使用者原本的裁決是「正解有在第二就給過」，實際做的是 A 案（加統計欄）
而不是 B 案（改判定），理由問過之後確認：

- **改判定等於換刻度。** 總分會從 1264 跳到約 1287，但引擎沒有變好，
  而且以後**再也看不出第一名準不準**。`long` 那種「整句 20 段全對」
  的節，第一名的正確率才是使用者實際體驗。
- **第 2 名的代價不是零。** 要按選字鍵、看一眼、選一個。一句話裡有
  5 個地方要按，跟 0 個要按是兩種產品。
- **想要的資訊不改判定也拿得到**，就是這一欄。

### 2.62.2 兩種「差一步」都算

使用者付的代價一樣是「按一次鍵」，所以兩種都計入：

| 關 | 什麼意思 | 使用者怎麼救 |
|---|---|---|
| ③ 排序 | 正解的**切法**排第 2 | 按 Tab 換切法 |
| ④ 字錯 | 每個錯的格，正解都在**候選**第 2 名 | 在那幾格各按一次選字鍵 |

④ 要求**每一格都在第 2 名**——有任何一格排更後面就不算，那要按好幾次
方向鍵找。段數對不上（切法不同）時直接不算：那時「哪一格對應哪個字」
本身就不可信，硬比只會得到假的樂觀數字。

### 2.62.3 這一欄怎麼用

它是**優先序的參考**，不是成績。`+14` 的 `long` 跟 `+6` 的
`kana_fragment` 告訴你「這裡的排序只差臨門一腳」，而 `en_split` 的
`—`（16 句③排序全部排在第 3 名之後）代表那一節的問題比較深。
