### 「あまり乗り気じゃない」退步：V1 本身的代價，不是加的規則錯

`のりき`（乗り気）在 mozc 資料裡有兩筆同表記不同詞類：`lid=1931`（cost 5045）與
`lid=1851`（cost 6890）。V0（H1c）的去重規則只留全平假名或會活用的詞類，「乗り気」
不是活用語，所以只留總成本最低的那筆（`lid=1931`）。V1 把限制拿掉之後兩筆都留著。

問題不在「乗り気」自己身上，而在**它引入的 `lid=1851` 這個詞類，同時也是「力」
（從假名「りき」查到的候選之一）的詞類**。「りき」查到的「力」有四個同表記不同
詞類的變體（`lid` 1921／1922／1949／1851，cost 2114～4580）。V0 的去重規則對「力」
（非活用語）一樣只留一筆——按總成本排序後只留 `lid=1921`（cost 2114，最便宜）。
V1 拿掉限制之後，「力」的 `lid=1851` 那筆也留著。

整句轉換的 DP 在比較「乗り気」單獨一個詞 vs.「の」＋「力」兩個詞哪個總成本
（詞成本＋接續成本）低。用 `show_ime`／手動查表 `connection_single_column.txt`
量出來：

- 「乗り気」（`lid=1931`）：詞成本 5045 ＋ 句首接續 2121 ＋ 句尾接續 0 ＝ **7166**
- 「の」＋「力」：V0 只有 `力(lid=1921)` 可選，最便宜組合 ＝ **7565**（比 7166 貴，
  「乗り気」贏，V0 選對）
- 「の」＋「力」：V1 多了 `力(lid=1851)` 可選，這個 `lid` 剛好接在「の」（`lid=433`）
  後面的接續成本很低，最便宜組合掉到 **5820**（比 7166 便宜，DP 改選「の力」，
  V1 選錯）

也就是說：V1 讓「乗り気」多留一個候選詞類，但**真正翻盤的是「力」也多留了一個
剛好跟「の」接續很便宜的詞類**——兩個不相關的詞在資料裡各自多了一種詞性，
恰好组合出一條比正解更便宜的路。這是 mozc 資料＋我們的 Viterbi 模型本身的行為，
不是這次新加的規則造成的（V1 沒有針對「乗り気」或「力」寫任何特殊邏輯，純粹是
「同表記不同詞類一律保留」這條通用規則的副作用）。

**判斷：不修**。這類副作用理論上會發生在任何詞上（常見助詞／量詞 + 剛好接續便宜
的多詞類候選），要根治得動 Viterbi 的成本模型本身（例如額外的長度先驗，但
`維特比 DP ＋ 長度先驗` 已經在中文那邊被實測否決過，見〈總體策略〉），修法會動
到很多東西且沒把握不會有別的副作用。3 句退步換 90 句泛化裡 7 句修好（65 對
58），淨值是正的，接受這個代價。

**實測要注意的**：日本人名／作品名變英文（D-H3）、長句前段被事後改字（A3）。
（F-H1c、D-H4b 已裁決不採用，搭uber 那類、助詞緊接數字都不再是風險）
