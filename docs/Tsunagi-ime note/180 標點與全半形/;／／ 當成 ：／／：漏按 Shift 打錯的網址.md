# `;//` 當成 `://`：漏按 Shift 打錯的網址

使用者提議：偵測到 `//` 前面的 `;` 可以自動變換。

`:` 與 `;` 是**同一個實體鍵**（差在 Shift），而 `https://` 是極高頻的
輸入，漏按很自然。關鍵在於 **`;//` 這個組合在中文、日文、英文、程式碼
裡都沒有意義**——不是歧義，是純粹的打錯。

## 2.69.1 為什麼直接改，不是給候選

一開始的提案是「多給一個 `://` 候選讓使用者選」，沿用 [[標點選不到半形：一個裁決漏了反向，補了兩輪]] 的作法。
使用者指出 **`;//` 大概率就是網址**，那個提案太保守了：

沒有歧義的時候讓使用者「選」，等於浪費他一次按鍵去確認一件雙方都已經
知道的事。`...` → `…` 需要給候選是因為使用者可能真的要三個點；`;//`
沒有這種可能。

這跟輕聲別名（打本調也查得到輕聲詞）的精神一致：**使用者不必知道自己
打的鍵不標準，我們知道就好。**

## 2.69.2 回頭改寫算不算例外

`compose.rs` 有一條已定案的原則：「已經定案的標點不該再變⋯⋯回頭改寫的
代價更高」，而漏斗有硬指標盯著（改寫伸到游標 3 格外必須是 0）。

使用者的判斷是**這種改寫算例外**，成立：那條禁令防的是**引擎自己搖擺
不定**——使用者什麼都沒做錯，字卻因為引擎重新評估而跳動。`;//` 是
確定性的觸發條件、當下就完成、使用者看得懂為什麼，而且那一格本來就
還沒定案。

## 2.69.3 做法：格子層，不動切點也不動合併

spike 確認 `;//` 是**三個獨立的格子**（`;` `/` `/`），不會被合併成一格，
所以 `combo_variants`（`...` → `…` 那條路）走不通。

改在 `compose.rs` 的標點迴圈：那裡有 `i` 和完整的 `segs`，**看得到鄰居**。
偵測到「這格是 `;` 且後面兩格都是 `/`」就把預設文字換成 `:`。

判準要求後面**兩格都是 `/`**：`;/` 兩個字元還可能是別的東西（分號後面
接路徑），兩條斜線才是網址的樣子。

**位置在學習層之前**——使用者如果刻意選了 `;` 兩次，學習層仍然覆蓋得掉
這個猜測。使用者的意志優先。

實測：`https;//google.com` → `https://google.com`、`http;//a.com` →
`http://a.com`；而 `a;/b`（一條斜線）、`a;b`、`你好；` 都不動。
漏斗 1280 持平、541 個測試全過。
