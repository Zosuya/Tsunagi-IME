# 鎖定注音時打不出標點：一鍵兩用怎麼解

使用者回報「注音模式下沒辦法打標點」。查出來是**真實的鍵位衝突**，
不是漏寫。

## 2.19.1 根因

`,` `.` `;` `/` `-` 這五個鍵在大千配置上**就是注音符號** ㄝㄡㄤㄥㄦ。
鎖定模式的 `BopomofoInput::push` 邏輯是：音節緩衝吃得下就變注音符號；
吃不下的話，**只要是注音鍵就整個丟棄**（那段本來是為了擋「ㄈ 後面接ㄩ」
這種手滑）。兩條路都到不了標點。

反而 `!` `?` `[` 這些**不在注音配置上**的標點是打得出來的。

而且程式碼裡原本有一條測試把錯誤的假設寫死了：

> 「鎖定之後已經確定是注音，所以逗號就是ㄝ」

聽起來合理，實際後果就是五個最常用的標點全部消失。

## 2.19.2 判斷邏輯不必自己寫——它已經存在

`punct::is_punct` 早就在做這件事，而且判準正是**往後看聲調**：ㄝ 要成字
一定得再按聲調，沒有聲調就構不成字，那就是標點。自動模式打得出
`su3,` →「你，」就是靠它。

所以鎖定模式缺的不是邏輯，是**那個鍵在到達判斷之前就被音節緩衝吃掉**。

## 2.19.3 停在按鍵串，不要停在緩衝裡

第一版把待決的標點停在音節緩衝裡（顯示 ㄝ，下一鍵再決定）。**那是錯的**
——那時直接按 Enter 送出，`text()` 只看已收尾的按鍵，標點就憑空消失。
單元測試抓到的。

改成停在**按鍵串**裡：

- 空緩衝按下那五個鍵 → 直接進按鍵串，`is_punct` 判成標點，Enter 送得出去
- 下一鍵是聲調 → 把它從按鍵串取回緩衝，當注音重打一次（ㄝˋ 欸）

**只處理「緩衝是空的」那個情況**。緩衝打到一半時不做——那會讓標點插到
還沒打完的音節前面，符號順序就亂了，而那也不是使用者會遇到的情境。

## 2.19.4 設定

`behavior.lock_punct`：`auto`（預設，上面那套）或 `symbol`（一律當注音
符號，要打標點就切回自動模式）。設定頁「行為」分頁可改。

## 2.19.5 Ctrl+標點鍵：攔截的判準是「是標點 ＋ 被注音佔用」

使用者提到「一般輸入法都是用 Ctrl+對應鍵」。那條可行，而且**Ctrl 組合
到得了輸入法**——程式自己就是證據：`OnTestKeyDown` 是先看到那個鍵、
才決定「留給宿主」的（`ctrl_tap.key_down()` 在那道防線前面）。先前把
§2.14 講 Alt 的
結論套過來說「要先量」，那是過度謹慎。

攔截的判準**由規則導出，不寫死清單**（使用者提的）：

> 這個鍵印出來是標點符號，**而且**被注音佔用。

兩個條件缺一不可：

- 少了「是標點」→ 會吃掉 `Ctrl+C`／`V`／`Z`／`S`。大千把 26 個字母全用
  掉了，那些字母鍵**全都是注音鍵**。
- 少了「被注音佔用」→ 會攔到 `=` `[` `]` `'` 這些**本來就打得出來**的鍵，
  白白弄壞 `Ctrl+=`（縮放）、`Ctrl+[`（縮排）。

導出來剛好是 `,` `.` `;` `/` `-` 五個，也就是 `punct::is_ambiguous`。

**已知衝突**：鎖定注音時 `Ctrl+-`（瀏覽器縮小）與 `Ctrl+/`（編輯器註解）
會被接走。其他模式不受影響。會用到那兩個的人可以在設定裡關掉整條
（`behavior.ctrl_punct`）——這種「有明確代價的功能」要給得起關掉的餘地，
不然使用者只能整個不用鎖定注音。

實作上要注意兩件事：

- **兩個入口的判斷必須一模一樣**（`OnTestKeyDown` 與 `OnKeyDown`），
  分岔的話會出現「說要卻不處理」（按鍵消失）或「說不要卻處理了」
  （宿主收到兩份）。這是 §2.14
  點名過的坑。
- **明講的標點不能再被聲調取回去當注音**。自動判斷才有「多看一鍵」
  那條規則；使用者按了 Ctrl 就是表態了，不該再猜。`BopomofoInput`
  記一個 `forced_punct` 旗標擋掉，而且**要先讀再清**——先清的話檢查時
  永遠是 false。

順帶更正一個誤判：先前說「Ctrl 組合要先量 keyprobe 才知道到不到得了」，
那是把 §2.14 講 Alt
的結論套過來。**Ctrl 組合到得了**——程式自己就是證據：`OnTestKeyDown`
是先看到那個鍵、才決定「留給宿主」的（`ctrl_tap.key_down()` 在那道
防線前面）。
