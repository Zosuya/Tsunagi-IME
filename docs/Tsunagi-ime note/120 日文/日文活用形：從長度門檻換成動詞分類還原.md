# 日文活用形：從長度門檻換成動詞分類還原

排序有兩個地方在用**長度**猜「這串日文是不是活用形」，而長度只是
代理指標。換成照文法反推辭書形之後，漏斗 1149 → 1230，而且順手
解掉了選字層「活用形一律顯示假名」的老問題。

### 2.57.1 結果

| | 改前 | 改後 |
|---|---|---|
| 漏斗通過（測資同步從 1343 擴到 1416） | 1149 | **1230** |
| `japanese_verbs` 節 | 28／50 | **109／123** |
| 一段動詞涵蓋率（起きる・浴びる型） | 13% | **98%** |
| 誤觸（日文詞＋英文詞被誤認） | — | **0** |
| 五段例外稽核（40 個動詞） | 30 | **33** |
| 按鍵 p99 | 6.6ms | **7.9ms** |
| 單元測試 | 490 | **507** |

測資同期從 1343 擴到 1416（`japanese_verbs` 50 → 123 句），所以總分
不能直接比；`japanese_verbs` 那一節才是這次改動的真實效果。

### 2.57.2 病灶：兩處長度門檻

```rust
LONG_SENTENCE = 16   // has_dict_word 的豁免：單段且夠長就當作「有詞」
KANA_FRAGMENT = 12   // kana_bits：短且不在詞典的日文段算碎片
```

mozc 只收辭書形，所以活用形一律查不到詞典。這兩道門檻都是拿
「活用形通常很長」當代理指標，於是兩頭出錯：

```text
mitukaranakatta（見つからなかった，15 字元）
  日:mitukaranakatta         cov=15 has_dict=0  ← 正解，差一個字元沒豁免
  日:mitukara|英:nak|日:atta cov=15 has_dict=1  ← nak、atta 都在 en_50k

tabete（食べて，6 字元）
  日:tabete       kana_bits=1  ← 正解，被當成假名碎片罰
  英:tab | 日:ete kana_bits=0  ← `ete` 在詞典裡反而不罰，就贏了
```

`LONG_SENTENCE` 掃 6～16 全部同分到 13、14 掉 1、16 掉 8——那是平台
不是刀鋒，代表門檻早就沒在做原本的工作（擋 `sushitime` 那件事已經被
後來加的 `split_word`／`kana_bits` 接手）。

### 2.57.3 走過的死路：後綴表

第一版做的是**活用語尾表**——「語尾長得像活用形就算」。天花板很快就到：

| | 涵蓋率 | 誤觸 |
|---|---|---|
| 後綴表（77 條，語幹門檻 4） | 96%（測資裡的活用形） | 2 |
| 同一份表，測**一段動詞** | **13%** | — |
| 補上裸 `ta`／`te`／`de` 之後 | 54% | **6** |

一段動詞（起きる・浴びる）的語尾是光禿禿的 `ta`／`te`，補進表裡就
誤觸 `gakkousite`（学校 site）、`onegaidata`（お願い data）、
`sigotomode`（仕事 mode）——那正是引擎最該切開的「日文詞＋英文詞」。

**每加一條語尾就多一批誤觸，再加一道驗證去擋，補不完。** 根本原因是
拿結果反推原因：語尾長什麼樣是活用的**結果**，該問的是它是不是動詞。

### 2.57.4 做法：照文法反推辭書形

日文動詞只有三類，這是封閉的：

| 類別 | 辭書形 | 活用方式 |
|---|---|---|
| 一段 | `iru`／`eru` 結尾 | 去掉 `ru`，語幹直接接語尾 |
| 五段 | 其餘 `u` 結尾 | 語幹**音變**後接語尾 |
| 不規則 | `suru`／`kuru` 兩個 | 各自獨立 |

所以流程是**反推**：拿活用形去試各類的還原規則，還原出來的辭書形
查得到詞典就算數。

```text
okita       一段·過去 → 語幹 oki → 辭書形 okiru      ✓ 詞典有
            五段·過去 → 音便還原 → okitsu／okiku…    ✗ 都不在

gakkousite  一段·て形 → gakkousiru                   ✗
            五段·て形 → gakkousu／gakkousuru…        ✗ → 不是活用形
```

**詞典自己就是判準**，不必列舉語幹，也不必為每個動詞窮舉活用形——
詞典收「起きる」一條，起きた／起きて／起きない／起きられる／
起きさせる 全部涵蓋得到。實作在 `core/src/romaji/inflect.rs`，
四張規則表（音便還原、段母音、一段語尾、五段例外）加起來約 150 行。

### 2.57.5 實作中被實測推翻的七件事

這一節是這次的主要價值——每一條都是「看起來對、實測錯」。

**① 例外表不能拿來否決。** `iru`／`eru` 結尾卻是五段的動詞（帰る・
走る・切る）本來想用表擋掉一段還原，但 `kiru` 同時是「切る」（五段）
與「着る」（一段），羅馬字分不開。硬擋的話 `nete`（寝て）認不出來。
改成**兩條路都試**，任一條走得通就算數。

**② 「查得到詞典」不等於「是動詞」。** 詞典大得足以碰巧收錄還原
規則湊出來的假辭書形：

```text
arukimasu（歩きます）→ 一段規則剝 masu → arukiru →「アルキル」（alkyl）
hanashimasu（話します）→ hanashiru →「鼻汁」
asobimasu（遊びます）  → asobiru   →「アソビル」
```

改成要求有「漢字＋u 段送假名」的寫法（歩く・話す・入る）。實測 13 個
真假辭書形全部分對。

**③ 拗音音節換段要整個換。** `hanashi` 的 `shi`（し）是一個音節，只換
最後一個字母得到 `hanashu`，正解是 `hanasu`。`machi`→`matsu` 同理。

**④ 「行く」的例外不能當後綴。** `itta` 比 `tta` 長，會攔截
`sitta`（知った），還原成 `s`＋`iku`＝`siku`（敷く）。改成只在整串
就是它時才成立。

**⑤ 音便還原的順序＝可能性。** 促音便能還原成る／つ／う 三種，撥音便
能還原成む／ぶ／ぬ 三種，而且**同一個活用形往往有好幾個「查得到的
動詞」**：

```text
kaetta  → kaeru（帰る）✓  但 kaetsu 也在詞典裡
katta   → kau（買う）✓    但 karu（狩る）也是動詞
matta   → matsu（待つ）✓  但 mau（舞う）也是動詞
```

排序定案：る → つ → う（る 結尾的五段遠多於つ、う）、む → ぶ → ぬ。
再加一道「詞典首選就是動詞的優先」——`かう`→「買う」是動詞，
`かる`→「軽」是名詞。

**⑥ 複合動詞的語幹不能取「開頭連續的漢字」。** 「話しかける」是
話→し→かける，漢字不連續，那樣取只得到「話」，組出「話けられた」。
改成「表記去掉尾端送假名」。

**⑦ 送假名的長短兩種寫法。** 這是最隱蔽的一個：

```text
起きる  送假名「きる」開頭「き」（い段）→ 一段 ✓
交じる  送假名「じる」開頭「じ」（い段）→ 判成一段 ✗（實際是五段）
```

「交じる」和「交る」是**同一個五段動詞的兩種正書法**，字面上跟一段
一模一樣。判準改成**同一個漢字語幹有沒有更短的送假名寫法**——五段的
活用語尾只有最後一個音在變（交る→交った），送假名可以只寫「る」；
一段的語幹尾音固定（起きる→起きた），省不掉。實測 まじる・おわる
（五段）長短並存，おきる・たべる・かんがえる・しらべる（一段）
一個都沒有。

### 2.57.6 選字層：把漢字組出來

排序修好之後，選字層還有一個老問題：**活用形一律顯示假名**。打
「おきた」出來就是「おきた」，「よんだ」還被 Viterbi 硬切成「4」＋「だ」。

先試過調 `CONFIDENT_COST`（敢不敢預設顯示漢字的門檻），走不通：
掃 6500～11000，7500～8300 是平台（+3）、8600 崩（-12），而且**賺的
不是正解**——放寬到 8000 之後「おきた」變成「沖田」、「おきて」變成
「掟」。因為「起きた」在詞典裡根本不存在，門檻放得再寬也只會撈到
同音的姓氏。

改成**用還原出來的辭書形組漢字**：

```text
おきた → 還原 おきる →「起きる」→ 語幹「起」＋「きた」→ 起きた
のんだ → 還原 のむ  →「飲む」  → 語幹「飲」＋「んだ」→ 飲んだ
```

接的位置有兩處：`best_japanese` 查不到時試組，以及**分詞之前先攔**
（`よんだ` 會被 Viterbi 切成兩個詞，不攔就到不了選字）。

### 2.57.7 兩條使用者裁決的規則

**「平假名該贏的時候會自己贏」不能過頭。** `ある`／`わかる` 的日常
寫法就是假名，硬轉成「有ります」「分かりました」實測 `cutpoint` 節
賠 14 句。判準是辭書形的**詞典首選**本來就是假名。

但**只看平假名**——片假名的首選是外來語名詞碰巧同音（`ほてる`→
「ホテル」、`まいる`→「マイル」），一起擋掉的話「火照った」「参った」
完全選不到。

**有歧義的顯示不算錯，但候選一定要有**（使用者 2026-09-07 裁決）。
所以「習慣寫假名」只擋**顯示**，不擋候選：

| 輸入 | 顯示 | 候選裡有 |
|---|---|---|
| `arimasu` | あります | 有ります、在ります |
| `itta` | 言った | **行った**、逝った、往った |
| `tetta` | てった | **照った**、輝った |

同理，同一個活用形對應好幾個動詞時**全部都要在候選裡**——`よんだ` 是
読んだ／詠んだ、`とった` 是 取った／撮った／採った。只給一個的話
其餘的使用者選不回來。

一段與五段的活用形則**不能互串**（`kaetta` 不該給「変えった」、
`kaeta` 不該給「帰た」）。這不是把字藏起來——想打「変えた」就輸入
`kaeta`，兩種活用形各有各的按鍵。實測稽核 かえる／きる／とる／よむ／
おわる／しる 六個讀音共 55 個動詞，**全部打得出來，一個都沒漏**。

### 2.57.8 效能：熱路徑上不能直接呼叫

`rank.rs` 有兩處呼叫 `is_inflected`，而排序是最熱的路徑——59 鍵的
日文長句有 400 個候選、1472 個段落，每鍵都要重算。實測退步 8 倍：

| | 改前 | 直接呼叫 | 加快取後 |
|---|---|---|---|
| p99 | 6.6ms | **24.3ms** | **7.9ms** |
| 最慢 | 7.4ms | **58.4ms** | **13.4ms** |
| 超一幀預算的案例 | 0 | 2 | **0** |

兩個修法：**併進既有的 `Memo` 快取**（`SegFacts` 加 `inflected` 欄位，
同一段只算一次，非日文段連呼叫都省），以及**便宜的前置排除**（活用形
與辭書形的尾巴一定是母音，子音結尾直接回 `None`）。

`漢字候選` 裡那張「長短並存」的 `HashSet` 則量不出成本——它在選字
路徑，每鍵只跑幾次。**熱路徑與冷路徑的成本差三個數量級，優化前先確認
自己在哪一條上。**

### 2.57.9 這次學到的

- **代理指標會兩頭出錯。** 長度、語尾這些都是「活用形通常長這樣」的
  相關性，不是定義。照文法走雖然要多寫規則表，但每一條都說得出理由，
  而且不會有補不完的例外。
- **同一個病灶常常不只一處。** `LONG_SENTENCE` 修好之後，`KANA_FRAGMENT`
  是同一種病（用長度猜活用形），只是短的那一端。
- **詞典夠大就會有假陽性。** 74 萬個讀音裡，還原規則湊出來的假辭書形
  幾乎都「查得到」。驗證要問得更精確（是不是動詞），不能只問存不存在。
- **正確性與可及性是兩件事。** 顯示選錯字還有救（按選字鍵），候選漏了
  才是真的打不出來。這次一度把「不轉漢字」做在候選層，等於把字藏起來。
