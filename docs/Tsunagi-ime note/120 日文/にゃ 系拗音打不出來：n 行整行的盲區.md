# `にゃ` 系拗音打不出來：n 行整行的盲區

**§2.75 的 spike 順帶翻出來的既有缺陷**，跟擴充包編輯器無關，另案處理。
**已修，使用者實測通過**（2026-09-11）。

### 2.76.1 症狀

`にゃ`／`にゅ`／`にょ` 打不出來，實測：

```text
      nya -> None
     anya -> None
    annya -> Some("あんや")   ← 誤配，不是「あにゃ」
   annnya -> None
   kinyou -> None
konnnyaku -> None
```

受影響的詞：`にゃんこ`、`こんにゃく`、`メニュー`、`ニュース`、
`にょろにょろ`⋯⋯ mozc 詞庫 5000 筆抽樣裡有 22 筆（0.4%）踩到。

### 2.76.2 病因：合法性閘門，不是切分順序

> **最初的診斷是錯的**，這裡保留更正的經過——`split_moras` 的貪心
> 順序沒有問題。

第一版寫的是「切 mora 時撥音的分支先跑，`nya` 被切成 `ん`+`や`，
修法是讓長的優先」。實際去看 `romaji/mod.rs` 的 `split_moras`，
**它早就是由長到短**（`for len in (1..=4).rev()`），註解還明講必須
如此，否則 `kyo` 會先被切成 `ky`+`o`。所以補在切分那一層是修不好的。

真正的病灶在**更前面的合法性閘門**，`romaji/mora.rs` 的 `check_body`：

```rust
// 撥音：單獨的 n 或 nn
if first == 'n' && i == 1 {
    return Validity::Invalid;   // ← 無條件
}
// 拗音 `y`：⋯⋯          ← 排在後面，輪不到
if x == 'y' { ... }
```

**「`n` 開頭、第二字元不是母音 → 一律非法」擋在拗音規則前面。**
`nya` 的第二字元是 `y` 不是母音，於是在還沒輪到拗音判斷之前就被殺
掉了。`kana.rs` 的 mora 表裡明明有 `("nya","にゃ")`，轉換那層是好的
——只是永遠走不到。

`annya` 那個誤配也是同一回事：`nya` 不合法，切分退而求其次拿
`nn`+`ya`，就成了「あんや」。

**教訓**：症狀出現在「切出來的結果」，病灶卻在「合法性判斷」。
兩層之間隔著一個貪心迴圈，讀症狀很容易把責任推給看得見的那一層。

### 2.76.3 為什麼測試沒抓到：n 行是整行的盲區

`mora.rs` 的 `拗音` 測試列了
`kya/kyu/kyo/sha/cha/gya/bya/pya/jya`——**獨缺 n 行**。

而且不只拗音。修好之後跑既有的 `表對得上引擎`（那個窮舉三字元、
比對「引擎判合法但表查不到」的一致性測試）立刻紅了：

```text
引擎說合法但表查不到的 2 個：["nye", "nyi"]
```

別的行都收滿五個母音（`kyi`/`kye`、`myi`/`mye` 都在表裡），
**只有 n 行連 `nye`／`nyi` 也一起漏了**。跟拗音那個缺陷同一個根因：
n 行整行被遺忘。表因此從 224 條變成 226 條。

> 這個一致性測試很值錢——它不是靠人想到要測什麼，而是窮舉全部組合
> 去逼出「引擎與表不同步」。修 A 的時候它替我抓出了沒注意到的 B。

### 2.76.4 修法：放行給拗音規則，不是特例硬編

一處，`check_body` 的撥音那條加一個例外：

```rust
if first == 'n' && i == 1 && x != 'y' {
    return Validity::Invalid;
}
```

**放行的是「落到下面的拗音規則去判斷」，不是「n 開頭都合法」**——
所以 `ny` 沒接母音（`ny`、`nyk`）、或 `n` 接別的子音（`nk`、`nt`）
仍然非法，由既有規則把關，不必另寫長度與母音的檢查。

撥音那一族**完全不受影響**，原因跟原本推測的不同：文件本來擔心
`kinnyoubi`（金曜日）會被切成 `ki`+`nnyo`，推論是「`nnyo` 不在表裡
所以應該安全」。實際上 `nn` 早在 `check()` 的更前面就被判定為撥音並
直接回傳，**根本走不到我改的這一段**——兩者井水不犯河水。

另外確認：`mora.rs` 檔頭寫明「175 條 mora 沒有 4 字母的」，所以
`nnya` 本來就不該是一個 mora，`nn`+`ya` 的切法是對的，不需要動。

### 2.76.5 驗收

| 項目 | 結果 |
|---|---|
| **使用者實測打字** | **通過**（2026-09-11，重開宿主行程後） |
| `cargo test -p ime-core` | 673 全過，**連跑 10 次穩定** |
| 漏斗 | **1286 → 1291（+5）**，通過率 90.2% 持平 |
| 改寫硬指標 | `⚠10` 不變 |
| 各節 | 全部持平，無退步 |

**實測那一列才是結案的依據**。這個缺陷從頭到尾是引擎層的
（合法性判斷），單元測試與漏斗都涵蓋得到，但依 CLAUDE.md 的規矩，
組字區真的打出 `にゃ` 才算數——測試通過只代表引擎算對了，不代表
使用者按下去看得到。

測試補在兩層：`mora.rs` 的 `拗音` 那組補進 n 行、新增
`n_開頭只有拗音是例外`（把「放行的界線」釘死，含 `ny`／`nyk`／`nk`
／`nnya` 這些**仍該非法**的反例）；`kana.rs` 新增 `n_行拗音`。
`撥音()` 那組原本就有 `kinnyoubi`，替我守住反向。

`regression` 節加 6 筆（按鍵用 `mkkeys --sent` 產）：

```text
蒟蒻        konnnyaku    ← 刻意留紅，見下
こんにゃく   konnnyaku
にゃんこ     nyannko
メニュー     menyu-
ニュース     nyu-su
牛乳        gyuunyuu     ← 拗音接撥音，跟 konnnyaku 是相反方向
```

**`蒟蒻` 那筆刻意留紅**：實際輸出 `こんにゃく`——假名本身已經對了，
沒轉成漢字是選字層的事，不是這次修的合法性層。依「測資反映需求，
不反映目前的能力」留著。
