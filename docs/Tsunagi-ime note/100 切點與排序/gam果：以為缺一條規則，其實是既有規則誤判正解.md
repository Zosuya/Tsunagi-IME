# `gam果`：以為缺一條規則，其實是既有規則誤判正解

第二輪 20 句混打回歸抓到的：`這款game我玩了兩年` 打成「這款**gam果**完了兩年」。

```text
正解  英:game | 注:ji3（我）
實得  英:gam  | 注:eji3（果）   ← `e` 被注音段吃走了
```

### 2.43.1 第一個假設：缺了 `fewer_stolen` 的鏡像

`rank.rs` 有 `fewer_stolen` 罰「**英文段偷走注音音節的開頭**」
（`file`＋`d9` → `filed`＋`9`），但反方向沒人管。所以先做了鏡像的
`fewer_eaten`——把注音段的第一個字元還給英文段，如果合起來是**更常用
的**詞、而且注音段剩下的仍合法，就罰。

實測：`gam果` 確實從第 1 名掉到第 2 名。**但第一名變成 `がme我`**，
正解還是排第 3。假設只對了一半。

### 2.43.2 分數印出來才看到真相

`repl` 當時看不到分數，加了 `:s` 開關之後一切清楚：

```text
1. 日:ga | 英:me | 注:ji3    split_word=1
2. 英:gam | 注:eji3          eaten=1      ← 新規則有罰到
3. 英:game | 注:ji3          stolen=1     ← 正解被既有規則罰了
```

**根因不是缺一條規則，是 `fewer_stolen` 誤判了正解。**它以為 `game`
偷走了 `eji3` 的 `e`——因為把 `e` 還回去之後 `eji3` 是合法的ㄍㄨㄛˇ，
而剩下的 `gam` **剛好也在 en_50k 裡**（排 40216）。舊判準
（`head.is_empty() || is_common_word(head)`）到這裡就成立了。

而 `stolen`（第 6 欄）比 `split_word`（第 8 欄）先比，所以正解被壓到
`がme我` 後面。

### 2.43.3 修法：`stole_head` 也要「更常用」

判準加一條：剩下的頭必須**比原本整段更常用**（排名數字更小）。

```text
the (第 1 名)    → they (第 61 名)     ← the 更常用，是偷    ✓ 照樣抓到
file(第 1194 名) → filed(第 9613 名)   ← file 更常用，是偷   ✓ 照樣抓到
gam (第 40216)   → game(第 456 名)     ← gam 冷僻兩個數量級  ✗ 不是偷
```

「更常用」表達的是：如果拿掉最後一個字母之後那個詞**反而更冷僻**，
代表完整的那個詞本來就是使用者要的，不是多吃了一個字元。

### 2.43.4 `fewer_eaten` 被證明不需要，整條拿掉

修完 `stole_head` 之後回頭量：**開不開 `fewer_eaten`，三支計分器一個
數字都不差**。目標案例不靠它也是第一名（`game|ji3` 的 covered=4 本來
就贏 `gam|eji3` 的 3）。

照專案的慣例——不動數字的規則就是不需要的規則（[[Phase 2 完成：累加式切法與排序]] 已經砍過三條）
——整條移除。**留著一條沒有量測支撐的規則在排序核心裡是負債**。

### 2.43.6 順手修掉一個熱路徑的配置

加了排名比較之後 p99 從 10.9ms 變 **12.6ms**（穩定重現三次，不是雜訊）。
原因是 `english::is_word`／`rank`／`is_common_word` **每次呼叫都
`to_ascii_lowercase()` 配置一個 String**，而它們在切點引擎的熱路徑上
——每個候選的每一對相鄰段落都要問。

按鍵串本來就是小寫，加了一個免配置的快路徑（`key()` 回 `Cow`，
沒有大寫就直接借用）。p99 回到 **10.1～10.6ms**，比改動前還快。

### 2.43.7 三個可以帶走的教訓

- **查排序問題一定要看分數**，不要看顯示文字。`repl` 的 `:s` 就是這次
  加的；沒有它會一路往「缺規則」的方向做下去。
- **顯示文字會騙人**：排序看的是原始候選，顯示看的是 `normalize` 之後
  的。`repl` 現在兩者不同時會一併印出來。
- **先確認既有規則有沒有誤判，再考慮加新規則。**這次的第一個假設
  （缺鏡像規則）方向錯了，做出來的東西最後整條刪掉。
