# 「（中）」那一列不是純中文

### 症狀

打 `這種情況就要用切法的`，切法選單第 4 列標著「（中）」，內容卻是

```text
（中）這種fu/6況る噢藥用切法的
```

——混著日文段，中間還有一段連字都轉不出來。而**正確的純中文讀法就在
同一份選單的第 2 列**。

### 根因：一整段中文拿 0 分

「（中）」代表挑的是「注音涵蓋字數最多的那一種切法」，涵蓋分數由
`rank::covered_by` 算。它問的是 `claimed`——**「這一整段是不是一個詞」**。

一整句中文當然不是一個詞，所以：

| 切法 | 分數 |
|---|---|
| `注:這種情況就要用切法的`（一整段） | **0** |
| `注:這種` ＋ `日:る` ＋ `注:噢藥用切法的`（切碎的） | 7 |

被切碎、每小塊剛好是個詞的那一種反而贏。`rank.rs` 早就為這件事寫了
`claimed_chars`（逐詞最長匹配、加總命中字數），但 `covered_by` 一直
用的是舊的 `claimed`。

### 兩處都改

1. **`covered_by` 改用 `claimed_chars`**——它只被語言代表這一段用到，
   不進排序，所以三支計分器一個數字都不會動。
2. **先找「整串都是這個語言」的那一種**。「（中）」這個記號答應使用者
   的就是「整句當中文唸」，只要那種讀法存在它就是答案，不必再跟涵蓋
   分數比。原本這條只是「涵蓋全是 0」時的墊底（單音節那個情境）。

改完抽驗，既有的判斷都沒退步：

```text
check u vu84  →  （中）check 一下     ← 沒有純中文讀法，退回涵蓋最多的
su3cl3        →  （中）你好
sushi         →  （日）寿司
```
