# 切點排序：點名式懲罰先於計數式

**只重排 `Score` 的欄位順序，一條規則沒加沒減。**漏斗
1264→**1277**（+13），前 2 名 1318→**1340**（+22），**六節進步、
零節退步**。

這個改動來自一支 2026-09-06 的舊分支（`claude/cutting-point-engine-improvements`），
當時的基準比現在舊 73 個 commit，而這段期間 `rank.rs` 動很大（活用形
判斷、`Memo` 快取）。所以不是直接 cherry-pick，是**照它的診斷在現在的
master 上重做一次再複量**。

### 2.65.1 兩個病因

`Score` 用 `derive(Ord)` 依欄位順序逐項比較，**欄位順序就是排序優先權**。

**病因一：計數式壓過點名式。**`stolen`／`split_word` 是點名式的——
指得出「哪個字被誰偷走」「哪個詞被攔腰切開」，有具體證據。
`passthrough` 是計數式的，只數殘渣有幾個字元。計數式排前面時，
字元數會壓過具體證據：

```text
英:AP | 英:It    殘渣 2 個  ← 贏
英:API           殘渣 3 個  ← 正解，卻輸在數量
```

**病因二：`same_lang` 在罰「詞典沒收錄」。**同語言的兩段之間有沒有
切點，對最後輸出根本沒有影響（`normalize` 會黏回去），所以它是所有
懲罰裡證據最弱的一條。而它排在前面時會踩到要命的情況：**詞典沒收
整個詞的時候，正解只能以拆開的樣子活下來**——`logout` 不在 en_50k
裡，整段那條在 `prune` 就死了，正解只剩 `英:log | 英:out`，卻正好被
這一欄扣分。

這正是 `en_vowel` 一直上不去的病因（`logout`／`footer`／`config`
這種**不在 en_50k 裡**的技術詞）。

### 2.65.2 改法與結果

`stolen`／`split_word` 提到 `passthrough` 前，`same_lang` 退到
`kana_bits` 後。改動 22 行，全在欄位順序。

| 節 | 句數 | 通過（前→後） | 前 2 名（前→後） |
|---|---|---|---|
| `en_vowel` | 100 | 83 → 84 | 87 → **95**（+8） |
| `long` | 60 | 26 → **32**（+6） | 40 → **47**（+7） |
| `en_split` | 50 | 46 → **49**（+3） | 46 → **50**（全中） |
| `cutpoint` | 314 | 311 → 312 | 311 → 312 |
| `holdout` | 100 | 85 → 86 | 91 → 92 |
| `number` | 101 | 79 → 80 | 88 → 89 |
| **總計** | 1416 | 1264 → **1277** | 1318 → **1340** |

其餘 11 節持平。附帶指標全部同向或持平：總排名 1.16、總錯字率 2.9%、
`long` 切不出 18→**13**、`en_vowel` 排名 1.71→**1.18**、`en_split`
排名 1.40→**1.02**。改寫的 `⚠`（伸到游標 3 格外）維持 **2**，沒有惡化。

`en_vowel` 的第 1 名只 +1 但前 2 名 +8——**還有 7 句擠到第 2 名**，
離修好只差臨門一腳。`long` 的 +6 一半來自「切不出來」變少，也就是
正解本來根本沒被生出來。

### 2.65.3 兩件要記住的事

**`fewer_same_lang` 不能整個拿掉**，只能退到後面。它擋的是
`英:ma | 英:kes | 注:u3` 這種拿兩個短詞硬湊 `makes` 的切法
（原分支實測：整個拿掉第 1 名會掉 11 句）。

**效能沒動。**排序是熱路徑，改完特地還原程式碼再量一次對照：
p99 8.0ms→7.9ms、記憶體 54MB→54MB，差異是量測雜訊。517 個單元
測試全過。
