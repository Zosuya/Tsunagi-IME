# `youtube` 打成ようつべ：門檻救不了，選字層才行

跟 [[詞典沒收的英文縮寫：切法根本沒生出來]] 同一天回報。`youtubeao6g4`（youtube 沒事）第一名是
「ようつべ沒事」，而「youtube沒事」在選單裡排第 17／26。

### 2.40.1 第一眼的判斷是錯的

看到「排第 17 名」會直覺歸類成排序問題。**不是。** 把候選連語言標籤
一起倒出來（`repl`）才看得清楚：

```text
第 1 名   日:youtube | 注:ao6g4        ← ようつべ沒事
第 16 名  英:you | 英:tube | 注:ao6g4  ← 顯示成「youtube沒事」
```

第 16 名那個看起來像 `英:youtube`，其實是 `you`＋`tube` 兩段被
`normalize` 黏起來的假象。它在 `fewer_same_lang`（第 4 優先的欄位）
就先扣分了——同語言相鄰不該有切點。

**「`英:youtube` 一整段」這個候選根本不存在**。跟 [[詞典沒收的英文縮寫：切法根本沒生出來]] 一樣是生成
階段的問題，只是死在不同的地方。

### 2.40.2 死在 `lang_of` 的門檻

`incremental.rs` 的 `lang_of`：`youtube` 是合法羅馬字（ようつべ），
而 mozc **真的收了這個詞**，所以「只有英文詞典收 → 判英文」不成立。
最後一道關卡是 `is_top_word`，門檻 `TOP_WORD_RANK = 5000`——
**`youtube` 排 10160**。

### 2.40.3 「把門檻拉高」這條路是死的

`english.rs` 的註解記著「5000 之後是一片高原，20000 一樣是 96.4 分」，
看起來拉到 20000 就解決了。**那會炸掉日文。**

| 詞 | en_50k 排名 |
|---|---|
| sake | 1017 |
| samurai | 5093 |
| **sushi** | **7210** |
| **karaoke** | **9015** |
| **youtube** | **10160** |
| tofu | 12455 |
| ramen | 14522 |
| kimono | 15889 |
| manga | 21592 |

`sushi` 和 `karaoke` 都排在 `youtube` 前面。門檻只要高到能救
`youtube`，`sushi` 就會變成英文原樣而不是「すし」——那是 `prune`
註解裡拿來當招牌範例的案例。

**英文詞頻排名分不開「英文詞」與「用羅馬字打的日文外來語」**，
這兩群在 1000～35000 之間完全交錯。不要再試調這個門檻。

### 2.40.4 做法：§2.24 的鏡像

那一格**本來就可以選字**，只是候選全是日文寫法：

```text
#1  youtube    ようつべ   ヨウツベ ようつべ ﾖｳﾂﾍﾞ      ← 沒有英文原文
```

§2.24 解 `ii`→いい 用的就是這招，方向相反而已。鏡像過來：
**日文段若英文詞典也收得到這串按鍵，把英文原文補在候選最後**。

- **補在最後、不動前面**：預設輸出不變（第一名仍是日文），三支計分器
  因此一個數字都沒動——實測確認 570/570・560/570・551/570、
  677/720 錯字率 2.5%、測資 0 對不上，全部對齊。
- **學習那條路本來就通**：日文格的學習鍵是**假名**
  （`learn::record_run`），查詢端 `best_kana_word` 也用假名，
  選過 `LEARNED` 次之後預設就會換成英文原文，不必另外接線。
- **用 `is_common_word` 不是 `is_word`**：`en_50k` 收了大量冷僻的
  兩字母詞，用 `is_word` 的話每個助詞格都會冒出雜訊（`wo`→を 那一格
  多出「wo」）。`is_common_word` 對兩字母有頻率門檻（≥10 萬）正好濾掉
  這批，三字母以上一律放行，`youtube`／`sushi` 不受影響。

### 2.40.5 教訓

**回報「打不出來」時，第一件事是分辨切法有沒有生出來**，而且要看
**帶語言標籤**的候選——`show_ime` 的顯示文字會讓 `英:you|英:tube`
看起來像 `英:youtube`，光看文字會把生成問題誤判成排序問題。

`repl` 才印得出語言標籤，`show_ime` 的 `-m` 才看得到第 17 名。
這兩件工具上的小事，是這次沒有走錯方向的原因。
