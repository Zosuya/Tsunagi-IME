# 發布前的授權盤點：資料比程式碼難

**結論先講**：資料授權不擋發布。二進位詞庫可以打包，義務是**標示出處**，
不是不能散布。程式碼授權可以自由選（沒有用到任何 copyleft 的程式碼）。

### 程式碼：我們不受任何人約束

參考過新酷音的做法（分層字典、學習曲線、Tab 的職責），但**沒有用到
它的任何一行程式碼**。參考設計不構成衍生作品，所以它的 LGPL／GPL
不及於我們。

新酷音的分法仍值得記著，因為切點跟我們的架構一樣：

| 專案 | 對應我們的 | 授權 |
|---|---|---|
| libchewing（引擎） | `core/` | LGPL-2.1-or-later |
| windows-chewing-tsf（TSF 層） | `platform/windows/` | GPL-3.0-or-later（舊版 LGPL-2.1） |

**他們分兩層是因為 libchewing 是要給別人連結的函式庫**——LGPL 的重點
正是「你可以連結我，但不必開源你自己」。我們的 `core/` 目前沒有這個
需求，將來要開放給別人連結才需要重新考慮。

### 決定：GPL-3.0-or-later（2026-09-02 使用者裁決）

問過「有沒有更嚴格的」，答案是**在開源這條線上 GPL-3 已經是實用範圍的
上限**：

| 選項 | 更嚴在哪 | 為什麼不選 |
|---|---|---|
| AGPL-3.0 | 補上「網路服務」漏洞 | 輸入法是桌面軟體，那條款**永遠不會觸發**；換來的是企業普遍禁用 |
| SSPL / BUSL / CC BY-NC | 限制更廣或禁止商業使用 | **OSI 不認可**，等於放棄免費 code signing 資格與開源身分 |

選 GPL-3 的三個檢查都過：跟打包的資料相容（BSD-3 與 MIT 可單向納入）、
不會傳染給宿主程式（是**系統透過 COM 載入我們**，不是我們連結宿主；
`windows-chewing-tsf` 本身就是 GPL-3）、SignPath 認 OSI 授權。

**額外的好處**：GPL-3 保留了「將來借用新酷音程式碼」的選項。libchewing
是 LGPL-2.1-or-later（可單向升級成 GPL-3）、windows-chewing-tsf 本身就是
GPL-3。選 MIT 就永遠不能納入他們的程式碼，除非整個專案改授權。

### 配套：程式碼與資料分開標示

**資料檔不宣告成 GPL-3。** GPL-3 要求接收者能自由修改、再散布，而
`dict_zh.bin` 背後有教育部字頻（ND）的影子——把它一併宣告成 GPL-3
等於替它加上原始授權沒有給的權利，那個宣告站不住。

```text
程式碼（core/、platform/、settings/）：GPL-3.0-or-later
資料檔（*.bin、en_50k.txt）        ：各依原始來源，見 CREDITS.md
```

這不是為了規避什麼，就是誠實標示，順便滿足 BY 的標示出處義務。
`CREDITS.md` 已建立（2026-09-02）。

**授權在實務上不可逆**——一旦有外部貢獻者，改授權要每個人同意。現在
還沒公開、沒有貢獻者，是最容易決定的時候。

### 資料：五個來源，只有一個受限

`data/download.ps1` 的檔頭有 2026-08-23 的逐項查證，這裡補上發布角度
的盤點：

| 資料 | 授權 | 能不能打包散布 |
|---|---|---|
| McBopomofo 映射表 | MIT | 可以 |
| mozc 日文辭典＋接續矩陣 | BSD-3-Clause | 可以 |
| FrequencyWords（中英詞頻） | MIT | 可以 |
| 國教院詞頻 | 開放資料（可改作、可再授權） | 可以，標示出處 |
| **教育部字頻** | **CC BY-ND 3.0 TW** | **可以，但不得散布改作版本** |

**體積大的四份全部沒有限制**，受限的那份本身只是一個小文字檔。

### CC BY-ND 到底禁止什麼

兩件事查證過，結論都比直覺寬鬆：

**一、格式轉換不算改作。** CC 自己的說明白紙黑字：「僅改變格式不算是
創作衍生作品」。所以 `dict_zh.bin`／`dict_ja.bin` 這種二進位化**完全
沒問題**——同樣的字、同樣的數字，只是換個存法。3.0 的措辭不同（「為
了在其他媒介與格式呈現，可以做技術上必要的修改」）但結論一樣。

**二、ND 禁止的是「改作」，不是「編輯」。** CC 台灣的林誠夏在
`cctw-discussion` 的解釋：

| 關係 | 判準 | ND 下 |
|---|---|---|
| 編輯 | 保持原內容完整、忠實呈現、清楚區分各來源歸屬 | **允許** |
| 改作 | 增刪修改原著作的內容細節 | 禁止 |

組合多個資料源、只取部分內容都合規，關鍵是**標示各來源的歸屬並區分
開來**。

### `char_freq_by_reading.txt` 落在哪一邊

那張表（§2.16）拿教育部字頻乘上 McBopomofo 的讀音佔比，算出「這個字念這個音
的佔比」。它**不是格式轉換**，所以第一條救不了它。

但按第二條的框架，它也**不是改作**：我們沒有增刪修改教育部字頻的任何
一個數字，原表還是原表；產出的表**還原不回原表**（是相乘後的結果），
談不上散布原著作的改作版本。

界線要說清楚：那個討論串講的情境是「辭典並列多來源解釋」，我們是「用
資料做統計計算」，不是一對一對應。但兩者都落在「沒有修改原著作內容
細節」這一側。**不是法律意見**，是依 CC 台灣的公開解釋做的實務判斷。

**保守的退路成本也很低**：`dict.rs` 的 `load_reading_share` 在檔案缺席
時直接回空表，查不到的字視為不打折、行為不變（註解自己寫著這件事）。
所以真要保守，讓安裝程式在本機產生、或乾脆不給，都不會壞——代價只是
多音字排序退回「只看字頻」。

### 我們跟新酷音的處境不同

| | 新酷音 | 我們 |
|---|---|---|
| 資料 | 一份自有詞庫（libchewing-data，LGPL） | **五個外部來源** |
| 進版控 | 是，隨程式碼散布 | 否，各自下載 |
| 改作自由 | 完全自由 | 四個自由，一個限制散布改作版本 |

他們的源頭是 libtabe（BSD），社群接手後花力氣整理成 LGPL，才換到今天
的自由。**我們是站在別人的資料上**——代價是要接受各來源的條件，換到的
是一開始就有中英日三語的高品質字詞頻（新酷音沒有日文那一套，也沒有
教育部字頻，我們在同音字排序上贏他們就是那份表的功勞）。

**不需要為了授權重建一份自有詞庫。** 盤點下來真正受限的只有一份，而且
只卡在一個小衍生檔。

### 發布時一定要做的一件事

**標示出處。** BY 那一半是所有 CC 授權的共同義務，國教院的開放資料也
明文要求。README、安裝程式、設定頁的「關於」三處擇一或全做，把五個
來源與各自的授權列清楚。成本是零，而且本來就該做。
