# 自動更新：只做「檢查並提示」，不做背景替換

> 🔨 **2026-09-14 實作完**（`settings/src/update.rs`），單元測試過、Mac 上真的連過一次 GitHub。
> **還沒在設定頁實際看過畫面**，Windows 上也還沒跑（那邊要確認 curl 不會閃黑色視窗）。
> 實作與下面「實作前要確認的」四點的答案見文末 [[#實作（2026-09-14）]]。

使用者裁決：**設定頁查 GitHub Releases 的版本號、有新版就提示並給下載
連結**；背景自動下載替換 DLL **不做**。

### 兩個理由，第二個更硬

**一、DLL 換不掉。** 這是 `build-ime.ps1` 存在的同一堵牆——Windows 不
允許覆寫正在被載入的 DLL，而檔案總管永遠挖著它。就算背景換成功了，
**每個已經開著的程式跑的還是舊版**，使用者會處在「記事本是新版、瀏覽器
是舊版」的混亂狀態。詞庫也一樣：`gen_dict_*` 的原子寫入讓換檔本身安全
（舊映射活到行程結束），但**已經在跑的行程還是讀舊的**。

**二、沒簽章之前，自動更新是攻擊面。** 那等於開一條「可以把任意 DLL
送進使用者每一個程式的行程」的通道——而輸入法看得到使用者打的每一個
字。通道被劫持（DNS、中間人、帳號被盜）的後果比一般軟體嚴重一級。
防守要靠下載後驗簽，而簽章還沒做。

### 做什麼

| 行為 | 做不做 |
|---|---|
| 設定頁查 Releases 版本號，有新版就提示 | ✅ |
| 給下載連結，使用者自己執行安裝程式 | ✅ |
| 背景下載並替換 DLL | ❌ |

**只在設定頁查，不在輸入法啟動時查。** 後者會讓每一個宿主行程各發一次
請求（檔案總管、瀏覽器、編輯器…），既浪費也可疑。設定頁是獨立執行檔、
由使用者主動開啟，那裡查一次剛好。

### 實作前要確認的（尚未 spike）

- **GitHub API 的細節**：未認證有 60 次/小時/IP 的限流，而且**不帶
  User-Agent 會直接 403**。要實測。
- **版本規則**：目前 `Cargo.toml` 是 `0.1.0`，發布前要定語意化版本的規則。
- **隱私**：查詢會讓 GitHub 知道「這台電腦裝了這個輸入法」。要有關閉的
  設定項。
- **失敗要安靜**：沒網路、限流、repo 不存在都不該跳錯誤視窗。

### 順序

**排在安裝程式後面**——沒有 Releases 就沒得查，而 Releases 的內容正是
安裝程式產出的東西。

### 什麼時候重新考慮自動更新

簽章做完**而且**真的有一批使用者之後。那時兩個前提才同時滿足：驗得了
簽章、也值得為一群人省下手動下載。現在做等於為零個使用者建一條有風險
的通道。

### 實作（2026-09-14）

**使用者裁決**：開設定頁時自動查一次、可以關；連網方式「簡單就好」；**只提示正式版，beta 不抓**。

| 塊 | 做法 |
|---|---|
| 什麼時候查 | **開設定頁時背景查一次**（`Config::check_updates`，預設開）。「關於」分頁另有「檢查更新」按鈕 |
| 怎麼連網 | **叫系統內建的 curl**（macOS `/usr/bin/curl`、Windows 10 1803 起的 `curl.exe`），TLS 用系統的。只新增 `serde_json` 一個套件讀 JSON——不拉 rustls 那一整串 |
| 提示在哪 | 有新版時**分頁列右邊**掛綠色「有新版 vX」，點了跳「關於」；「關於」分頁有狀態、「開啟下載頁」按鈕與自動檢查的開關 |
| 連到哪 | **Release 頁面，不是安裝檔**——頁面上有兩個平台的檔案與說明（macOS 未簽章版的 `xattr` 那行就在說明裡） |
| 失敗 | 沒網路、限流、找不到 curl、回傳看不懂，一律「無法檢查更新」一行灰字，不跳視窗 |

**上面「實作前要確認的」四點的答案**：

- **GitHub API**：實測**不帶 User-Agent 回 403** 屬實；限流 60 次／小時（`x-ratelimit-limit: 60`），
  設定頁一次開一次綽綽有餘
- **只看正式版**：prerelease 旗標**與**標籤後綴（`-beta`）兩個都擋，發布時漏勾或版號寫錯任一邊
  都不會誤報。發布 repo（`Zosuya/Tsunagi-IME`）目前四版全是 beta，所以**現在一定顯示「已是最新版」**
- **坑：`/releases/latest` 在沒有正式版時回 404**——跟 repo 不存在、網址錯同一個狀態碼，分不出
  「沒有正式版」（該顯示已是最新）與「查詢壞了」（該顯示無法檢查）。改拿 `/releases` 清單自己挑，
  **空的或全是 beta 算已是最新，回傳看不懂才算失敗**
- **版本規則**：比三段數字。**發第一個正式版時版號要往上跳**（例如 `0.4.0` 或 `1.0.0`）：
  Cargo 版本沒有 beta 後綴，裝著 `v0.3.1-beta` 的人程式裡記的是 `0.3.1`，這時發 `v0.3.1` 正式版
  會被判成「已是最新」而不提示
- **隱私**：有開關，說明文字寫明「查詢會讓 GitHub 知道有人在用」
- **失敗要安靜**：見上表

**Windows 要注意的**：設定頁是 GUI 程式，叫 console 程式預設會**閃黑色視窗**，所以帶了
`CREATE_NO_WINDOW`。Mac 上只驗得到 `cargo check` 過，實際有沒有閃要在 Windows 看。

**測試**：`settings/src/update.rs` 七個單元測試（版本解析、比較、有新正式版才提示、沒有正式版算最新、
清單挑最大正式版、全是 beta、看不懂的回傳）。另有一個 `#[ignore]` 的真連線測試，改 curl 參數或網址後手動跑：
`cargo test -p ime-settings -- --ignored 真的連`。
