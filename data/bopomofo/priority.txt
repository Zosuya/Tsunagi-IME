# 注音候選的人工排序調整表
#
# 格式：`注音 字1 字2 ...`（空白分隔）
# 意思：這個注音底下，列出的候選要依序排到最前面，其餘維持原順序。
#
# 注音可以是**單一音節**（調整同音字排序）或**多音節連寫**（調整同音
# 詞排序）。兩者用同一套機制——查詢表的 key 本來就是完整音節序列。
# 例如：
#   ㄕˊ 實 時 十          ← 單字：ㄕˊ 底下「實」排第一
#   ㄕˊㄗㄨㄛˋ 實作 十座    ← 詞：ㄕˊㄗㄨㄛˋ 底下「實作」排第一
#
# 多音節的調整很重要：最長詞優先會先匹配到詞，根本走不到單字排序。
# 實測「實作現況」給出「十座現況」，就是因為「十座」這個詞條在檔案裡
# 排得比「實作」前面，跟單字排序無關。
#
# 為什麼需要這份檔案：
#
# McBopomofo 的 `BPMFBase.txt` 沒有詞頻欄位，只能照檔案順序排候選，
# 實測（`bench_doc_text`，開發文件的真實中文 100 組）第一候選正確率
# 只有 51%。接上 `zh_tw_50k.txt` 詞頻表後提升到 59%，但那份資料來自
# 字幕語料、有明顯雜訊（罕見字「稰」的頻率竟高於「需」），而且它的
# 高頻詞偏口語（「嗎」「吧」「啊」），書面語常用字反而排很後面。
#
# 所以最後一哩靠人工判斷：下面每一行都是實際檢視過該讀音的候選清單、
# 依中文常識判斷後寫下的，不是機械套用任何統計數字。
#
# 判斷原則：
# - 只調整「明顯排錯」的（常用字被罕見字壓過去）
# - 多音字要確認該字真的念這個音才調整（例如「來」念 ㄌㄞˊ 不是
#   ㄌㄞˋ，就不能把它排進 ㄌㄞˋ 的清單）
# - 資料裡的雜訊字（琌、硂 這種）直接忽略，不特別處理
