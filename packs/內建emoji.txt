# name: 內建emoji
# description: 表情、手勢、動物、食物、天氣、交通這些 emoji，中日英三種名字都叫得出來
# version: 1.0
# license: CC0
# updated: 2026-09-07
#
# 633 組、涵蓋 1061 個 emoji（Unicode 主要區段的 61%）。
# 沒收的四成是刻意跳過的：占星相位、易經卦象、鍊金術符號、族譜記號
# 這類「一輩子不會打」的東西，塞進來只會讓候選變擠。
#
# 【格式】第三欄的符號用**空白分隔**（跟 內建符號.txt 4.0 同一套）。
# 不能靠「一個字元就是一個符號」——👨‍👩‍👧 是五個字元（中間夾零寬
# 連接符）組成的一個圖，逐字元拆會拆出三個人加兩個看不見的字元。
# 膚色（👍🏽＝手＋色票）、變體選擇符（☀️）也一樣。
#
# 【分組哲學】沿用內建符號.txt 那條：
#   同一個東西的不同寫法 → 留在一組，方向鍵翻
#   根本是不同東西       → 各給各的名字，一次到位
# emoji 的難處在邊界比符號模糊，所以這裡多一層：
#   粗組（\笑\）當瀏覽入口，想不起來叫什麼時翻一遍
#   細名（\大笑\ \苦笑\）給知道自己要哪個的人，一次到位
# 兩者平行存在，不是階層——執行期只有一張平表。
#
# 【跟內建符號包撞名是刻意的】\音樂\ 兩邊都有，打一次 ♪♫♬♩ 和
# 🎵🎶🎤 都在候選裡（符號包的排前面，那份先載）。對使用者來說
# 「音樂的符號」本來就是一件事，不該因為技術上分兩個檔案就要記兩個
# 名字。合併規則在 pack::build_index。
#
# 【國旗不收】🇹🇼 在 Windows 上顯示成「TW」兩個字母——Segoe UI Emoji
# 故意不含國旗字形，這是微軟的既定政策，不是我們能修的。實測見
# 開發文件 §2.51。
#
# 【組合用 + 寫】`👩+💻` 載入時會展開成真正的 ZWJ 組合。
# 為什麼不直接寫：那中間夾的是零寬連接符（看不見的字元），而包裡
# 一律不准有不可見字元——那道防線擋的是惡意包拿它偽裝輸出。寫成
# `+` 兩邊都成立：檔案肉眼可審、防線不動、組合照樣打得出來。
# 真的要放半形加號的話寫 `++`。
